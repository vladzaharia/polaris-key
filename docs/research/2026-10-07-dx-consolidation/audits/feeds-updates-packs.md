_Domain auditor, DX consolidation, 2026-10-07. Tree read: `/Users/vlad/Repos/pk-wt/dx-plan` (v0.8.31
plus batch 5), with LX-08, UK-13, UK-14 and HA-12 checked for overlap. Owner brief items covered:

---

## 1. Summary

Most of what the owner asks for in this domain is **already built**, and some of it is built twice.
The owner believes the feeds are "all public, so there's no authentication support". That is not
true. Since F-21, every tenant feed has four access modes and `pkeyr_` tokens. Owners mint them in
the console, and licensees mint licence-bound tokens in the portal. Feed retention (pruning
`-main.N` builds) landed on 2026-10-06. Update channels with `stable` always granted and other
channels granted by name, plus promote/pin/yank and per-outlet rollouts, have existed since P0–P2b.
Packs, Background Assets, Play Asset Delivery and Steam depots shipped in P4/P5.

The domain does not need much new capability. It needs work in four areas:

1. **The token model is per product, not per person.** A customer with licences for three
   products needs three tokens, and docker, SwiftPM and netrc can hold only one of them per host.
   This was a known limit, accepted in F-20 Q2 "until a customer hits it". The owner's request is
   that trigger.
2. **Defaults are permissive and the switches are many.** Enabling one npm feed takes Distribution,
   the operator-only `packageFeeds` switch, the feed's `enabled` and a namespace. New feeds default
   to `public`. Feed settings have 11 sections, and two of them do nothing: **Upstream** has one
   option, and **Untagged manifests** is stored but never applied.
3. **"Feed" means four different things.** It names package registries, the signed update
   document, storefront sources (AltStore, F-Droid and others) and the Update section's only page.
   Access is configured in three places with the same four-value vocabulary.
4. **Channels are almost what the owner described, but `dev` is missing from Release.** `dev` is
   only a licence-gate pseudo-channel that also **bypasses the version window** for `0.0.0-dev`
   builds (R3-01, pinned in the gate corpus). There is no "demote". The update endpoints shown to
   developers are not scoped to the platforms they ship.

**The single most important change: account-level personal access tokens.** One `pkeyr_` token
per person reads every feed that person may read, across products. That means every product where
the person holds a usable licence, plus every product where they are on the team, with the SDK
feeds for developers. It comes with a portal "Packages" page and a `pkey feeds login` command that
writes every package manager's configuration from one sign-in. This is a new Core table and a new
principal kind on the existing access ladder. It changes no wire format, no SDK and no URL. Per-owner
URLs and strict routing stay. It is a THREAT-MODEL §9 review trigger ("a new registry principal
kind"), so it goes through a plan.

**Push-back.** I recommend against hiding the SDK feeds behind tokens. The repository is public and
MIT-licensed (`gh repo view`: PUBLIC; `LICENSE`), so protecting the SDK feeds adds a credential to
every tenant's CI and protects nothing. Instead, keep them public and hide them from customers'
views. The owner's actual goal, "customers shouldn't see our internal SDKs, developers should", is
about **audience**, not secrecy.

## 5. Target design

### 5.1 One vocabulary, four nouns

- **Packages** (console product section item; Platform keeps **Package feeds**). These are library
  registries on `pkg.plrs.im`. CLI: `pkey feeds setup|login|prune|publish-public`.
- **Outlets** (was "Outlets & feeds"). Storefront sources are details of an outlet. CLI:
  `pkey storefront fdroid` (`pkey feeds fdroid` kept as a deprecated alias for two minors).
- **Updates** (Update section's page, was "Feed"). The signed `pkey-feed+jws` is called the
  "signed update feed" only in docs and code.
- **Channels** (Release → Channels). The one home of stable/beta/dev and custom channels: who gets
  them (tier grants), where they go (outlet track maps), what they point at (promote, demote, pin).

Central push is called **"Publish to public registries"**, never "mirror", because HA-08 already
uses "mirror".

### 5.2 Access: one page, two questions

**Distribution → Access** ("Who can get what") becomes the single access page:

| Row                                       | Options                                                                    | Stored in (unchanged)                                      |
| ----------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Update checks (metadata)                  | Public · Signed-in device · Customers · Customers on the release's channel | `release_config.metadata_access` (`update.metadataAccess`) |
| App downloads                             | the same four                                                              | `dist_access` (`app`)                                      |
| Each pack                                 | Public · Customers · Holds `<flag>`                                        | `dist_access` (pack), `entitlement`                        |
| Each package feed (one row per ecosystem) | **Public · Customers**                                                     | `dist_registry_feeds.access_mode` (`public`/`licensed`)    |
| Each package (only when stricter)         | Holds `<flag>`                                                             | `dist_access` (package)                                    |

- This is S-18 D16's copy-only unification. **No enum changes on the wire.** Feed `authenticated`
  stays readable and displays as Customers. The feed-level `entitled` value is no longer offered;
  per-package gates replace it, and existing rows keep working.
- The Update → Updates page and each feed page show the current access read-only, with a link
  here.
- **Who counts as a customer** of product P, for every row: a licence-bound token of P whose
  licence is usable; an account (FX-01) holding a usable licence of P; for a device-token
  surface, the device's licence. **Team** (owner and service tokens of P, any `pkeyci_` of P,
  personal tokens of console users) passes every row.
- **The system product is a special case of the same rule.** It has no License, so "Customers"
  admits only team principals. If the owner ever wants the SDK feeds protected, set them to
  Customers and add one ladder rule: any product's team principal is team on `polaris-key`.

### 5.3 Personal access tokens (FX-01)

- A **new Core table** `registry_account_tokens` (expand-only; `registry_tokens` is untouched):
  `token_id`, `token_hash` (UNIQUE), `hint`, `label`, `subject_kind` (`account` | `admin`),
  `subject_id`, `scopes_json` (`["read"]`; `["publish","read"]` only for `admin` subjects, 1–30
  days), `products_json` (NULL = everything the subject may read; optional narrowing, API and
  Advanced only), `presentation` (`header` | `url`, where url is godot read-only), `created_at`,
  `expires_at` (≤ 365 days, default 90), `last_used_at`, `revoked_*`.
- **The prefix is still `pkeyr_`**, so every snippet, challenge and client stays as it is.
  `lookupRegistryCredential` checks the per-product table, then this one (one indexed point read
  on a miss).
- **New principal** `{kind: "person", subject, tokenId}`. At ladder step 5, for owner P, its
  standing is computed lazily and cached for 30 s per (subject, P):
  - team: an `admin` subject (until RBAC: a platform admin, so team everywhere; after RBAC: a role
    covering P);
  - customer: an `account` subject holding usable licences of P (union over them). `entitled`
    gates pass when **any** held licence holds the flag.
  - Otherwise the person is anonymous on P (native 401). That keeps "another owner's token is no
    credential here" true.
- **Listing documents** (PyPI project list, Godot search, the OCI catalog) for a person principal
  are filtered at serve time to the packages that principal may read. Answers for non-public
  modes are already `private, no-store`, so nothing cached changes.
- **Surfaces**:
  - Portal: **Account → Packages**, one page with every product the account can read, its feeds,
    one combined copy-paste setup (all scopes in one `.npmrc`, every uv index, every Gradle
    repository), and the token list.
  - Console: **Account menu → Personal tokens**.
  - Packages → Tokens keeps product **service tokens** (today's owner-bound, renamed) for
    machines.
  - Licence-bound tokens are minted **only by operators**, from the licence page, for floating
    licences with no account. The portal stops minting them; existing ones run to expiry and stay
    listed and revocable.
- **Cascades**: account deletion and merge (I-05 already moves "registry tokens" in a merge, per
  THREAT-MODEL line 5609); admin removal (until RBAC, revoke on the next console sign-in that
  lacks the admin group, plus an operator "Revoke all personal tokens" action).
- **Fixes P1** for docker, SwiftPM and netrc: one credential per host now covers every product.

### 5.4 Feeds that provision themselves (FX-02)

- Distribution on + a **declared package deliverable** of ecosystem E means the feed (P, E)
  exists and is enabled. Its namespace is **derived from the declared names**: the npm scope of
  `@scope/name`, the Swift scope, the Maven groupId of each artifact, the exact PyPI names, the
  Godot publisher.
- An exact-name namespace is stricter than today's prefixes, so this narrows rather than widens.
  The operator can still widen to prefixes.
- **Access starts at Customers** (`licensed`). Moving a feed to Public stays an operator L1
  action. A manifest can never widen access (F-01's rule holds).
- `packageFeeds` remains, as the operator's **off switch** in the Packages header (default on once
  a package is declared). The platform kill switch and ceiling stay in Platform → Settings
  (ST-09).
- Feed settings shrink to **General · Namespace (derived, override) · Limits · ecosystem panel**.
  Upstream goes. Untagged-manifest retention goes. Asset-listing metadata moves onto the package
  deliverable in `.pkey/release`, with the feed value as fallback. Maven's "hide yanked" becomes
  the default behaviour, so its knob goes too.

### 5.5 Publish to public registries (FX-03)

- **Per package, operator-owned**: "Also publish to npmjs.com / PyPI / Maven Central / crates.io /
  GHCR". A manifest may declare the **intent** (`publish.public: [npmjs]`); the console shows it
  as pending until the operator approves it once.
- **CI plane only.** After `pkey release publish` stores a package version, the publish Action
  runs `pkey feeds publish-public`. That command re-hashes the bytes against the release record,
  publishes them with the registry's trusted publishing (npm `--provenance` with OIDC; PyPI
  Trusted Publishers), and falls back to a CI secret for registries without OIDC. It reports the
  result back with `distribution:report`, and the package record shows "npmjs: 1.4.0 ✓".
- **Rules**: refused unless the package's access is Public; only `stable` (as `latest`) and `beta`
  (as `next`); `dev`/`main` never. A yank or deprecation on our feed offers the matching action on
  the public registry as a CI follow-up where the registry allows it (npm deprecate, PyPI yank).
  Feed retention never touches public registries.
- **Wizard** (per registry, three steps): claim the name (an npm org for a scope; PyPI first
  publish), configure the trusted publisher (deep link pre-filled with repo, workflow and
  environment), then live verification on the next stable publish.

### 5.6 Channels (UC-01, UC-02)

- `BUILT_IN_CHANNELS = ["stable","beta","dev"]`. Default includes: **dev ⊇ beta ⊇ stable**.
  A product's declared manual `dev` keeps priority, the same rule `staging` already follows.
- Discovery `update.channels` lists the built-ins, the manual channels and the app's declared
  channels (from `knownChannels`, minus `pr-<n>`).
- **Default outlet track maps** for the built-ins, used unless declared:

  | Channel | Play             | TestFlight | Steam   | MS Store      | Snap   |
  | ------- | ---------------- | ---------- | ------- | ------------- | ------ |
  | stable  | production       | none       | default | (main)        | stable |
  | beta    | open/closed beta | external   | `beta`  | flight `beta` | beta   |
  | dev     | internal         | internal   | `dev`   | none          | edge   |

- **Grants**: stable is always held. beta and dev are granted by tier, licence or grant (the
  `channels` key; LX unions). The tier editor offers `dev` with the hint "Dev builds; also lets
  `0.0.0-dev` local builds skip the version window" (R3-01 unchanged).
- **Operations**: publish to a channel, then promote (up), **demote** (down), pin, yank. Demote
  writes a membership override (`release_channel_moves`, Release-owned). The release stops being
  a member of the channel and of every channel that only reaches it through `includes`, while it
  stays a member of the target channel. The signed feed is re-composed and package tags
  re-render. Console lanes show where a release was published to, promoted to and demoted from.
- **WIRE-CONTRACT-V4 §5.1**: the `dev` row changes from "Release has none" to "header, selector,
  grant". It is a document row with no corpus or SDK change, so UC-01 is flagged plan-mode for a
  cheap contract plan.

### 5.7 Updates page (UC-04) and one resolver (UC-05)

- **Update → Updates** is built from builds and outlets. One row per shipped platform and outlet
  gives the update method, the endpoint and ready-to-paste config:
  - macOS direct: Sparkle `SUFeedURL` and `SUPublicEDKey` filled in, or the Swift
    `PolarisKeyUpdate` call;
  - Windows: Velopack `UpdateManager(url)`, WinSparkle `win_sparkle_set_appcast_url`, App Installer
    URI;
  - Linux: AppImage `--updateinformation "zsync|…"`;
  - Android direct: Kotlin PackageInstaller driver; Play: In-App Updates (priority from the
    connector);
  - App Store and Steam: "store-managed", plus the SDK's store prompt;
  - Godot: `PKeyBoot`/updater settings;
  - Web: `update.driver` (SP-15).

  Each row turns **Wired ✓** on the first `update_offered`/`update_applied` event from that
  outlet (the update-health counters already exist). Those events are the "integration
  handshake" signals the Products integration section consumes.

- Compatibility window and artifact policy stay on the Updates page as settings rows.
  Metadata access moves to the Access page.
- `pkey release keys init --sparkle` generates the Sparkle EdDSA pair, prints the public key for
  `.pkey/release`, and sets the private key as a CI secret through the same path `pkey ci init`
  uses.
- **UC-05** routes every appcast and version-check request through the truth-store resolver
  (`resolve.ts`), with GitHub-synced rows as candidates (P0-02/P0-03 already keep them current).
  It deprecates `release.betaBranch` and `release.channelWorkflow` (beta = the descriptor channel
  or GitHub's prerelease flag), keeps every URL and alias, and pins byte compatibility of
  shipped Sparkle feeds in tests.

### 5.8 Packs (CP-01, CP-02)

- `transports.packs: auto` (the new default when `.pkey/distribution` declares outlets):
  `apple-ba` on `app-store`/`testflight`, `steam-depot` on `steam` when depots are declared,
  `pkey-cdn` elsewhere. Play stays `pkey-cdn` plus an embedded baseline unless the developer
  explicitly chooses `play-pad`, because PAD pins packs. Explicit per-outlet declarations still
  win.
- `pkey storefronts sync` (SETUP D27) also runs each auto or explicit transport's package and
  upload step, so no workflow edit is needed per transport. The App Store connector adds approved
  asset-pack versions to the next review submission where Apple's API allows it, and shows a
  deep-link step otherwise.
- **Gate approval**: a pack whose manifest asserts `entitlement: X` shows "Gate: X (from
  manifest) · Approve" on Distribution → Access. One click writes `dist_access.entitlement`.
  The publish-time check is unchanged, so no push can gate or un-gate. The pack record shows
  "Sold as: `<sub-licence>`" once LX's sub-licence model lands.
- An attention item, "N packs declared, Update is off: devices get embedded baselines only",
  replaces silence.

## 7. Automation and onboarding
