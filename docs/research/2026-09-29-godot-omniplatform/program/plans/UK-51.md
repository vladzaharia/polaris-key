## 3. Contract: the `cli` family

Added to `UiMatrix` as `cli: { verbs, mount, help, gate, outcomes, stdin, capabilities, exit }`.
All values are ASCII, sorted where they are sets.

**`verbs`.** Ids are the verb path joined with a space. `endUser` (the default mount): `activate`,
`deactivate`, `status`, `login`, `logout`, `devices list`, `devices rename`, `devices deauthorize`,
`update check`, `update apply`. `developer` (opt-in): `enroll`, `register`, `config get|list|set|reset`,
`secret`, `mint`, `packs status|ensure`, `changelog`, `offline-request`, `import-bundle`, `boot`,
`doctor`, `completion`. `aliases`: `sign-in` is `login`, `sign-out` is `logout`.

**`mount`.** Rows `{host, options} -> {mounted, collision}`. `options` has `namespace`, `verbs`,
`onCollision` (`"error"` default, `"skip"`). Pinned: root mount; `namespace: "license"` gives
`mytool license activate`; `verbs` picks a subset; a host verb equal to a mounted one fails at
registration with code `polaris-verb-collision`, naming the verb and the fixes `namespace` and
`verbs`; `onCollision: "skip"` drops the verb and warns once; the host's own verbs are never
changed. Once `config` is given, `--product`, `--trust` and `--base-url` are hidden.

**`help`.** Host commands first under the host's headings; the Polaris verbs under one heading
whose copy key is `cli.help.group` (a new kit catalog key, added by UK-51 with its seven locale
packs per the catalog process; the English text is "License" unless the brand copy owner says
otherwise).

**`gate`.** One row per `licenseStatus` (the 9 values in `enums.json`) x `tty` x `json` x
`entitled`, 4 quadrants per refused status (this is also `kitboard:terminal:pipe-quadrant`).

- `ok`, `grace`, `not-applicable` with the entitlement held: `run`, the host action's own exit.
- Interactive TTY, not `--json`, status `needs-activation`, `expired` or `revoked`: `flow`
  (the kit's activate or sign-in flow runs inline, then the action).
- Everything else: `refuse`. The refusal is ▲, the copy keys are the existing `core.gate.<status>.*`
  keys, the fix rows name verb ids (`activate`, `login`, `update apply`), and the exit is **4**.
  Without `--json` the refusal goes to **stderr**, once, with no escape off a TTY. With `--json`
  stdout carries the existing result line: `{"v":1,"command":..,"event":"result","ok":false,"exit":4,"error":"license_required"}`.
  `CLI_JSON_VERSION` stays 1; only `error` values are new.
- `error` is `license_required` for every non-usable status and for `version-too-old` and
  `version-too-new`; `not_entitled` for `channel-not-entitled` and for a usable licence without the
  entitlement (fix: `status`).
- `version-too-old` and `version-too-new` never run the inline flow, since activating fixes
  neither; their fix is `update apply`.

**`outcomes`.** Verb x situation -> `{mark, exit, error?, stdout}`. Pinned here: the gate refusals
above (▲, 4); `status` for `revoked`, `expired` and the version refusals (▲ with the fix rows, exit 1;
the reason and date only when the wire carries them); a network failure (✗, 1); `activate` key
refused (▲, 1, `unauthorized`); device limit (▲, 1); `secret` and `mint` without `--reveal` (▲, 2,
stdout empty; UK-45 M5); usage error (2, `usage`); Ctrl-C (130, `interrupted`); a cancelled
sign-in (✗, 1; the parity board keeps ✗ for a cancel, which is the person's choice, not a refusal).

**`stdin`.** `activate` with no key: TTY -> masked prompt; file, FIFO or socket -> first non-empty
line; a silent open pipe or `/dev/null` -> `cli.activate.noKey`, exit 2, within 2 s and the process
exits (UK-45 B1, B2).

**`capabilities`.** The 15 rows of the UK-45 table (environment x streams x flags -> `color`,
`unicode`, `interactive`, `animate`, `links`), verbatim.

**`exit`.** `{ok: 0, failed: 1, usage: 2, licenseRequired: 4, interrupted: 130}`.

`docs/design/UI-KITS.md` already states the intent (DL6 to DL8, "Terminal output for scripts", the
capability table); UK-51 edits it only where it must point at the rows, and adds the exit-4 row.

## 6. Worker, rollout, deployed software

No Worker, route, migration or table. The Worker never sees exit codes. A deployed CLI built on the
0.8.x kit keeps working, with two visible changes that the Node README's "Changed in 0.8.x"

UK-51 -> the adapters. No feature flag.

## 7. Questions for the human (each with a recommendation)

1. **Version number.** The brief says `uiMatrixVersion` becomes 2, but UK-03 also bumps. Recommend
   the next free number at merge time (expected 3), one regeneration, since a new top-level family
   is something every runner must learn.
2. **Where the human refusal goes.** Recommend stderr, so a host's piped stdout stays clean. The
   existing kit writes flows to stdout; the gate is a new place.
3. **`channel-not-entitled` and version refusals.** Recommend `not_entitled` for the channel and
   `license_required` for version, with `update apply` as the version fix.
4. **Inline flow on an expired or revoked licence in a TTY.** Recommend yes (the person can
   activate another key or sign in), none for version and channel refusals.
5. **The `cli.help.group` text.** Recommend "License".
6. **`update apply` hand-off exit** (UK-45 m7: 0 for a package-manager hand-off, 1 for no driver).
   Recommend leaving it out of UK-51 and giving it to UK-46 and UK-48.
