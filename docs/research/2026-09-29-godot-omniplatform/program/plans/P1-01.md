# P1-01 plan: `sdks/godot`, its corpus mirror and the `godot` CI job

This is the plan for [P1-01](../wp/P1-01-godot-scaffold.md). `pkey-wire-planner` wrote it and
`pkey-godot-engineer` implements it once it is approved. The implementation follows the brief's
Scope plus the decisions below; where the two differ, this plan wins.

Facts marked **(measured)** were run on 2026-09-30 with a scratch copy of the layout in §5:

- **Engines:** Godot 4.7.2 and 4.4.1 (official macOS editors), the official 4.7.2 macOS release
  template, and the official 4.7.2 Linux arm64 editor in `ubuntu:24.04` (Docker).
- **Downloads:** the upstream `SHA512-SUMS.txt` values in §5 were checked against the files.

## 1. Summary

- **Scaffold.** `sdks/godot/` becomes a Godot 4 project.
  - The prototype verifier moves in with its history and takes the `PKey` prefix.
  - A headless runner is the project's main loop, so the editor and an export template run it the
    same way.
- **Sixth corpus language.** Godot runs the 36 `jwsCases`, the 24 SHA-512 vectors and the 26 Ed25519
  vectors (on both verifiers) on three targets:
  - the 4.7.2 editor;
  - an exported pack on the official 4.7.2 `linux_release.x86_64` template;
  - the 4.4.1 editor.
- **Mirror.** `tools/sign-corpus.ts` writes a second mirror, at `sdks/godot/tests/corpus/v2/`, through
  one list of corpus targets. `pnpm gen:corpus -- --check` guards it like Swift's. No vector
  changes; `corpusVersion` stays 2 and `PROTOCOL_VERSION` stays 3.
- **One additive field, one contract entry.**
  - `expect.docNulReplaced` gives, for each `jwsCases` string containing U+0000, its U+FFFD form.
  - A WIRE-CONTRACT-V3 §10 entry requires a platform whose strings cannot hold U+0000 to decode it
    as U+FFFD on every engine.
  - Godot's runner asserts those strings exactly; every other runner ignores the field.
- **CI and docs.** A new `godot` job runs two legs. The corpus, runner and gate text names Godot,
  and `reference/corpus.mdx` is regenerated.

## 2. Contract

`docs/security/WIRE-CONTRACT-V3.md` gets two edits. The Scope line's SDK count stays for P1-12.

- The header's **Conformance** line ends "…byte-for-byte across all implementations, within the one
  representation limit declared in §10."
- **§10** gains this paragraph:

> **Declared representation limit: U+0000 in decoded strings.** Some client platforms cannot hold
> U+0000 in a native string: GDScript's `String` drops it on Godot 4.4 and replaces it on 4.7.
>
> - Such an implementation MUST decode the JSON escape `\u0000` as U+FFFD on every engine version,
>   before its duplicate-key scan and parse, so its decoded documents are the same everywhere and
>   the loss stays visible.
> - Verdicts do not depend on this, because the signature covers the encoded bytes (§1).
> - For each string value under a `jwsCases` `expect.doc` that contains U+0000, the generator
>   writes `expect.docNulReplaced`. It maps the value's RFC 6901 pointer to the value with every
>   U+0000 replaced by U+FFFD.
> - A runner on such a platform compares those values against `docNulReplaced`, and the rest of
>   the document as usual. Every other runner ignores the field.
> - An object key containing U+0000 is outside this entry. The corpus has none, the generator
>   refuses to emit one, and no verdict for it is pinned yet.
>
> This is the only declared representation limit, and it covers no other character. **[C]**

No change in `shared-protocol`, `shared-jws` or `client-core`. `PROTOCOL_VERSION` and
`CACHE_VERSION` stay 3.

**Clients and Workers already deployed** are unaffected:

- nothing on the wire changes;
- the new field exists only in test fixtures;

- the first release (P1-12) carries the rule from day one.

## 4. Corpus

`tools/sign-corpus.ts` changes in three places.

1. **Targets.**
   - Add `GODOT_V2_RESOURCES = sdks/godot/tests/corpus/v2` beside `SWIFT_V2_RESOURCES`.
   - `main()` reconciles every file (a name-to-content map) into each directory of
     `CORPUS_TARGETS = [V2_DIR, SWIFT_V2_RESOURCES, GODOT_V2_RESOURCES]`. Later files therefore reach
     both mirrors by construction: P1-09's `stage-matrix.json`, P1b-04's `headers.json` and
     `config-matrix.json`, and P3-02's matrices.
   - A top-level `*.json` in a target that the map does not name fails both modes, so a dropped or
     renamed file cannot linger in a mirror. Subdirectories are left to their owners (P4-04's
     `content/`).
2. **U+0000 annotation.**
   - `annotateNul(expect)` walks `expect.doc` in document order. It writes
     `expect.docNulReplaced: { "<RFC 6901 pointer>": "<value with U+0000 → U+FFFD>" }` when the map
     is not empty.
   - It throws on U+0000 in an object key, and on a replacement that still contains U+0000 or
     equals the original.
   - `buildJwsCases()` applies it to every case. `VerifyExpect` gains
     `docNulReplaced?: Record<string, string>`.
   - Any later section that pins a decoded document reuses the helper. It is never added to
     `bundleCases`, whose whole `expect` object the Node and Python runners compare
     (`corpusV2.test.ts:464`, `test_conformance.py:249`).
3. **Header comment** (`:1-13`): name both mirrors and the Godot runner. `:2119` is historical and
   stays.

**`PKeyJws`, one deliberate behaviour change** (its own commit):

- `_parse_strict_json` passes the UTF-8 text through `_nul_as_fffd()` before the duplicate-key scan.
- That is one native `RegEx.sub` of the PCRE pattern `(?<!\\)((?:\\\\)*)\\u0000` with the JSON
  escape `$1\ufffd`, taken only when the text contains `\u0000`. It rewrites real escapes only.
- Measured on 4.7.2, 4.4.1 and the template: `"a\u0000b"` → `a�b`; two escapes in a row → `��`;
  `"\\u0000"` stays text; `"\\\u0000"` → `\�`.
- Without it, 4.4.1 drops the NUL and the conformance suite fails `valid-nul-byte-in-string`
  (measured), so the check is not vacuous.
- A NUL in a key now collides with a U+FFFD key and is rejected as a duplicate (fail closed). No
  corpus case exercises that.

**Runner protocol** (`tests/runner.gd`, `class_name PKeyTestRunner extends SceneTree`).

- **Selection.** Suites run only when the user arguments contain `--pkey-test <suite>[,<suite>]`.
  Anything after the list is passed through (for example `ed25519 bench 20` for S-04).
- **Without `--pkey-test`** the runner returns from `_initialize()` and is a plain `SceneTree`.
- **The `ci` set** is `SETS["ci"] = ["sha512", "ed25519", "conformance"]`. Later packages append to
  it; `platform` and `profile` stay outside it.
- **Suite contract.** A suite is `extends RefCounted` with
  `func run(t: PKeyTestContext, args: PackedStringArray) -> bool`, and the runner `await`s it.
  - A suite that fails to load, returns anything but `true`, or reports zero checks fails.
  - Suites report only through `t.check(name, ok, detail)`, from `tests/support/test_context.gd`.
- **Release-template rule.** Suites never use `assert` or rely on a runtime error. Each one ends
  with a coverage check: vectors evaluated equals vectors loaded, and at least 36 `jwsCases`.
  - A release template skips GDScript runtime checks (measured): a method call on null, a missing
    key or index read (which returns null) and `assert(false)` all continue silently.
  - The editor aborts the function in each case.
- **Output.** The first line is
  `PKEY-TEST engine=… build=debug|release target=editor|template os=… arch=… sdk=0.1.0 suites=…`.
  Then come `PASS|FAIL <suite> <name>` and `INFO` lines, and last
  `PKEY-TEST SUMMARY suites=N checks=N failed=N`. The exit code is 1 on any failure.
- **The runner's own dependencies** are only `polaris_key.gd` (for the version) and
  `test_context.gd`. A broken addon file therefore fails one suite cleanly instead of the runner
  (measured).
- **`suite_conformance.gd`:**
  - It parses the mirror with `JSON.new().parse()` and checks the `Error`.
  - It prints `FileAccess.get_sha256()` of the mirror, and asserts `corpusVersion == 2` and at least
    36 `jwsCases`.
  - It self-checks the comparator: a copy of the first doc with one changed leaf must compare
    unequal. `Dictionary ==` ignores key order and catches leaf and array-order changes (measured).
  - Per case, it asserts the verdict, then the `kid` on `ok`. Where there is a doc, it
    deep-copies `expect.doc` and puts each `docNulReplaced` value at its pointer. The pointer must
    resolve to a `String`, and the value must contain U+FFFD. It then asserts `payload == doc`.
  - No case id appears in the suite.

**`tools/run_tests.sh`** is committed with mode 100755 and written for bash 3.2 (macOS
`/bin/bash`).

- **Variables:**
  - `GODOT_BIN` defaults to `godot` on `PATH`; if none is found, the script exits 2 and never skips;
  - `GODOT_TEMPLATE` is optional;
  - `PKEY_TEST_SUITES` defaults to `ci`;
  - `PKEY_TEST_TIMEOUT` is per step, default 300 s.
- **Setup.** It recreates `build/` with `build/.gdignore` and `build/logs/`.
- **Steps:**
  1. `--import`, retried once only on a signal exit, because notes/A5 saw one SIGABRT;
  2. fail if any `.uid` is left untracked (`git status --porcelain --untracked-files=all`);
  3. the editor run;
  4. with `GODOT_TEMPLATE` set: `--export-pack "Conformance (Linux)" build/pkey_conformance.pck`,
     copy the template to `build/pkey_conformance.x86_64`, and run
     `build/pkey_conformance.x86_64 --headless -- --pkey-test "$PKEY_TEST_SUITES"`.
- **Each step** runs in the background with its log in `build/logs/<step>.log`, which is polled
  every second.
  - It is killed and failed on
    `SCRIPT ERROR|Parse Error|Failed to load script|Cannot get class|Invalid MainLoop`. The patterns
    match 4.4.1's coloured output too.
  - It also fails on the timeout, on a non-zero exit, or (for runs) without a final
    `PKEY-TEST SUMMARY … failed=0`.
- **Measured:** green in 11 s on this Mac (import, editor, export and template). A broken runner is

## 8. Decisions and risks

The research left four decisions open, and measuring raised three more. Each is resolved here for
the lead to approve.

1. **U+0000: option (a), made non-vacuous.** Corpus annotation plus §10, U+FFFD on every engine,
   and an exact assertion.
   - **Why annotate at all.** A Godot-only comparison passes vacuously: both sides go through the
     same lossy parser (PARITY §6.3 #4).
   - **Why not pointers plus a mask** (the first draft of this plan). A mask only type-checks the
     strings: 4.4.1's dropped NUL would pass, and the MUST would go untested.
   - **Why U+FFFD rather than dropping.** It is Unicode's replacement character and 4.7's own
     behaviour. It keeps length, and it keeps the loss visible. Dropping can turn one meaningful
     string into another (`ad\u0000min` → `admin`).
     - It does collide with a literal U+FFFD at the same position. The claim is determinism, not
       injectivity.
   - **Why not (b).** It flips a vector in every SDK.
   - **Keys.** P3-01's plan decides U+0000 in keys (and control characters) with report §9.1 #19's
     JSON edge vectors.
2. **Mirror path `sdks/godot/tests/corpus/v2/`.** The release zip ships only `addons/polaris_key/`,
   so no vectors reach games.
3. **Engines: the 4.7.2 editor, the 4.7.2 template and the 4.4.1 editor.** 4.4.1 is the latest 4.4.x.
   - The prototype passes there unchanged (measured), and so does the layout above.
   - The floor stays 4.4 with no syntax fixes. 4.5 and 4.6 legs are optional later.
4. **Template: the full `.tpz` on a cache miss, verified against upstream SHA-512, caching only the
   extracted binary.** A Range fetch of the single member (28.3 MB, measured) cannot check the
   upstream hash, and it needs a custom zip client.
5. **No boot guard** (new; the earlier draft had one).
   - When the main-loop script fails to load, `main/main.cpp:4393-4422` (at `4.7.2-stable`) calls
     `OS::alert()`, then returns `EXIT_FAILURE`. The main scene never loads, so no scene script can
     help.
   - macOS blocks in `-[NSAlert runModal]` under `--headless` (sampled).
   - Linux prints `Invalid MainLoop script base type` and exits 1 (measured in Docker).
   - The watchdog and the SUMMARY line are the guard.
6. **Explicit checks only** (new). Release templates silence runtime errors, so the rule in §5
   binds every later Godot suite (P1-02 onwards).
7. **Our own fetch rather than `chickensoft-games/setup-godot`** (report §5.11). No third-party
   action runs with the checkout, every archive is hash-checked, and the pins drive the cache key.
