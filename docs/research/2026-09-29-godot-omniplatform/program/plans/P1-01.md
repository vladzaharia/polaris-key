# P1-01 plan: `sdks/godot`, its corpus mirror and the `godot` CI job

This is the plan for [P1-01](../wp/P1-01-godot-scaffold.md). `pkey-wire-planner` wrote it and
`pkey-godot-engineer` implements it once it is approved. The implementation follows the brief's
Scope plus the decisions below; where the two differ, this plan wins.

Facts marked **(measured)** were run on 2026-09-30 against a scratch copy of the layout in §5:

- **Engines:** the official Godot 4.7.2 and 4.4.1 macOS editors, and the official 4.7.2 macOS
  release template.
- **The two CI binaries**, in an amd64 `debian:bookworm-slim` container: the 4.4.1 Linux x86_64
  editor and the 4.7.2 `linux_release.x86_64` template running the exported pack. Both reported
  146 checks, 0 failed and exit 0, with the same mirror SHA-256 as the macOS runs.
- **Downloads and source:** the SHA-512 pins in §5.6 equal upstream `SHA512-SUMS.txt`. Engine
  source lines are cited at the `4.7.2-stable` tag.

Line numbers are those of `main` at `c4339b1`. P1b-01, which is being merged, inserts one line
into several gate blocks, so the implementer re-locates each edit by its quoted text.

## 1. Summary

- **Scaffold.** `sdks/godot/` becomes a Godot 4 project.
  - The prototype verifier (SHA-512, two Ed25519 implementations, JWS) moves in with its history
    and takes the `PKey` prefix.
  - A headless runner is the project's main loop, so the editor and an export template run it the
    same way.
  - The prototype keeps only its spike probes and their runner.
- **Sixth corpus language.** Godot runs the 36 `jwsCases`, the 24 SHA-512 vectors and the 26
  Ed25519 vectors (on both verifiers) on three targets:
  - the 4.7.2 editor;
  - an exported pack on the official 4.7.2 `linux_release.x86_64` template;
  - the 4.4.1 editor (the floor).
- **Mirror.** `tools/sign-corpus.ts` writes a second generator-owned mirror,
  `sdks/godot/tests/corpus/v2/`, through one list of targets. `pnpm gen:corpus -- --check` guards
  it like Swift's.
  - No vector changes.
  - `corpusVersion` stays 2 and `PROTOCOL_VERSION` stays 3.
- **One additive corpus field, one contract entry.**
  - `expect.docNulReplaced` gives the U+FFFD form of each `jwsCases` string that contains U+0000.
  - WIRE-CONTRACT-V3 §10 declares that representation limit.
  - Godot asserts those strings exactly; every other runner ignores the field.
- **CI, parity and docs.**
  - A new `godot` job runs two legs.
  - `sdks/godot/parity.json` declares every feature `planned`.
  - The corpus, runner and gate text names Godot.
  - `reference/corpus.mdx` and `reference/parity.mdx` are regenerated.

## 2. Contract

`docs/security/WIRE-CONTRACT-V3.md` gets two edits. The Scope line's SDK count stays for P1-12.

- The header's **Conformance** line (`:6`) reads: "…pins every rule marked **[C]** byte-for-byte
  across all implementations, within the one representation limit declared in §10.
  `pnpm gen:corpus -- --check` is the drift gate."
- **§10** gains this paragraph:

> **Declared representation limit: U+0000 in decoded strings.** Some client platforms have a
> native string type that cannot hold U+0000. GDScript's `String` is one: Godot 4.4 drops the
> character and 4.7 replaces it. Such a platform is conformant only under this rule.
>
> - It MUST decode the JSON escape `\u0000` as U+FFFD on every engine version, before its
>   duplicate-key scan and its parse. Its decoded documents are then the same on every engine,
>   and the loss stays visible.
> - Verdicts do not change. The signature covers the encoded bytes (§1). Every value a verifier
>   compares is ASCII (`typ`, `kid`, `iss`, `aud`, `deviceId`, channel names, versions), so a value
>   that contains U+0000 fails the comparison on every platform alike.
> - For each string value under a `jwsCases` `expect.doc` that contains U+0000, the generator
>   writes `expect.docNulReplaced`. It maps the value's RFC 6901 pointer to the value with every
>   U+0000 replaced by U+FFFD.
> - A runner on such a platform compares those values against `docNulReplaced`, and the rest of
>   the document as usual. Every other runner ignores the field.
> - An object key that contains U+0000 is outside this entry. The corpus has none, the generator
>   refuses to emit one, and no verdict for it is pinned yet (P3-01 decides it).
>
> This is the only declared representation limit, and it covers no other character. **[C]**

No change in `shared-protocol`, `shared-jws` or `client-core`. `PROTOCOL_VERSION` and
`CACHE_VERSION` stay 3.

**Clients and Workers already deployed** are unaffected:

- nothing on the wire changes, and no Worker code changes (one Worker test file does, §6);
- the new field exists only in test fixtures, which the shipped runners ignore (§4);
- no Godot SDK has shipped; the first release (P1-12) carries the rule from day one.

1. **Targets.**
   - Add `GODOT_V2_RESOURCES = join(HERE, "..", "sdks", "godot", "tests", "corpus", "v2")` beside
     `SWIFT_V2_RESOURCES` (`:34-46`). Its comment says why: an exported pack can read only `res://`.
   - `main()` (`:2334-2379`) builds one map from file name to content. It reconciles every entry
     into each directory of
     `CORPUS_TARGETS = [V2_DIR, SWIFT_V2_RESOURCES, GODOT_V2_RESOURCES]`.

       P1b-04's `headers.json` and `config-matrix.json`, and P3-02's matrices.
   - **Stray-file guard.** A top-level `*.json` in a target that the map does not name fails both
     modes, with `stray: <path> is not written by the generator`. It is never deleted
     automatically, so a dropped or renamed file cannot linger in a mirror.
     - Subdirectories are left to their owners (P4-04's `content/`).
2. **U+0000 annotation.**
   - `annotateNul(expect)` walks `expect.doc` depth-first in insertion order. For each string that
     contains U+0000, it records the RFC 6901 pointer (`~` as `~0`, `/` as `~1`) and the value with
     U+0000 replaced by U+FFFD.
   - It writes `docNulReplaced` after `doc`, and only when the map is not empty, so 35 of the 36
     cases stay byte-identical.
   - It throws on U+0000 in an object key, on a replacement that still contains U+0000 or equals
     the original, and on `docNulReplaced` without `doc`.
   - `buildJwsCases()` maps every case through it. `VerifyExpect` gains
     `docNulReplaced?: Record<string, string>`.
   - It is never applied to `bundleCases`. The Node and Python runners compare that whole `expect`
     object (`corpusV2.test.ts:464`, `test_conformance.py:249`). Any later section that pins a
     decoded document reuses the helper.
3. **Header comment** (`:1-19`): name both mirrors and the Godot runner. `:2119` is historical and
   stays.

### 5.4 `PKeyJws`: one deliberate behaviour change, in its own commit

- `_parse_strict_json` passes the UTF-8 text through `_nul_as_fffd()` before the duplicate-key scan.
- `_nul_as_fffd()` is one native `RegEx.sub` of the PCRE pattern `(?<!\\)((?:\\\\)*)\\u0000` with
  the replacement `$1\ufffd`, the six-character JSON escape, so no offset in the text moves. It
  runs only when the text contains `\u0000`, and it rewrites real escapes only.
- Measured on 4.7.2, 4.4.1 and the template:
  - `"a\u0000b"` becomes `a�b`, and two escapes in a row become `��`;
  - `"\\u0000"` stays text, and `"\\\u0000"` becomes `\�`.
- The check is not vacuous. Without the rule, 4.4.1 drops the NUL and `valid-nul-byte-in-string`
  fails (measured); 4.7.2 passes either way, so the 4.4.1 leg is what proves the rule.
- A NUL in a key now collides with a U+FFFD key and is rejected as a duplicate (fail closed). No
  corpus case exercises that.

### 5.5 Runner and suites

`tests/runner.gd` is `class_name PKeyTestRunner extends SceneTree`.

- **Selection.** Suites run only when the user arguments contain `--pkey-test <suite>[,<suite>]`.
  Anything after the list is passed to every suite; for example, `--pkey-test ed25519 bench 20`
  runs a timing loop for S-04.
- **Without `--pkey-test`**, `_initialize()` returns and the runner is a plain `SceneTree`.
- **The `ci` set** is `SETS["ci"] = ["sha512", "ed25519", "conformance"]`. Later packages append to
  it; `profile` stays outside it.
- **Suite contract.** A suite is `extends RefCounted` with
  `func run(t: PKeyTestContext, args: PackedStringArray) -> bool`, and the runner `await`s it.
  - A suite fails if it fails to load, returns anything but `true`, or reports zero checks.
  - Suites report only through `t.check(name, ok, detail)` and `t.info(text)`, from
    `tests/support/test_context.gd`.
- **Release-template rule.** Suites never use `assert` and never rely on a runtime error. Each one
  ends with a coverage check: vectors evaluated equals vectors loaded, with a floor (24, 26 twice,
  36).
  - A release template skips GDScript runtime checks (measured). A method call on null, a missing
    key or index read (which returns null) and `assert(false)` all continue silently.
  - The editor aborts the function instead.
  - The prototype's `profile` suite used `assert`; its adapted version uses `t.check`.
- **Output.**
  - The first line is
    `PKEY-TEST engine=… build=debug|release target=editor|template os=… arch=… sdk=0.1.0 suites=…`.
  - Then come `PASS|FAIL <suite> <name>` and `INFO` lines.
  - The last line is `PKEY-TEST SUMMARY suites=N checks=N failed=N`.
  - The exit code is 1 on any failure.
- **The runner's own dependencies** are only `polaris_key.gd` (for the version) and
  `test_context.gd`. A broken addon file therefore fails one suite cleanly instead of the runner
  (measured).
- **`suite_conformance.gd`:**
  - It reads `res://tests/corpus/v2/cases.json`, parses it with `JSON.new().parse()` and checks the
    `Error`.
  - It prints `FileAccess.get_sha256()` of the mirror, and checks `corpusVersion == 2` and at least
    36 `jwsCases`.
  - It self-checks the comparator: a copy of the first document with one extra key must compare
    unequal. `Dictionary ==` ignores key order and catches leaf and array-order changes (measured).
  - For each case, it checks the verdict, then the `kid` on `ok`. It calls
    `PKeyJws.verify(c.jws, c.trust, c.typ, int(c.get("maxPayloadBytes", 0)))`.
  - Where there is a document, it deep-copies `expect.doc` and writes each `docNulReplaced` value at
    its pointer, decoding `~1` and then `~0`. The pointer must resolve to a `String`, and the value
    must contain U+FFFD. It then checks `payload == doc`.
  - No case id appears in the suite.
- **`suite_sha512.gd` and `suite_ed25519.gd`** keep the prototype's vectors. Ed25519 checks all 26
  on `PKeyEd25519` and on `PKeyEd25519Ref`. Timing is `INFO`, never a check.

### 5.6 `tools/run_tests.sh`, `tools/fetch_godot.sh` and the CI job

`run_tests.sh` is committed with mode 100755 and written for bash 3.2 (macOS `/bin/bash`). It uses no
GNU `timeout`.

- **Variables:**
  - `GODOT_BIN` defaults to `godot` on `PATH`; if none is found, the script exits 2 and never skips;
  - `GODOT_TEMPLATE` is optional;
  - `PKEY_TEST_SUITES` defaults to `ci`;
  - `PKEY_TEST_TIMEOUT` is per step, default 300 s.
- **Setup.** It recreates `build/`, with `build/.gdignore` and `build/logs/`.
- **Steps:**
  1. `--import`, retried once only on a signal exit, because notes/A5 saw one SIGABRT;
  2. when `git` is available and the project is inside a work tree, fail if any `.uid` under
     `sdks/godot` is untracked (`git status --porcelain --untracked-files=all`);
  3. the editor run: `"$GODOT_BIN" --headless --path sdks/godot -- --pkey-test "$PKEY_TEST_SUITES"`;
  4. with `GODOT_TEMPLATE` set:
     - `--export-pack "Conformance (Linux)" build/pkey_conformance.pck`;
     - copy the template to `build/pkey_conformance.x86_64`;
     - run `build/pkey_conformance.x86_64 --headless -- --pkey-test "$PKEY_TEST_SUITES"`.
- **Each step** runs in the background with its log in `build/logs/<step>.log`, which is polled every
  second.
  - It is killed and failed on
    `SCRIPT ERROR|Parse Error|Failed to load script|Cannot get class|Invalid MainLoop`. The patterns
    also match 4.4.1's coloured output.
  - They must not match a generic `ERROR:`. A slim container prints fontconfig errors on every
    run (measured).
  - A step also fails on the timeout, on a non-zero exit, or (for runs) without a final
    `PKEY-TEST SUMMARY … failed=0`.
- **Measured:**
  - green in 11 s on this Mac (import, editor, export and template);
  - a broken runner is caught in 4 s on both engines, and a broken `jws.gd` in 6 s;
  - a one-byte corruption of a mirror document is caught in 5 s;
  - a script without its `.uid` is caught immediately.
- **Root `package.json`:** `test:all` gains `&& sdks/godot/tools/run_tests.sh`.

**`fetch_godot.sh <version> <dir> [--template]`** does nothing if `<dir>` already holds the
binaries, as it does after a cache hit. Otherwise it:

- downloads with `curl -fsSL` from `github.com/godotengine/godot/releases/download/<v>-stable/`;
- checks each file against its line in `sdks/godot/tools/godot.sha512`, with `sha512sum -c`, or
  `shasum -a 512 -c` where `sha512sum` is missing (macOS);

**The CI job `godot`** is appended to `.github/workflows/ci.yml`:

  runs-on: ubuntu-latest

    fail-fast: false
    matrix:
      include:

          godot: "4.4.1"

    - uses: actions/cache@v4

        path: ~/.cache/pkey-godot/${{ matrix.godot }}

    - run: >-
        sdks/godot/tools/fetch_godot.sh "${{ matrix.godot }}"

        D="$HOME/.cache/pkey-godot/${{ matrix.godot }}"

## 8. Decisions and risks

The research left four decisions open, and measuring raised six more. Each is resolved here for the
lead to approve.

1. **U+0000: option (a), made exact.** A corpus annotation plus a §10 entry, U+FFFD on every engine,
   and an exact assertion.
   - **Why annotate at all.** A Godot-only comparison passes vacuously, because both sides go
     through the same lossy parser (PARITY §6.3 #4).
   - **Why not a pointer mask** (the first draft). A mask checks only the type, so 4.4.1's dropped
     NUL would pass and the MUST would go untested.
   - **Why U+FFFD rather than dropping.** It is Unicode's replacement character and 4.7's own
     behaviour. It keeps the length and keeps the loss visible. Dropping can turn one meaningful
     string into another (`ad\u0000min` becomes `admin`). It can collide with a literal U+FFFD at
     the same position; the claim is determinism, not injectivity.
   - **Why not (b).** It flips a vector in every shipped SDK for one platform's limitation.
   - **Keys.** P3-01 decides U+0000 in keys, and control characters, with report §9.1 #19's JSON
     edge vectors. Its item 14 ("keep, or reject") is settled by this entry.
2. **Mirror path `sdks/godot/tests/corpus/v2/`.** The release zip ships only `addons/polaris_key/`,
   so no vectors reach games.
3. **Engines: the 4.7.2 editor, the 4.7.2 template and the 4.4.1 editor.** 4.4.1 is the latest 4.4.x.
   - The prototype passes on 4.4.1 unchanged, and so does the layout above. That includes the
     Linux x86_64 editor that CI uses (measured).
   - The floor stays 4.4 with no syntax fixes.
   - 4.5 and 4.6 legs are left for P1-12, before it states a tested range.
4. **Template: the full `.tpz` on a cache miss, checked against upstream SHA-512, with only the
   extracted binary cached.** A Range fetch of the single member (28.3 MB, measured) cannot check
   the upstream hash, and it needs a custom zip client.
5. **No boot guard.**
   - When the main-loop script fails to load, `main/main.cpp:4394-4410` (at `4.7.2-stable`) calls
     `OS::alert()` and returns `EXIT_FAILURE`. The main scene never loads, so no scene script can
     help.
   - The watchdog and the SUMMARY line are the guard (table below).
6. **Explicit checks only.** Release templates silence runtime errors, so the rule in §5.5 binds
   every later Godot suite.
7. **Our own tooling.**
   - `fetch_godot.sh` rather than `chickensoft-games/setup-godot` (report §5.11): no third-party
     action runs with the checkout, every archive is hash-checked, and the pins drive the cache key.
   - A main-loop runner rather than GUT or gdUnit4 (notes/E4 §7): both start through `-s`, which
     official 4.6+ templates ignore, and neither is needed for pure-function vectors.
8. **The prototype keeps its runner and probe suites; only SDK code and SDK suites move.**
   - S-06's outlet harness and its brief's Verify line run the prototype project through `cli.gd`.
   - The SDK runner is a rewrite, so moving `cli.gd` would carry no useful history.
   - Moving it would also force the prototype's `project.godot` to drop `run/main_loop_type`.
     Otherwise every prototype run would hit the missing-main-loop alert of decision 5.
   - S-04's harness, which copies the prototype addon, gets a pointer to the pre-move commit (§7).
9. **The parity manifest is created here**, with every feature `planned` under the owner rule and
   table in §5.1, and three features unowned.
10. **The raw NUL in `gen-reference.mjs` becomes an escape.** The file stops being binary to git, so
    this PR's edit is reviewable and later edits can merge (§6).
