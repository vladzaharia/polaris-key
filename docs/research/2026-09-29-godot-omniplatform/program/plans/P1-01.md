# P1-01 plan: `sdks/godot`, its corpus mirror and the `godot` CI job

This is the plan for [P1-01](../wp/P1-01-godot-scaffold.md). `pkey-wire-planner` wrote it and
`pkey-godot-engineer` implements it once it is approved. The implementation follows the brief's
Scope, plus the decisions below. Where the two differ, this plan wins.

Facts marked **(measured)** were run on 2026-09-30 against the official 4.7.2 and 4.4.1 builds.

## 1. Summary

- **Scaffold.** `sdks/godot/` becomes a Godot 4 project. The prototype verifier moves in with its
  history and takes the `PKey` prefix, and a headless runner is the project's main loop.
- **Sixth corpus language.** Godot runs the 36 `jwsCases`, the 24 SHA-512 vectors, and the 26
  Ed25519 vectors against both of its verifiers (`PKeyEd25519` and `PKeyEd25519Ref`).
- **Mirror.** `tools/sign-corpus.ts` writes a second mirror at `sdks/godot/tests/corpus/v2/`, which
  `pnpm gen:corpus -- --check` guards the same way as Swift's.
  - No vector changes.
  - `corpusVersion` stays 2 and `PROTOCOL_VERSION` stays 3.
- **One additive field.** A generated field, `expect.docNulPointers`, lists the U+0000 strings in a
  `jwsCases` document (today only `valid-nul-byte-in-string`), and a WIRE-CONTRACT-V3 §10 entry
  documents it. Godot's runner masks those strings; every other runner ignores the field.
- **CI.** A new job, `godot`, runs on the 4.7.2 editor, on the official 4.7.2
  `linux_release.x86_64` template (as an exported pack), and on the 4.4.1 editor, which is the
  floor.
- **Docs.** The corpus, runner and gate text names Godot, and `reference/corpus.mdx` is
  regenerated.

## 2. Contract

`docs/security/WIRE-CONTRACT-V3.md` gets two changes:

- **§10** gains the paragraph below.
- **The header's Conformance line** gains "(one declared representation limit, §10)".

The Scope line's SDK count stays for P1-12.

> **Platform string representation.** GDScript's `String` cannot hold U+0000. Godot's JSON parser
> drops it (4.4) or replaces it with U+FFFD (4.7). Verdicts do not depend on this, because the
> signature covers the encoded bytes (§1). A decoded string that contains U+0000 cannot be
> byte-identical there, and such an implementation MUST decode U+0000 as U+FFFD rather than drop
> it, so that two distinct signed strings never decode as equal.
>
> Where the `expect.doc` of a `jwsCases` entry has string values that contain U+0000, the generator
> lists their RFC 6901 pointers in `expect.docNulPointers`. A runner on such a platform masks
> exactly those values on both sides and compares the rest. Every other runner ignores the field
> and compares byte for byte.
>
> This is a limit on representation, not a tolerance: no verdict may differ, and it covers no other
> character.

Nothing changes in `shared-protocol`, `shared-jws` or `client-core`. `PROTOCOL_VERSION` and
`CACHE_VERSION` stay at 3.

Deployed clients and Workers are unaffected: nothing on the wire changes, the new field lives only
in test fixtures, and no Godot SDK has shipped yet.

## 4. Corpus

`tools/sign-corpus.ts` changes in three places:

1. **`GODOT_V2_RESOURCES`** is set to `sdks/godot/tests/corpus/v2`, next to
   `SWIFT_V2_RESOURCES`.
   - `main()` writes every file to each directory in
     `CORPUS_TARGETS = [V2_DIR, SWIFT_V2_RESOURCES, GODOT_V2_RESOURCES]`. Later files therefore
     reach both mirrors by construction: P1-09's `stage-matrix.json`, P1b-04's `headers.json` and
     P3-02's matrices.
   - A stray `*.json` file in any target fails both the write and `--check` modes.
2. **`nulStringPointers(doc)`** returns, in document order, the RFC 6901 pointers of every string
   value that contains U+0000.
   - It throws on U+0000 in an object key, because no runner could mask one there.
   - `buildJwsCases()` sets `expect.docNulPointers` whenever the list is not empty, and
     `VerifyExpect` gains the field as optional.
   - Any later section that pins a decoded document reuses the helper. P3-02 and the pack plans
     must say so.
3. **The header comment** (`:1-13`) names both mirrors and the Godot runner.

**Output**

- `cases.json` changes in one hunk, in the source and in both mirrors:
  `valid-nul-byte-in-string` gains `"docNulPointers": ["/profile/name", "/profile/firstName"]`
  after `doc`.
- `gate-matrix.json` and `fingerprint.json` do not change.
- The Godot mirror is new, at 1.47 MB. The generator formats it with prettier, so it needs no
  `.prettierignore` entry.
- The version constants do not move: `corpusVersion` 2, `gateMatrixVersion` 2,
  `fingerprintVersion` 1.
- The drift gate is `pnpm gen:corpus -- --check`, run in the CI `js` job and the pre-commit hook.

The existing runners ignore the field (checked in the code):

| Runner | Why the field is ignored                                                                        |
| ------ | ----------------------------------------------------------------------------------------------- |
| Node   | reads only `verify`, `kid` and `doc` (`conformance/runners/node/corpusV2.test.ts:188-208`)      |
| Python | reads the same three fields (`sdks/python/tests/test_conformance.py:74-94`)                     |
| Swift  | its synthesised `Decodable` for `JwsExpect` skips unknown keys (`ConformanceTests.swift:55-61`) |
| React  | has no `jwsCases` runner                                                                        |

Only `bundleCases` compares the whole `expect` object (`corpusV2.test.ts:464`,
`test_conformance.py:249`), so the field must never be added there.

**The Godot project.** These are the decisions beyond the brief:

- **Move.**
  - The first commit is a pure `git mv`, so `git log --follow` survives even a squash. The crypto
    files stay more than 99% similar.
  - Each `.uid` moves with its file (`cli.gd.uid` → `runner.gd.uid`).
  - `tests/http_probe.gd` stays in the prototype, because D-01 cites it.
  - `vectors/gen_corpus.mjs` is deleted, because the mirror supersedes it.
  - `PKeyJws` keeps the prototype signature, including the `fast := true` test seam. P1-02
    reshapes it.
- **Project files.**
  - `project.godot` enables the addon under `[editor_plugins]`, so every import parses
    `plugin.gd`.
  - It has no `config/features`, which would pin it to 4.7. The 4.4.1 import leaves it untouched
    (measured).
  - `polaris_key.gd` is `extends Node` with no `class_name`, because `PolarisKey` is the autoload
    name P1-02 registers.
  - The `Conformance (Linux)` preset adds `runnable=true`, `exclude_filter="build/*"` and
    `binary_format/architecture="x86_64"`.
  - Every `.gd` file has its `.uid` committed, generated by the 4.7.2 editor.
- **Runner protocol.**
  - A suite is `func run(t: PKeyTestContext, args: PackedStringArray) -> bool` and the runner
    `await`s it. A suite that does not load, or returns anything but `true`, fails; that includes
    a runtime error, which returns null.
  - Suites report through `t.check()` (`tests/support/test_context.gd`), never through `assert` or
    `push_error`.
  - Arguments after the suite list are passed through, for example `ed25519 bench 20` for S-04.
  - `ci` means `sha512,ed25519,conformance`. The `platform` and `profile` suites stay out of it.
  - The first output line is
    `PKEY-TEST engine=… build=… target=editor|template os=… arch=… sdk=0.1.0 suites=…`. The last is
    `PKEY-TEST SUMMARY suites=N checks=N failed=N`.
- **Boot guard.** When the runner fails to load, Godot falls back to a plain `SceneTree` and runs
  the main scene forever (measured on both engines).
  - `main.tscn` therefore carries `tests/support/boot_guard.gd`.
  - The guard fires when the tree has no script and `--pkey-test` was passed. It prints
    `PKEY-TEST FATAL` and quits with code 3.
- **`suite_conformance.gd`.**
  - It parses the mirror with `JSON.new().parse()`, checks the returned `Error`, and prints the
    mirror's SHA-256.
  - It asserts `corpusVersion == 2` and that there are at least 36 `jwsCases`.
  - It self-checks its comparator first: `valid-stable`'s doc with one leaf changed must compare
    unequal. `Dictionary ==` ignores key order and does catch leaf changes (measured).
  - Each case asserts the verdict, then the `kid` on `ok`. Where there is a doc, it asserts
    `payload == doc` after masking every `docNulPointers` value on both sides; each pointer must
    resolve to a `String`.
  - No case id appears in the suite.
- **`tools/run_tests.sh`** (bash 3.2, as macOS ships).
  - A missing `GODOT_BIN` exits 2; the script never skips.
  - `--import` is retried once, and only on a signal exit, because notes/A5 saw one SIGABRT.
  - An untracked `.uid` left after the import fails the run: a script was committed without its
    sidecar.
  - Each Godot call logs to `build/logs/<step>.log`. A watchdog polls the log every second.
  - The call fails if the ANSI-stripped log matches
    `SCRIPT ERROR|Parse Error|Failed to load script|Cannot get class`. The strip is needed because
    4.4.1 colours its errors even into files.
  - It also fails after 600 s, or on a non-zero exit. A test run also fails unless its SUMMARY line
    reads `failed=0`.
  - The root script `test:all` gains `&& sdks/godot/tools/run_tests.sh`.
- **CI job `godot`.**
  - It runs on `ubuntu-latest` with `timeout-minutes: 20` and `fail-fast: false`, and permissions
    stay `contents: read`.
  - There is no path filter, because a required check behind a path filter never reports.
  - The two legs are `Godot SDK (4.7.2 editor + release template)` and
    `Godot SDK (4.4.1 editor, floor)`.
  - `actions/cache@v4` caches `~/.cache/pkey-godot/<version>`, keyed
    `pkey-godot-<version>-linux-x86_64-v1`.
  - On a cache miss, the job fetches with `curl -fsSL` and checks each file with `sha512sum -c`
    against the upstream `SHA512-SUMS.txt` values below.
  - It unzips the editor. From the `.tpz` it extracts only `templates/linux_release.x86_64`
    (`unzip -j`), then deletes the `.tpz`.
  - It exports `GODOT_BIN`, plus `GODOT_TEMPLATE` on the 4.7.2 leg, and runs `run_tests.sh`.
  - Afterwards, `git diff --exit-code -- sdks/godot` must pass and
    `git status --porcelain -- sdks/godot` must be empty.
  - On failure, it uploads `build/logs/`.

## 8. Risks and decisions

The research left four decisions open. Each is resolved here for the lead to approve.

1. **U+0000: option (a), refined.**
   - **Why it needs refining.** When Godot parses both sides, the document comparison passes
     vacuously: 4.7.2 turns U+0000 into U+FFFD on both, and 4.4.1 drops it from both (measured).
     A plain runner would claim a round trip that never happened.
   - **What the refined version does.** The corpus declares the affected strings and the runner
     masks them. This works on every engine, and it survives P1-02's `PKeyJson`, which must also
     produce U+FFFD on 4.4.
   - **Why not (b).** It changes every SDK and flips a vector, and control-character rules belong
     to P3-02.
   - **Known gap.** Until P1-02 lands, the prototype parser drops the NUL on 4.4.1. The mask
     covers this, and no verdict is affected.
2. **Mirror path: `sdks/godot/tests/corpus/v2/`.** The release zip ships only
   `addons/polaris_key/`, so no vectors reach games.
3. **Engines: the 4.7.2 editor, the 4.7.2 template and the 4.4.1 editor.** 4.4.1 is the latest
   4.4.x; there is no 4.4.2.
   - The unchanged prototype passes on 4.4.1: SHA-512 24/24, Ed25519 26/26 on both verifiers, and
     `jwsCases` 36/36 (measured).
   - The `main_loop_type` runner also works there without `--script` (measured).
   - So no syntax fixes are needed, and the floor stays at 4.4.
4. **Template: download the full `.tpz`, then cache the extracted binary.**
   - The download is checked against the SHA-512 upstream publishes, and it only happens on a cache
     miss.
   - A single-member Range fetch also works (28.3 MB, measured), but it cannot check that SHA-512
     and it needs a custom client.

**Risks.**

- **Parse errors are silent.** `--import` exits 0 on both engines and `--check-only` exits 0 on
  4.7.2 (measured). Only the watchdog, the boot guard and the SUMMARY line catch a broken script.
- **Not runnable on this host:** a green CI run, the parse-error run in CI, the Linux x86_64
  template, and the required-check setting. Two local stand-ins exist:
  - the macOS 4.7.2 release template runs the Linux-preset pack (measured: 36/36,
    `template=true`);
  - `docker --platform linux/amd64 ubuntu:24.04` replays the Linux legs.

**Brief edits.**

- **Made with this plan:** P1-01's brief, covering the inventory, the pitfalls, and decisions 1
  and 3.
- **Due in the implementation PR:**
  - **P1-02:**
    - an acceptance row requiring that `PKeyJson` decodes `\u0000` as U+FFFD on both engines;
    - the runner protocol;
    - the fingerprint text.
  - **P3-02:** point it at `sdks/godot/tests/vectors/`.
  - **S-04 and S-06:** use `godot --headless --path sdks/godot -- --pkey-test ed25519|platform`.
