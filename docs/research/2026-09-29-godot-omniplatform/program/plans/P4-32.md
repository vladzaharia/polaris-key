**Verdict: this does not change the wire contract. It adds conformance evidence for behaviour
that already exists.** WIRE-CONTRACT-V4 §11.4 (with §2.6: "bundles are blobs") already fixes the rule: one single-range request
per run with `If-Range: "<bundle sha256>"`, an exact `bytes o-e/<size>` on the `206`, a `206`
clipped at the end of the object, and "any other answer fails the strategy". `blobResponse`
(`packages/worker/src/core/blobs.ts`) already serves that rule. Every SDK's `chunkRangeFetch`
already enforces it. The only things that change are the test-side transcript format (a new
action and one more recorded response header), the feature registry's proof list, and the
replayers.

## 4. Corpus and transcripts

The content corpus is untouched. `pnpm gen:corpus -- --check` must stay clean.

**Transcript format** (`packages/worker/test/transcripts/format.ts`, documented in its header):

- `Action` gains `"chunkRange"`, with args `{ bundle: <hex sha256>, offset, length }`. The step is
  the SDK's chunk-range fetch (client-core `chunkRangeFetch`, Python `chunk_range_fetch`, Swift
  `chunkRangeFetch`, Godot `PKeyPackChunks.chunk_range_fetch`). It runs over the SDK's own pack
  object transport, against the discovered `distribution.endpoints.blobs` template.
- `chunkRange` has two `expect` keys:
  - `range`: `"ok"` or `"refused"`;
  - `bytes`: the returned body as a string, present only on `"ok"`. A clipped `206` returns fewer
    bytes than `length`.
- `RECORDED_RESPONSE_HEADERS` gains `"content-range"`. The existing transcripts carry no range
  response, so their files must come out byte-identical. The check in §9 proves it.
- `recorder.ts` `ExchangeSpec` gains two optional fields:
  - `assertHeaders`: sent and asserted by value;
  - `presentHeaders`: sent, and asserted by presence (added to `requiredHeaders`).

**Scenario** (new `packages/worker/test/transcripts/scenarios/packs.ts`, listed in
`scenarios/index.ts`):

- **World.** Product `djdl` with `release` and `distribution` on, and an `R2Mock` as `BLOBS`, as
  in `packTransports.test.ts`. Do not set `BLOB_ORIGIN`, so the blobs template stays on
  `https://key.plrs.im`.
- **Fixture.** The bundle is the 64 ASCII bytes `0-9a-zA-Z-_`. It is staged as a public pack
  object through the same `uploads` + `stage` publish routes that `packTransports.test.ts`'s
  `stage()` uses. That path writes a `pack-upload` ref and does not parse the content. Factor
  `stage()` and `access()` into `test/seed.ts` if both files need them. Setup requests are not
  recorded.
- **Transcript fields.** `features: ["packs.apply.chunk"]`, `requires: []`, no `initial.token`,
  and `initial.services: ["release", "distribution"]`. Every blob exchange uses
  `metadata: false`, because React's browser transport sends no `X-PKey-*` headers. No exchange
  asserts `Accept-Encoding`: undici adds it in Node, browsers forbid it, and each SDK's own
  fake-server tests keep covering it.

| Step         | Request (asserted)                                                                                     | Recorded response                                                 | `expect`                     |
| ------------ | ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------- | ---------------------------- |
| `discover`   | `GET /djdl/.well-known/polaris.json`                                                                   | `200`, with `distribution.endpoints.blobs`                        | `result: ok`, `services`     |
| `chunkRange` | `GET /djdl/distribution/blobs/sha256/<hex>`, `range: bytes=16-39`, `if-range: "<hex>"` (both by value) | `206`, `content-range: bytes 16-39/64`, `etag: "<hex>"`, 24 bytes | `range: ok`, `bytes`         |
| `chunkRange` | `range: bytes=48-79`, `if-range: "<hex>"` (both by value)                                              | `206`, `content-range: bytes 48-63/64`, 16 bytes                  | `range: ok`, 16-byte `bytes` |
| `chunkRange` | `range: bytes=16-39` by value; `if-range` by **presence** (the recorder sends `"<64 zeros>"`, see Q1)  | `200`, `etag: "<hex>"`, the whole 64 bytes                        | `range: refused`             |

As it records, the scenario asserts each status, `Content-Range`, `ETag` and body. Each recording
also checks the server side: `Repr-Digest` is present and `Content-Encoding` is absent.

**Regeneration.** Run `pnpm build`, then `pnpm gen:transcripts`. This writes the canonical file
and the generator-owned mirrors, `sdks/swift/Tests/PolarisKeyTests/Resources/transcripts/` and
`sdks/godot/tests/transcripts/`. Python, Kotlin, Node and React read the files in place.

## 5. SDKs, in order (all in P4-32 unless stated)

Each replayer's header gains the tag `@pkey-feature packs.apply.chunk`. Each replayer also gets
one doctored case: a recorded `content-range` altered to `bytes 17-40/64` must fail the step's
`expect`. No public API changes.

1. **Node.** `conformance/runners/node/transcripts.test.ts` runs client-core's `chunkRangeFetch`

2. **React.** The `fetchObject` closure in `packages/sdk-react/src/packs/browserPacks.ts` becomes

   `packages/sdk-react/test/transcripts.test.ts` maps `chunkRange` over that export. React must
   replay because rule 6 applies the transcript to React: React implements the feature, and the
   transcript requires nothing React marks `na`.
3. **Python.** `sdks/python/tests/test_transcripts.py` (and `transcript_replay.py` if needed)

4. **Swift.** `PacksClient.fetchObject` changes from `private static` to `internal static`.

5. **Godot.** `tests/suite_transcripts.gd` and `tests/support/transcript_replay.gd` call

## 8. Risks and open questions (owner decisions)

- **Q1: the `If-Range` miss.** The blobs URL is content-addressed, and every SDK derives
  `If-Range` from that same hash. So no SDK can send a validator that misses. Options:
  - **A (recommended):** record the miss with the stale validator sent and asserted by presence
    only. The scenario proves the Worker's `200`, and the replay proves that the SDK refuses a
    `200` to its own `If-Range`.
  - **B:** add a test-only `ifRange` override to every SDK's chunk fetch.
  - **C:** keep the `200` as a Worker-only assertion, outside the file.
- **Q2: the bundle bytes.** Options:
  - **A (recommended):** use an ASCII fixture staged as a pack upload, with no format change.
  - **B:** publish a real zstd bundle through pack ingest. Transcript bodies are strings, so this
    needs a new base64 body field, which is a format change in all six replayers.

  Decoding is already proven by the content corpus (`chunkIndexCases`, chunk `applyCases`).

- **Q3: React and Kotlin scope.** React is included because rule 6 forces it; the alternative
  is to make the transcript require `core.store` only to exclude React. For Kotlin the plan adds
  no graph dependency, and whichever of P4-32 and P6-08 lands second maps Kotlin. Recommended:
  as written.
- **Risk:** Godot's `PKeyFakeServer` may not support `open_range` pull bodies. If not, add that
  to the replay support. Do not fall back to a different fake.
