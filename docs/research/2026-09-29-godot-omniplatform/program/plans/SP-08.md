## 0. Owner decisions honoured

- **SDK-PARITY-PASS Q4 (2026-10-05):** canonical `tvos`, `visionos`, `watchos`, not `ios`.
- **S-19:** the licence is the access contract, made of grants; the holder is the account signed
  in on the device; legacy products stay byte-identical. The platform header feeds no licence,
  grant, seat or holder decision (§5.2 rule 3: "No server decision reads these headers"), and no
  signed document carries it. Legacy-mode licence bytes therefore cannot change.
- **S-16 / S-17:** identity is not touched. Cloud Sync's `scope: platform` families (U-01 Q8,
  approved) need a family for each new value, fixed in §8 D6.
- **S-18:** no new setting or flag. The Worker change is a table entry; products stay data.

## 1. Summary

- `X-PKey-Platform` (WIRE-CONTRACT-V4 §5.2) gains `tvos`, `visionos` and `watchos`.
  `PLATFORM_SPELLINGS`, the parity enum `platform` and `headers.json` carry them.
- A native tvOS, visionOS or watchOS build of the Swift SDK sends them, and so does Godot's
  visionOS export. An iPad app running on visionOS still sends `ios`, because the binary is iOS.
- The Worker canonicalises and stores them through the shared table, which takes no code change.
  The console labels them.
- **What the device is offered does not change.** `RELEASE_PLATFORMS`, `OUTLET_PLATFORMS`, the
  feed's `?platform=`, `outlet-matrix.json` and `update-matrix.json` keep their six values. An
  SDK whose platform is outside `OUTLET_PLATFORMS.unknown` has no update platform and behaves
  exactly as it does today (§2 rule 5).

## 2. Contract

**`docs/security/WIRE-CONTRACT-V4.md` §5.2** (the bracketed `[C]` stays):

- Table row: `X-PKey-Platform` = `macos`, `ios` (iPadOS too), `tvos`, `visionos`, `watchos`,
  `android`, `windows`, `linux`, `web`.
- Examples: keep "an iPad app running on a Mac or on visionOS sends `ios`" and add "a native
  visionOS build sends `visionos`".
- **New rule 5. Header vocabulary and update vocabulary.**
  - The build and update vocabularies keep six values: `RELEASE_PLATFORMS`,
    `OUTLET_PLATFORMS.unknown`, the feed's `?platform=` and `targets[].platform` targeting.
  - An SDK's _update platform_ is its header value when that value is in its mirror of
    `OUTLET_PLATFORMS.unknown`, and no value otherwise.
  - With no value, the SDK takes today's path for a platform with no canonical value:
    - Swift throws `not_configured` unless `UpdateClientOptions.platform` is set;
    - Godot uses `""`.
  - A later package that ships tvOS or visionOS builds widens both vocabularies (out of scope).
- **§6.1:** the informative fingerprint column `iOS` becomes "iOS, iPadOS, tvOS, visionOS,
  watchOS" (`identifierForVendor`, `hw.machine`, rule 3). `fingerprint.json` is not keyed by
  platform and does not change.

**`packages/shared-protocol/src/core.ts`:** `PLATFORM_SPELLINGS` gains `tvos: "tvos"`,
`visionos: "visionos"` and `watchos: "watchos"`. `ClientPlatform` widens with it.
`test/exports.test.ts` pins the new table. `distribution.ts` is **unchanged**.

**`packages/client-core`:**

- `canonicalPlatform` is unchanged; its return type widens.
- `test/headers.test.ts` adds `tvOS` → `tvos`, `visionOS` → `visionos` and `WATCHOS` → `watchos`
  (ASCII folding).

**`packages/shared-jws`:** untouched.

**`conformance/parity/enums.json`:**

- `platform.values` appends `tvos`, `visionos`, `watchos` after `web`.
- The description becomes "… iPadOS is `ios`. `tvos`, `visionos` and `watchos` are header values
  only; build targets are `RELEASE_PLATFORMS` (WIRE-CONTRACT-V4 §5.2 rule 5)."

**Clients and workers already deployed:**

- **Old Workers** already store an unlisted value as sent (rule 3), and a new SDK sends the
  lowercase canonical value. The stored row is therefore identical before and after the Worker
  deploy.
- **Old SDKs** on these OSes send no header today:
  - Swift's `compileTimeToken` is nil off macOS, iOS, Linux, Windows and Android.
  - Godot's table lacks `visionos`.
  - The device row keeps `platform` NULL until an upgraded SDK writes it (the `?? existing` merge
    fills a NULL).
- **Old SDKs on iPad-compatible visionOS apps** send `ios`, which stays correct.
- No client refuses anything because of this change.

## 8. Owner decisions (delegated to Claude, 2026-10-05)

1. **D1 Enum order.** Append after `web`, so no existing generated constant moves.
2. **D2 Spellings.** Six rows: an identity row and the OS token for each value. No `xros`,
   `appletvos` or simulator aliases, because no SDK reports them.
3. **D3 Update and release vocabularies stay six** (rule 5). A tvOS or visionOS build,
   `ASC_PLATFORM_TO_RELEASE` for `TV_OS` and `VISION_OS`, outlets and feeds are a later work
   package, created when a product ships such a build. This keeps the brief's "Out" list.
4. **D4 Device facts.** `os.name` reports the canonical value on these OSes. Today it reports
   `unknown`, and no decision reads it.
5. **D5 Convergence migration.** Yes. It is cheap and idempotent, and it covers any pre-§5.2
   Godot that sent `visionOS` raw.
6. **D6 Cloud Sync families (U-01 Q8):**
   - `tvos` → `console`: a ten-foot, controller-first screen;
   - `visionos` → `mobile`: an iPad-compatible app on visionOS already reports `ios`, so settings
     stay continuous when the app goes native;
   - `watchos` → `mobile`.
7. **D7 Parity runtimes.** The `tvos`, `visionos` and `watchos` runtimes, Swift's manifest
   `runtimes` and their `allowedNa` land with SP-S16, which owns Swift's support for these OSes.
   Godot's `visionos` runtime lands with Godot's visionOS export support. SP-08 declares no
   support.
8. **D8 Display names.** The console and portal labels are part of SP-08. The UI-kit strings come
   through SP-00's copy catalog.

**Risks.**

- A pre-§5.2 SDK may have stored a free-form string, which D5 cannot fix. Rule 3 already accepts
  that.
- If Godot's `get_name()` spelling is wrong, a row fails. §4 makes checking it a step.

**Brief changes** (lead, after approval):

- **SP-08:** reads `RELEASE_PLATFORMS`; points to this plan's steps; adds §9 as the acceptance.
- **SP-00:** nine `platform.*` copy rows; runtimes deferred to SP-S16.
- **U-05:** D6's families in the Core family function.
- **SDK-PARITY-PASS §5.4 SP-S16:** "the platform header waits on W8" becomes "the header ships with
  SP-08; add the runtimes, CI jobs and `Package.swift` platforms".
