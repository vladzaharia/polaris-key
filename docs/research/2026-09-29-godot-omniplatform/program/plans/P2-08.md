# P2-08 plan: built-in `dev` release track and default store track maps

> **Approved (2026-10-09)** by the lead under delegated authority, with the recommendation on all five decisions (include chain dev ⊇ beta ⊇ stable with a declared dev winning; applied in the Worker tier and license write path; default track maps as a constant in shared-manifest; the pure stale-track helper; the default store lanes as listed). A product that publishes to an undeclared `dev` starts to include beta and stable builds unless it declares `includes: []`: call that out in the changelog.

Role: `pkey-wire-planner` (plan), `pkey-implementer` (code, after approval). Branch `plan/P2-08`, from `integ/ux-docs`. Brief: `wp/P2-08-built-in-dev-release-track-default-store.md`. Contract-adjacent, not wire-changing: no signed document, `typ`, claim, header, corpus file or `PROTOCOL_VERSION` changes.

## 1. Summary

- `dev` becomes a built-in release track beside `stable` and `beta`, with includes `dev ⊇ beta ⊇ stable`. A product's declared `dev` (manual channel or `.pkey/release` `channels`) keeps priority, exactly as `staging` does.
- The Worker teaches `classifyChannel` a `dev` selector. Today `/update/dev/feed.jws` and every other `{channel}` route 404 for `dev` unless the product declares it, because `channels.ts:58-84` returns `null` (found while planning; P2-12 §7 already requires it). The signed feed's `channel` claim is already an arbitrary canonical name, so the feed shape is unchanged.
- The Play, TestFlight, Steam, Microsoft Store and Snap outlets get default track maps, used unless the product declares a map. One constant in `shared-manifest`; connectors and the CLI read it through one resolver.
- Choosing `dev` for a tier or licence stores `["beta","dev"]`, applied once on the write path. The wire predicate (V4 §5.1 rule 4) is untouched.
- Corpus, signed documents and SDKs: **no change**. The gate-matrix already pins `dev` (header, grant, build-implied channel).

## 2. Contract

- `docs/security/WIRE-CONTRACT-V4.md` §5.1 table: the `dev` row changes from "Release has none" to "built in, the top of the include chain; also the gate pseudo-channel of `0.0.0-dev*` builds", Valid as `header, selector, grant`. A sentence under the table states `dev ⊇ beta ⊇ stable` and that "dev includes beta" is stored by the editors, never inferred by the gate. Rules 1-6 and `channelEntitled` (`core/channels.ts:102-112`) are untouched; the "Amended by" header line gains `plans/P2-08.md` (docs only, no new `typ`, claim or shape).
- `packages/shared-protocol`, `shared-jws`, `client-core`: none. `PROTOCOL_VERSION` stays 4, `corpusVersion` stays 2. Update decisions in client-core key floors and staged updates by the feed's `channel` claim and never enumerate names.
- Old clients: an SDK or app sending `X-PKey-Channel: dev` is gated exactly as before. A `0.0.0-dev` build still bypasses the version window through a `dev` grant until P2-14 splits it (R3-01); the picker hint says so (section 6).

## 3. Catalog and manifests

- `shared-manifest/src/index.ts:1155`: `BUILT_IN_CHANNELS = ["stable","beta","dev"]`. Its five readers follow with no further edit: `knownChannelNames` (`:3195`), pack-channel reachability (`:4055`, error text "stable, beta or one of the pack's channels" gains `dev`), `descriptor.ts:1180` and `:1746` (`channel: dev` in a descriptor is rejected today unless declared; this is what lets our SDK prereleases publish on `dev`), `packs/ingest.ts:225` and `resolve.ts:654`.
- Replace the hand copy in `release/store.ts:1264` (`channelNames`) with `BUILT_IN_CHANNELS` (tracks.md rule 4: one list). `admin/src/kit/stories/forms.tsx` fixtures are story data and stay.
- New `DEFAULT_OUTLET_TRACKS` in `shared-manifest/src/distribution.ts` and `effectiveTrackMap(kind, declared)` (declared entries win per channel; defaults fill the rest; never written back):

  | Channel | Play (`tracks`)  | TestFlight | Steam (`branches`) | MS Store (`flights`) | Snap (`channels`) |
  | ------- | ---------------- | ---------- | ------------------ | -------------------- | ----------------- |
  | stable  | `production`     | none       | `default`          | non-flighted         | `stable`          |
  | beta    | open/closed beta | `external` | `beta`             | flight `beta`        | `beta`            |
  | dev     | `internal`       | `internal` | `dev`              | none                 | `edge`            |

  Play beta resolves to `beta` (open) unless the product's declaration names `alpha` (closed); TestFlight has no identity field today, so its map is a resolver default only (group names `external`/`internal`, a label the ASC connector already looks up).

- Validator (rule 9): no new path and no new rule. The existing `channelMap` rules (`distribution.ts:324`) already admit a `dev` key. Mutation-table and JSON schema are unchanged except the `BUILT_IN_CHANNELS` enum text, which `pnpm gen` regenerates if `schemas/` embeds it (the implementer confirms; expected none).
- Read model for the mockups (`packages.release-tracks-stale`, lead answer 1): a pure `trackFallbackState(newest, fallbackNewest)` in the Worker release read model returning `behind` only when a track's newest build is older than the track it falls back to; "N builds ahead" is a count of builds newer than the source track's current. No time-based rule. No route; P2-09/P2-11 expose it.

## 6. Worker, console, CLI, Action

- `release/channels.ts`: `ChannelKind` gains `"dev"`; `classifyChannel("dev")` returns `{kind:"dev",raw:"dev"}` after the manual lookup. `resolve.ts:212` `defaultIncludes`: `dev -> ["beta"]`, `beta -> ["stable"]`. `compose.ts`, `access.ts` (`entitledSelectorFor`) and `admin.ts:540` map `dev` to the channel `dev`. The legacy GitHub resolver (`gateway.ts:381` switch) treats `dev` as unresolvable until P2-12's switch, so legacy surfaces answer 404 for `dev` before it and serve it after (P2-12 §7).
- `services/update/index.ts:56-63`: discovery `update.channels` = `knownChannels` minus `pr-<n>`, so `dev`, manual and declared names appear; a product with no release config still returns `[]`.
- Track-map consumers: Play and Steam setup, MS Store provision, `cli/src/transportSteam.ts:126` and `storefronts/snap.ts` call `effectiveTrackMap`.
- Write path: one helper `withIncludedChannels(["dev"]) -> ["beta","dev"]` in the tier and licence write routes (server side, so API clients get it). The console tier and licence pickers offer `dev` with the R3-01 hint, in console copy (ST-37 ledger, `copy.debt.json`).
- `actions/publish/dist` bundles `BUILT_IN_CHANNELS`; rebuild it (its dist drift check).
- Routes: no new route, so no rule 10 entry. Migrations: none (`release_channel_policy`, `release_yanks.channel` and `release_metadata.channel` are free-text channels). If one appears, name it `00XX_<name>.sql`; the lead numbers it. No `TABLE_OWNERS` change.
- Docs: `services/release/channels.md` (hand-written; generated reference pages are touched only if their gate reports drift), plus this package's part of releases/release-tracks, updates/\*, packs/\*, help/beta.

## 7. Rollout

Deploy the Worker; the console ships with it. No flag. Old Workers never see a `dev` feed because nothing asks. Existing installs and tokens are unaffected; grants are matched as stored, so a stored `["dev"]` stays `["dev"]` and gets beta only when re-saved in an editor.
Behaviour change to accept: a product already publishing releases to `dev` without declaring it gains `includes: [beta, stable]`, so its `dev` feed may now offer a newer beta or stable build. Declaring `includes: []` on `dev` restores the old behaviour.

## 8. Decisions for the human (each with a recommendation)

1. Include chain `dev ⊇ beta ⊇ stable` as a default that a declared `dev` overrides. **Recommend yes** (matches the tracks mockup and P2-12 Q1).
2. Apply "dev includes beta" on the server write path, not only in the picker. **Recommend yes**; it keeps API and console identical.
3. Where `DEFAULT_OUTLET_TRACKS` lives: `shared-manifest` constant now; A-19's `tools/channels.json` may later generate it. **Recommend the constant now**; A-19 does not block this package.
4. Stale-track helper ships here as a pure function with no route. **Recommend yes**; the alternative is to leave it to P2-11.
5. TestFlight `external`/`internal` and Play `beta` (open) defaults. **Recommend** these; products override per channel.
