## 0. Owner decisions encoded (binding)

- **S-19 (decisions 1, 4, 5, 18 and 23).**
  - A licence is an **access contract**, and grants are the reasons someone holds an entitlement.
  - The holder is **the account signed in on the device** (`entitlementHolder: device`).

## 1. Summary

- **Today.** `GET /<p>/update/<channel>/velopack/<FileName>` answers a `302` to the package's
  `files/<releaseId>/<name>` URL on the bytes host. Velopack's HTTP client (ureq) drops
  `Authorization` on **every** redirect: P5-07's run saw this even on same-origin redirects
  (`godot-desktop.md`). Under `authenticated`, `licensed` or `entitled` delivery the second hop
  therefore answers 401, so Godot's facade reports `unsupported (product)`.
- **Change.** Under a non-public delivery the route checks access in two steps:
  - first, the feed's access check, as today;
  - then the **per-file** check the bytes route would run: the release's stored version, pinned.

  It then redirects to the same URL with PX-W3's ticket appended:
  `https://dl.plrs.im/<p>/distribution/files/<releaseId>/<name>?ticket=v1.<kid>.<exp>.<mac>`.
  The second hop needs no header.

- **The bytes route is unchanged.** PX-W3 already makes the `file` target accept a valid ticket on
  the bytes host. The ticket is bound to (bytes host, product, releaseId, name, sha256) under the
  label `pkey-download-ticket/1`.
- **No widening.** The route mints a ticket only for a file that the caller's bearer could fetch
  from the bytes route at that moment, and only for a file the feed lists.
- **Drivers.** On a download 401 or 403, retry once. A retry hits the route again, so it gets a
  fresh ticket. Godot changes in SP-09. Node, Python and Kotlin build the rule into their first
  driver.

## 5. SDKs and UI kits, in order

**The rule for every Velopack driver.**

1. Pass the bearer through the source options (`vpkc_new_source_http_url_with_options`).
2. If a download fails with 401 or 403, call `download()` **once more**. Velopack requests each
   package through the route again, which mints a new ticket.
3. If it fails a second time, it is a real refusal. Answer:
   - the licence outcome when the feed check itself was refused;
   - otherwise `unsupported (product)` with "this deployment cannot sign Velopack downloads". That
     covers a key that is unset or was rotated twice inside the window.

   Never wipe tokens on either answer.

## 6. Worker

**`services/update/updaterFeeds.ts`.**

- `RenderContext` gains `mode: ReleaseAccess`.
- `VelopackCandidate` gains `releaseId`, `name`, `version` and `sha256`. These are copied from the
  `FeedSelectionEntry` and its artifact. The change is additive, and P5-07's `gen_feeds.mts` keeps
  compiling.
- In `serveVelopackPackage`'s render, once the listed hit is found:
  - **`mode === "public"`:** return `hit.url`. The answer stays byte-identical and cached, as
    today.
  - **Non-public:** 1. Run `accessRefusal(env, db, product, bearer(req), mode, fixedReleaseSelector(hit.version),
true, now)`. This is the bytes route's `file` decision, verbatim. If it refuses, the route
    answers that refusal (`FeedPlan.render` may return a `Response`). 2. If `hit.url` passes `isAllowedDownloadRedirectHost` and PX-W3's
    `mintDownloadTicket(env, {product, releaseId, name, sha256}, now)` returns a ticket, return
    `hit.url + "?ticket=" + t`. 3. Otherwise return `hit.url`. That is today's behaviour, and today's second-hop 401.
- `serveFeed`'s redirect branch adds `referrer-policy: no-referrer`. The answer stays
  `private, no-store` for non-public delivery, so a ticket is never cached.
- `sha256` must be the digest that the bytes route's `resolveFile` reads. The test in §9 proves it
  by following the `Location`.

**Imports.** Core only: `core/entitledAccess.ts`, `core/downloadTicket.ts` (PX-W3) and
`core/bytesHostname.ts`. Update never imports Distribution (rule 6). `boundaries.test.ts` checks
this.

- **Old Workers during a rolling deploy:** they give today's 302 and today's 401. The retry may
  land on a new Worker.

  still refused there (Q4).

## 8. Open questions (recommendations recorded as proposed decisions)

1. **Q1 Mechanism.**
   - Options: PX-W3's ticket on the bytes host; streaming the package from the route on
     `key.plrs.im`; or a same-origin redirect.
   - A same-origin redirect does not help, because ureq drops the header on every redirect.
     Streaming puts customer bytes on the portal origin (PX-W3 §1) and costs Worker CPU on 45 MB
     packages.
   - **Proposed: the ticket.**
2. **Q2 Label.** Reuse `pkey-download-ticket/1`, or mint a new `pkey-update-ticket/1`. The ticket
   names one release file. PX-W3 reserves the label "for release files only", and these are
   release files on the same `file` target. **Proposed: reuse**, so the bytes route needs no
   change.
3. **Q3 Order.** Make PX-W3 a dependency of SP-09, or let whichever lands first own
   `downloadTicket.ts`. **Proposed: add PX-W3 to SP-09's `deps`.** PX-W3 is approved and small.
4. **Q4 No bytes host.** **Proposed: accept and document.** Licensed Velopack needs a bytes host.
   Production has one (`dl.plrs.im`).
5. **Q5 Revocation residual.** Up to 120 s after the route's check. **Proposed: accept**, as PX-W3
   Q5 did.
6. **Q6 The other updater feeds.**
   - Sparkle and WinSparkle enclosures are direct and carry the header (S-11), so they need
     nothing.
   - An `.appinstaller` `Uri` and a `.zsync` control file are fetched without any bearer. They
     are cached for days, too long for a 120 s ticket.
   - **Proposed: out of scope.** The lead records both in program README §9 as known gaps, to be
     closed by public delivery or a later plan.

**Risks.**

- SP-09 inherits PX-W3's deploy dependency on the key pair, and it fails closed to today's
  behaviour.
- The per-file check runs on every non-public package request. It costs one `accessRefusal`, the
  cost the bytes route already pays.

**Briefs this plan changes** (the lead, after approval):

- **SP-09:** `deps` gains PX-W3; scope gains the Godot retry and the docs.
- **PX-W3:** the glossary entry and THREAT-MODEL section name SP-09 as a second minter.
- **SDK-PARITY-PASS:** the SP-N09, SP-P09 and SP-K12 task text gains §5's rule.
- **LX-09:** the Velopack package route is one more `accessRefusal` caller under the `legacy`
  regression.
- **Program README §9:** the App Installer and zsync gap (Q6).

## 9. Acceptance

`DOWNLOAD_TICKET_KEY` set:

- **Licensed.** A device bearer gets a `302` whose `Location` is on the bytes host with
  `?ticket=`. The `Location` contains no `pkeyt_` token and no `Authorization` value. Following it
  **without** `Authorization` gives 200, and `Range` gives 206.
- **Entitled.**
  - Inside the window: as above.
  - A file of a release outside the window: the route answers `403 version_blocked`, with no

  - A channel that is not entitled: `403 channel_not_allowed`.
- **No credential:** today's refusal at the route.
- **Public:** the `Location` and cache headers are byte-identical to a snapshot taken before the
  change.
- **Fail closed:** with the key unset, or `BLOB_ORIGIN` unset, the `Location` is the bare URL.
- **Headers:** a non-public answer is `private, no-store` with `referrer-policy: no-referrer`.
