## 1. Summary

- HA-12 shipped the member, the rules and the proof. HA-13 is the consumer half: each SDK parses
  `core.presentation`, fetches and verifies one icon size, caches it, and exposes it through one
  accessor that implements `PresentationSource`.
- The UK kits already landed on `integ/ux-docs` with **local stand-in seams** (§3). HA-13 does not
  wait for them to be rewritten: it makes each SDK satisfy the kit's seam and the client-core
  shape, and retires the stand-ins.
- Defaults: the kit shows the verified icon and the product accent only when the integrator passes
  nothing. The integrator's value always wins.

## 2. Contract, catalog, Worker

No change to `WIRE-CONTRACT-V4.md` (§5.5 stands), `shared-protocol`, `shared-jws`,
`shared-catalog`, `shared-manifest` or the Worker. `client-core/presentation` is **consumed, not
edited**; a bug found there goes back to the planner, because it moves the corpus.

Today the Worker already emits the member from `packages/worker/src/core/presentation.ts` (name,
developer, accent from `presentation.accent` or the listing `tintColor`, icon from the
`presentation.icon` slot or `listing.icon`, only when something beyond the name resolves).
Discovery stays `public, max-age=300`.

**Already deployed.** Old SDKs ignore the member. A new SDK against an old Worker sees no member and
shows today's output. Nothing to migrate.

**Shared rules for every row** (all from HA-11 §2.1; none new):

- Limits come from the generated `PRESENTATION_*` constants, never a literal.
- Fetch: plain GET, no `Authorization`, cookies or `X-PKey-*`; no redirect followed (any 3xx fails);
  200 only; 10 s; 10 MiB cap; no error surfaced, no retry.
- Bytes are shown and cached only when their SHA-256 equals the pick's `sha256`. A failure or
  mismatch is a silent fall-back to the letter tile or today's mark.
- Cache by hash as `presentation/<sha256>`; last member as `presentation.json`; prune to 4 files
  after each successful discovery. Nothing enters the Core cache record.
- **Safe link.** The matrix's usable-URL rule already allows `http` only for loopback. The fetcher
  additionally refuses any URL that is not `https` (or loopback `http`) and any `{w}` expansion that
  leaves `original`'s origin, so it agrees with the kits' one validator (`safeLink`, UI-KITS DL14).
  The SDK never opens a presentation URL; it only fetches icon bytes.
- `name` and `developerName` are rendered by the kits in a bidi-isolated run.

**Accent and override.** The SDK only supplies data: `accent` and `accentDark`, lower-case, as
parsed. It never picks a colour. Resolution stays in the kits, which already encode it and are
pinned by the `theme` rows of `ui-matrix.json` (`accentSource`): integrator, then `product`
(`accent`, or `accentDark` in the dark scheme), then `icon` (derived by `@polaris-key/brand`
`deriveAccent`), then `ink`; `core` only when the integrator asks; `host` under the `native` preset.
`resolveAccent` (`packages/brand/src/accent.ts`, ported to Swift, Kotlin, GDScript and Python with
`accent-vectors.json`) then makes the contrast-safe `solid`, `on`, `fg` for the scheme. HA-13 adds no
second resolver. Its snapshot tests assert the `theme` rows that mention presentation:
"react: the integrator's accent wins over presentation", the light and dark Drift Kart rows, and
"no presentation, ink and a monogram".

**CSP.** Hosted Worker pages are unaffected: the app shells already add exactly `IMG_ORIGIN` to
`img-src` (`securityHeaders.ts` `appCsp`; `bytesHost.ts`), and the static and branded sign-in pages
keep `img-src 'self' data:` because they do not render SDK presentation. The requirement lands on
**integrator web apps**: `connect-src` (or `img-src` for a plain `<img>`) for the image origin, and
`img-src blob:`. A blocked image fires `onerror` and the kit falls back to the monogram.
`services/core/discovery.md` already names this (HA-12); the `build/ui/theming` page repeats it.

## 4. Corpus and regeneration

HA-13 **needs no corpus change**: `presentation-matrix.json` (`parseCases`, `pickCases`,
`verifyCases`) and `discovery-presentation.json` already exist with both mirrors, and the
`ui-matrix.json` `theme` rows already cover accent source and icon. Each SDK adds a _runner_, not
a file. The Swift and Godot mirrors are untouched.

- **Drift gates run:** `gen corpus --check`, `gen transcripts --check`,
  `gen constants --check`, `parity:check`, and `--filter @polaris-key/docs gen:check`.
  All must be clean with no regeneration.
- **If a runner finds a gap** (a missing row in the matrix), the porter does not regenerate. The
  row goes to one batch: the lead merges UK-03 first, the porter then appends rows to
  `tools/presentation-matrix.ts` and runs `pnpm gen corpus` **once** for all of them (plus any
  UK-03 or UK-02b row), then reruns the six runners. Rows are append-only, so UK-03 cannot conflict
  at the file level; the generated copies are the lead's auto-resolve set in `merge.sh`.
- `core.presentation` flips to `implemented` in the five manifests of this package
  (`packages/sdk-node`, `packages/sdk-react`, `sdks/python`, `sdks/swift`, `sdks/kotlin`);
  `sdks/godot` stays `planned` until HA-14. `pnpm parity:check` enforces it.

## 5. SDKs, in order

1. **Node** (uses client-core directly): accessor, cache, fetch-rule tests, matrix runner
   (`conformance/runners/node`), transcript replay, terminal kit adapter.
2. **React**: hook, blob handling, browser runner (Chromium, Firefox, WebKit), `brand.tsx` defaults.
3. **Python**: port, sync and `aio`, `ui/ansi.py` accent, `ui/qt/Theme.qml` through `ui/accent.py`.
4. **Swift**: `PolarisKeyCore` port, `ConformanceTests` matrix and transcript, `PolarisKeyModel` mapping.
5. **Kotlin**: `:core` port, `:conformance` matrix and transcript, `:ui` fall-backs.

Each passes the matrix, replays `discovery-presentation.json` (step 1 returns the normalised member,
step 2 returns none), unit-tests the fetch rules, and shows a snapshot with and without presentation.
Typed N/As: none (the headless SDKs expose the accessor). Qt needs the `imageformats` plugin for WebP;
without it the original is used.

## 6. Rollout

Ship SDK by SDK in the order above; no Worker deploy. Kill switches are server-side and need no SDK
release: `assets.hosting.enabled` drops the icon, and removing `presentation` from the manifest drops
the accent at the next resync. A kit whose integrator passes a logo or accent looks as before.
