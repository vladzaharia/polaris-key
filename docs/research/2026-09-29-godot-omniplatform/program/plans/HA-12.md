## 1. Summary

- Discovery's `core` block gains `presentation`: `name`, `developerName`, `accent`, `accentDark`,
  and an `icon` given by content-addressed image-host URLs with the original's hash and each
  WebP size's hash. The member is omitted when nothing beyond the name resolves.
- Discovery offers only bytes an SDK can verify. A slot with no hosted copy (all of production
  today) has **no icon** in discovery, and the kill switch drops the icon too. The `/media` proxy
  never appears in discovery (Q3).
- The contract gains §5.5, a §9 sentence and a §10 divergence class. `@polaris-key/protocol/core`
  gains the types and the `PRESENTATION_*` constants, which are generated into every SDK.
- The corpus gains `presentation-matrix.json`. The transcripts gain
  `discovery-presentation.json`, in which the member is present and then gone.
- The parity registry gains `core.presentation`, `planned` in all six manifests (HA-13 ×5, HA-14).

### 2.2 The member, in its normalised form

This is what the Worker emits, what `parsePresentation` returns, and what the matrix and the
transcript compare as canonical JSON (keys sorted):

```jsonc
"core": { "registration": …, "compat": …, "endpoints": …,
  "presentation": {                                         // absent ⇒ today's behaviour
    "name": "DJDL",                                         // always present
    "developerName": "Vlad Zaharia",                        // present only when valid
    "accent": "#2ed6e6", "accentDark": "#5ee6f0",           // lower-case; each optional
    "icon": {                                               // present only when valid
      "sha256": "<64 hex>", "contentType": "image/png",
      "width": 1024, "height": 1024,                        // present only when known
      "original": "https://img.plrs.im/djdl/a/<sha256>",
      "url": "https://img.plrs.im/djdl/a/<sha256>/{w}.webp", // present iff sizes is non-empty
      "sizes": [{ "w": 64, "sha256": "<64 hex>" }, …]       // always present; [] with no ladder
    } } }
```

The `sizes` member reads as `[]` when it is absent. **Never in the member:** the manifest's
`presentation.icon` ref (an https URL or a repo path), a developer host, a `/media` URL, the
image host's `/icon` alias (a 302, which SDKs refuse to follow), a device or licence fact.

### 2.3 Emission (new `packages/worker/src/core/presentation.ts`)

- **`presentationText(product, listing)`** is pure:
  - `name` is `listing.name`, else `products.name`;
  - `developerName` is `listing.developerName`;
  - `accent` is `presentation.accent`, else `listing.tintColor`, lower-cased;
  - `accentDark` is `presentation.accentDark`.
- **`presentationIcon(env, db, slug)`** returns `null` when `hostedImageOrigin(env)` is `null`.
  Otherwise it takes `firstHostedImage(await hostedImages(…, PRESENTATION_ICON_SLOTS), …)`:
  - `original` is `imgUrl(env, slug, sha256)`;
  - `url` is `` `${original}/{w}.webp` ``;
  - `sizes` is the image's `variants`, capped at 8.
- **`resolvePresentation(ctx)`** reads the listing only through `ctx.hooks.delivery()?.listing()`,
  so rule 6 holds.
  - It runs the candidate through client-core's `parsePresentation`, so the Worker never emits a
    field that an SDK would drop. For example, a listing `developerName` with a C1 character is
    valid in the manifest but fails §5.5 rule 2.
  - It returns `null` unless `developerName`, `accent`, `accentDark` or `icon` survives (HA-11 Q8).
- **How each slot state appears.** This is the per-slot fallback and the kill switch as discovery
  shows them:

| Slot state                                                                                           | `icon` in discovery                                    | The portal, for comparison (HA-07) |
| ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------ | ---------------------------------- |
| A copy of `presentation.icon`                                                                        | that copy                                              | the same copy                      |
| No copy there, but a copy of `listing.icon`                                                          | the `listing.icon` copy                                | the same copy                      |
| No copy in either slot: never resynced since HA-05 (**production today**), or a first pull in flight | **omitted**; `accent` and `developerName` still appear | the `/media` proxy URL             |
| An empty ladder (no Images binding, error 9422)                                                      | the original, with `sizes: []` and no `url`            | the original                       |
| A failed or stale re-pull                                                                            | the last good copy                                     | the same                           |
| Kill switch off, or `IMG_ORIGIN` unset or unusable                                                   | **omitted**; the rest of the member stays              | the `/media` proxy URL             |
| A copy deleted by the operator (HA-06), or a console upload reverted                                 | omitted, or the new hash, at the next discovery        | the same                           |

## 6. Worker, docs and threat model

- **Migration.** `packages/worker/migrations/00XX_products_presentation.sql`:
  `ALTER TABLE products ADD COLUMN presentation_json TEXT;`.
  - It is expand-only. There is no backfill and no new table, so `TABLE_OWNERS` is unchanged.
  - The lead assigns the number at merge; 0104 is the next free number on this base.
- **Code.**
  - `core/products.ts`: `ProductPublic.presentation` is `parseStoredPresentation(row.presentation_json)`,
    read defensively.
  - `core/hostedImages.ts`: `contentType` and `variants` (§0.2 rows 2 and 3).
  - `core/presentation.ts`: new (§2.3).
  - `core/discovery.ts`: sets `core.presentation` when `resolvePresentation(ctx)` is non-null.
  - `portal/library.ts` `presentationOf`: `name`, `developerName` and `tintColor` come from
    `presentationText`. The portal's tint therefore follows a declared manifest accent, which was
    HA-11's intent. Its art and `passthrough/client.ts` do not change.
  - No route is added, so rule 10 is not engaged.
- **Caching and ETag.**
  - Discovery keeps `cache-control: public, max-age=300` and gains **no ETag** (Q4).
  - Icon URLs are immutable: the image host answers `ETag: "<sha256>"` and caches for a year. An
    SDK never revalidates them.
  - A new icon, a new accent or a kill-switch flip reaches devices within 300 s plus the SDK's
    discovery cadence.
  - Cost: one D1 statement per discovery request (`hostedImages`, skipped while
    `hostedImageOrigin` is `null`), plus the listing read when Distribution is on.
- **OpenAPI.** `polaris-key.v3.yaml` `DiscoveryDocument.core.properties.presentation` gets the
  §2.2 schema. Then run `pnpm --filter @polaris-key/docs gen:check`.
- **Docs.** `services/core/discovery.md` gains a "Presentation" section:
  - the member;
  - the slot table from §2.3;
  - "display data, never authority";
  - the CSP that web kits need: `img-src <image host> blob:` and `connect-src <image host>`.
- **THREAT-MODEL.** A new subsection, "Product presentation in discovery (HA-12)", after
  "Serving hosted copies everywhere (HA-07)":
  - **Display data.** The member is unsigned and nothing gated, entitled or trusted reads it.
    Rewriting it needs a TLS-level attacker, who can already turn services off.
  - **Nothing new disclosed.** The listing fields are already public on the download page and in
    the sources, the icon is already public at `img…/<p>/icon`, and no manifest ref is ever
    emitted.
  - **The SDK icon fetch.** It is a public `GET` to content-addressed URLs only, with no
    credentials or `X-PKey-*` headers (so no device id reaches the image host). Redirects are
    refused, the fetch is bounded at 10 s and 10 MiB, and bytes are shown only on a hash match.
    A tampered CDN or image host can blank the icon but cannot swap it.
  - **Decoder surface.** Network raster images now reach the platform decoders. This is bounded
    by the hash pin and the sniffed types. The residual risk is a hostile image from the
    product's own operator, which carries the same trust as the app binary.
  - **Text.** C0 and C1 controls are dropped. Bidi controls are not, so the kits isolate the text
    (Q5).
  - **Kill switch.** Turning it off is not a security gate.
  - **Tests.** The subsection names the tests that cover it.

## 7. Rollout

1. **Order.** The migration is applied first, then the Worker is deployed. Code that runs on the
   old schema only reads, so it ignores the column. A code rollback leaves the column unread.
2. **Clients in the field.** Every released SDK ignores the member, so nothing changes for them.
   A new SDK (HA-13, then HA-14) against an old Worker sees no member and keeps today's output.
3. **Production.**
   - When HA-12 deploys, DJDL's discovery gains the member if its listing has `developerName` or
     `tintColor`, but with **no icon**, because production has no hosted copies.
   - After the deploy, the lead resyncs DJDL (S-20 §6.8, "pull on first resync"). HA-05 then pulls
     its art, and the icon appears in discovery within 300 s.
   - The system product declares no presentation, so its member is omitted until HA-15.
4. **Kill switches.**
   - `assets.hosting.enabled` (through `hostedImageOrigin`) drops the icon.
   - Removing `presentation` from the manifest drops the accent at the next resync.

   Neither needs a deploy or an SDK release.
