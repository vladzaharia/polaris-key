## 0. Decisions

- **D1. One registry file.** `conformance/parity/api.json` (schema `api.schema.json`) holds each
  concept, its canonical name, each SDK's exception or planned rename, and every name 0.9
  removed. `parity.json` gains no field: a concept names its feature id, and the feature's status
  in the SDK's manifest decides whether the symbol must exist.
- **D2. Spelling is generated:** camelCase in TypeScript, Swift and Kotlin, snake_case in Python
  and GDScript (PARITY §2.1); a Swift first argument is unlabelled unless the entry gives
  `labels`. Only a difference from the rule is written down, with a `reason`.
- **D3. Which name wins:** (1) integration.md C-24, C-25 and C-26; (2) the spelling most SDKs
  ship; (3) on a tie, the shortest spelling that does not repeat its namespace noun. Audit
  proposals are not a rule: C-25 kept `getConfigSource` and `onConfigChange` over CQS-06's
  `source` and `onChange`. A case the rule cannot settle goes to the lead before the PR.
- **D4. Options agree on leaf names, not nesting.** The five `polaris-key.json` facts
  (`productSlug`, `baseUrl`, `pinnedKeys`, `pinnedReleaseKeys`, `expectedServices`, C-24) agree up
  to casing; each SDK's path (`trust.`, `core.`, `update.`) is recorded. **Kotlin is not
  flattened** (a change from the scope): Swift nests the same way (`PolarisKeyClient.swift:33`,
  `CoreContext.swift:31-59`), and after `fromConfig()` the options bag is the advanced path.
- **D5. Entitlements get their own namespace** (`entitlements.has`, `.value`, `.all`; `quantity`,
  `grants`, `consume`, `acknowledge` reserved for LX-19 and LX-42), as the scope says (Q1).
- **D6. Removal, not deprecation** (owner, 2026-10-07: README §2.10 and §11, tracks.md rule 6,
  C-54, the brief). A renamed name leaves in the same change: no alias, no `@deprecated`
  forwarder, no warning, no window, no later removal package. A `removed` row in `api.json` feeds
  the migration table, the release notes and the lint. Swift's `changes`, deprecated since
  2026-10-05 (`Events.swift:181-182`), goes in SP-35b like the rest.
- **D7. A removed option fails loudly and names its replacement**, the SDK counterpart of the
  owner's "a removed manifest field is a validator error naming its replacement". Where a language
  would silently ignore an unknown name, the SDK refuses with `invalid-options` (`product` was
  renamed `product_slug` in 0.9): Godot's `PKeyOptions._set()` catches `product` and
  `pinned_trust_keys` from an old `.tres` and `configure` refuses; React's Provider and both
  adapters refuse `expectServices` from JavaScript callers. Python's keyword-only `trust=` already
  raises `TypeError`, and Swift and Kotlin fail to compile. At run time no value is ever read from
  an old name, so this is not an alias (Q3). The one reader is Godot's editor dock, which pre-fills
  the new fields from an old `.tres` so that Save rewrites the file. That is a one-time migration
  in the editor, the SDK's counterpart of a codemod.
- **D8. Reserved names are binding.** A reserved row fixes the name and the package that ships
  it; the lint refuses any other spelling.
- **D9. The setting handle.** On `config.setting(key)`, `value`, `source`, `locked` and
  `visibility` are read-only properties (Swift: `get async`); `set(value)`, `clear()` and
  `on(listener)` are methods. `value` is null when no layer has one (source `fallback`); a
  fallback goes through `config.get(key, fallback)`. Python and Godot read `value` that way today
  (`config/client.py:265-267`, `setting.gd:22`). `visibility` (`editable`, `readonly`, `hidden`)
  is new, derived from the document's `state` (`config/client.ts:211`). `sync` is reserved.
- **D10. Facade shortcuts.** A facade method that forwards to a renamed verb is removed, not
  renamed; the namespaced call is the one name. Shortcuts whose target keeps its name (`status`,
  `isLicensed`, `enroll`, …) stay, as rows.

## 1. Summary

- `api.json` records each public SDK concept once; a generator (P0-42 family `api`) writes one
  surface test per SDK; `pnpm parity:check` gains a lint: no public verb outside the registry, no
  removed name in the SDKs or their consumers, no second spelling of a reserved name.
- 0.9 renames only where SDKs disagree (Appendix A), with no aliases (D6): Node, React and Python
  in SP-35, Swift, Kotlin and Godot in SP-35b. Each SDK breaks once, in the v0.9.x release that
  carries its package, whose notes list every removal.
- `reference/api-names.mdx` is generated from the registry, with a "Removed in 0.9" table. Kits,
  samples, examples, docs, READMEs and console snippets move in the same change.
- The one way in (`polaris-key.json`, `fromConfig()`, `boot()`) and the one snippet generator take
  their names from the registry (§4).

## 3. The contract: `api.json`

```jsonc
{
  "$schema": "./api.schema.json",
  "apiVersion": 1,
  "casing": { "node": "camel", "react": "camel", "python": "snake", "swift": "camel", "kotlin": "camel", "godot": "snake" },
  "surfaces": {                       // what the lint reads; every public verb here is a row
    "node": [{ "ns": "config", "type": "ConfigClient", "file": "packages/sdk-node/src/config/client.ts" }, …],
    "godot": [{ "ns": "config", "file": "sdks/godot/addons/polaris_key/services/config.gd" }, …]
  },
  "concepts": [
    { "id": "config.get", "kind": "method", "feature": "config.resolve",
      "args": [{ "name": "key", "type": "string" }, { "name": "fallback", "type": "json" }],
      "sdks": {
        "react": { "spelling": "useManagedConfig().get", "shape": "hook" },
        "swift": { "spelling": "config", "labels": ["_", "default"], "planned": "SP-35b" },
        "godot": { "spelling": "get_value", "reason": "Object.get is a native method" } } },
    { "id": "options.pinnedKeys", "kind": "option", "configFile": true,
      "sdks": { "node": { "path": "trust.pinnedKeys" }, "swift": { "path": "core.pinnedKeys" },
                "godot": { "spelling": "pinned_trust_keys", "planned": "SP-35b" } } },
    { "id": "entitlements.quantity", "kind": "method", "reserved": "LX-19" }
  ],
  "removed": [
    { "sdk": "node", "from": "config.getConfig", "to": "config.get", "package": "SP-35" },
    { "sdk": "node", "from": "PolarisKeyClient.getConfig", "to": "config.get", "package": "SP-35" },
    { "sdk": "python", "from": "trust", "to": "options.pinnedKeys", "package": "SP-35",
      "scan": { "pattern": "\\btrust\\s*=\\s*(dict\\(|\\{|PINNED)|\"trust\"\\s*:" } }
  ]
}
```

- **`kind`**: `namespace`, `method`, `property`, `option`, `stream`, `hook` or `value`. **`args`**
  types: `string`, `json`, `bool`, `int`, `strings`, `listener` (the Swift and Kotlin emitters turn
  them into placeholder call sites).
- **A per-SDK entry** may carry `spelling`, `reason`, `labels`, `path`, `shape`, `sdkOnly` and
  `planned`. `planned` names an open package (as `parity-check.ts` rule 4) and the entry carries
  the SDK's **current** spelling, which the surface test asserts and lint rule 1 accepts. The
  package flips it to the canonical spelling and adds the `removed` row in the same change. That
  is Swift, Kotlin and Godot between SP-35 and SP-35b; no date field exists, so nothing starts a
  clock.
- **A `removed` row** carries `sdk`, `from`, `package`, and `to` (a concept id) or `note` (a
  replacement with no one-to-one name, such as SP-40's cookie mode). An optional `scan` gives a
  `pattern` that replaces the default match and `files` that narrow the default scope (§5).
- **`enums.json`** gains `settingVisibility` `["editable","readonly","hidden"]` and `eventKind`
  `["license","entitlement","config","updateAvailable","packs","store","cloudSync"]`.
- **Out of the registry**, each in `ignore` with its reason: client-core and the bridge v4 verbs
  (SP-31); the `/server`, `/electron`, `/cli` and `/terminal` subpaths; the kits' `ui.*` surface
  (UK-41); the React `PolarisAdapter` root; CLI commands and Action inputs.

## 4. How the one way in and the one generator use it

- **`polaris-key.json` (SP-32a):** the JSON Schema's properties, except `$schema` and
  `configVersion` (C-24), equal the `option` rows with `configFile: true` (a SP-32a test), and
  `fromConfig()` maps each key to the row's `path`. `fromConfig()` and `boot()` are rows, so every
  surface test asserts the start pair once SP-32a/b flip it from `reserved`.
- **The snippet generator (SP-33a, then SP-33b)** emits canonical spellings only, and its goldens
  are in the removed-name scan. Whichever of SP-33a and SP-35 merges second moves the other's
  templates; SP-33b's goldens compile in all six SDK lanes. No generated name module is needed.

## 5. Generators, the lint and the drift gates

`tools/gen-api-surface.ts` (P0-42 family `api`) reads `api.json`, `features.json`, `enums.json`
and every `parity.json`, and writes six GENERATED files. SP-35 writes all six; Swift, Kotlin and
Godot assert their `planned` spellings until SP-35b. Each asserts every required symbol; Node,
React, Python and Godot also assert each `removed` name is absent, so an alias cannot come back
(Swift and Kotlin rely on the lint).

**`tools/api-check.ts`** runs as `pnpm parity:check`'s rule 8 and fails when:

1. a public verb on a recorded surface is not a row, an SDK entry or an `ignore` entry (TypeScript
   compiler API for Node and React; per-language patterns elsewhere: `def` at class depth,
   `public (suspend )?fun|val`, `public (nonisolated )?func|let|var`, top-level `func`, `signal`);
2. a `removed` name appears in an SDK's own source (`packages/sdk-{node,react}/src`,
   `sdks/python/src`, `sdks/swift/Sources`, Kotlin `src/main`, `sdks/godot/addons`) or a consumer
   (the kits, `examples/`, `sdks/*/examples`, `sdks/kotlin/samples`, `packages/cli/src`,
   `packages/admin/src/console`, the `pkey sdk` samples, docs-site fences, SDK READMEs). The
   default match is receiver-qualified: `<ns>.<from>(` for a method, `<ns>.<from>` at a word
   boundary for a property or stream (so Swift's `client.changes`), and `<from>:`, `<from>=` or
   `<from> =` for an option. A `from` that is a common word (`trust`, `product`, `secret`,
   `config`, `activate`, `changes`) must carry its own `scan`, because Python's `trust=` also
   names Core's internal keyword, Godot's `product =` matches unrelated variables, and Swift's
   `ConfigSetting.changes` stays. `api-allow: <reason>` opts a line out. Dynamic reads no pattern
   sees are moved by hand (§7);
3. a reserved concept is spelled any other way;
4. a `planned` package is unknown or done, a `feature` or `enum` is unknown, a common-word row
   has no `scan`, or the schema fails.

`api-check --notes <package>` prints that package's `removed` rows as Markdown for the release
notes.

**The docs page.** `gen-reference.mjs` gains `"api-names.mdx": apiNames` in `EMITTERS`
(`:906-915`); `reference/index.md` gains a row. The page has one table per namespace (concept,
each SDK's spelling, feature id), a "Removed in 0.9" table (SDK, old name, new name or note) and
this policy: "During 0.9 a release may rename or remove an SDK name without an alias. Every
removal is listed here and in that release's notes, and a removed option fails with
`invalid-options` naming its replacement. Pin exact 0.9.x versions. From 1.0 every SDK follows
semver against `api.json`."

**Drift gates and rules.**

- **Rule 3.** After P0-42 the AGENTS.md rule-3 table is generated from `tools/generators.ts`, so
  the `api` row comes from `pnpm gen`, not a hand edit. The green gate's `parity:check` line
  (AGENTS.md:118) adds "and every public SDK verb is in `api.json`". Gates: `pnpm gen --check`,
  `gen:constants -- --check`, `parity:check`, docs `gen:check` and `check:links`. The `pkey sdk`
  samples are rewritten with `PKEY_UPDATE_SAMPLES=1`, and `bundle:action -- --check` runs because
  `sdkConfig.ts` changes. Rules 9 and 10 are not engaged.
- **Process text.** `contribute/waves.md`'s "A new feature starts with its registry entry" adds
  "and its `api.json` rows"; `.claude/agents/pkey-sdk-porter.md:31` reads "names come from
  `api.json`; the failing generated surface test is the checklist". Adding a row is normal mode;

## 8. Security and privacy

- **THREAT-MODEL** gains "SDK API names (SP-35)" before "Boundaries that are weaker than they
  look": a removed trust-pin name (Python `trust`, Godot `pinned_trust_keys`) is never read, so an
  old config fails with `invalid-options` or `TypeError` and cannot set, widen or empty the trust
  root unnoticed; Godot's `_set` keeps a legacy value only to refuse it and to pre-fill the dock,
  never the trust set; the refusal names options, never values; `api.json` and its lint are
  hygiene, not a security boundary.
- **PRIVACY:** no change. Nothing is collected or queried.

- No-behaviour proof: corpus and transcripts byte-identical and every replayer passes;
  `pnpm ui:report` shows no baseline change; the regenerated `pkey sdk` samples compile.

## 10. Rollout and rollback

1. **Release.** SP-35 ships in whichever v0.9.x batch it lands in. That is not v0.9.0, the first
   consolidation batch (README §12): SP-35 waits on P0-42, HA-13, HA-14 and P0-39. The lead
   pastes `api-check --notes SP-35` into that tag's notes; SP-35b ships the same way in a later
   v0.9.x. `tools/sdk-version.mjs` still derives the lockstep version from the tag.
2. **Deployed apps and Workers.** Nothing changes at run time: no wire change, no Worker code, and
   a build keeps the SDK it was compiled with, so rule 6's native-binary window does not apply. A
   developer meets the break on upgrading: a compile error in TypeScript, Swift and Kotlin;
   `AttributeError` or `TypeError` in Python; a GDScript error at the call; D7's
   `invalid-options` for an old option. The repository's consumers move in the same change; the
   app repositories of djdl, Diceroll and the system product are owner steps (rule 6).
3. **Rollback.** Revert before the tag that carries the change; after it, fix forward, because a
   revert would break adopters a second time.
