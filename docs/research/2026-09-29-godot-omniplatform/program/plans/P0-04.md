## 1. Summary

- One vocabulary everywhere: `stable`, `beta`, `pr-<n>` (grant `pr` covers every PR), a product's
  manual channels, and `dev`, the licence gate's pseudo-channel for `0.0.0-dev*` builds. `staging`
  (→ `beta`) and `latest` (→ `stable`) are accepted aliases that no current SDK emits. Every name
  matches `^[a-z0-9][a-z0-9-]{0,63}$`.
- The Worker's build gate and the `entitled` release check use one normaliser and one entitlement
  predicate in `core/channels.ts`. Release accepts `staging` as a `beta` selector unless the product
  declares a manual channel named `staging` (manual wins).
- `channelForVersion` maps `0.0.0-beta*` and `0.0.0-staging*` to `beta` in the Worker,
  `client-core`, Python and Swift, so SDK beta builds send `X-PKey-Channel: beta`.
- `gate-matrix.json` gains 18 rows (21 → 38) and retires the one carried row that pins the
  dev-build bypass R3-01 removed. The Node, Python and Swift runner ports are rewritten to mirror
  the server, and a new Worker test makes the real `checkBuildGate` the oracle for every row.
- No signed document, cache record or encoding changes. Old clients get the same decisions, except
  the widenings in §2.4 and one narrow tightening (`0.0.0-beta*` builds).

## 2. Contract

### 2.1 `docs/security/WIRE-CONTRACT-V3.md`

A new normative **§5.1 Channel vocabulary** follows the client-metadata header bullet. It is marked
**[C]** because gate-matrix v2 pins it.

| Name      | What it is                                                                 | Valid in                             |
| --------- | -------------------------------------------------------------------------- | ------------------------------------ |
| `stable`  | the shipping channel; every grant holds it                                 | header, selector, grant              |
| `beta`    | the pre-release channel                                                    | header, selector, grant              |
| `pr-<n>`  | one pull request; `<n>` is 1–7 digits, kept as written                     | header, selector, grant              |
| `pr`      | the family grant: covers every `pr-<n>`                                    | grant, header                        |
| `dev`     | licence-gate pseudo-channel of `0.0.0-dev*` builds (R3-01), not in Release | header, grant                        |
| manual    | a name from the product's `release.manualChannels`                         | header, selector, grant              |
| `staging` | legacy alias of `beta`                                                     | header, grant, selector (see rule 6) |
| `latest`  | alias of `stable`                                                          | header, selector                     |

1. **Alphabet.** Every name matches `^[a-z0-9][a-z0-9-]{0,63}$`. This is the intersection of the
   manifest's `CHANNEL_RE` and the feed routes' `^[a-z0-9-]+$`.
2. **Build-implied channel** (server `buildChannel(version)`):

   | Version          | Channel                                             |
   | ---------------- | --------------------------------------------------- |
   | `0.0.0-dev*`     | `dev`                                               |
   | `0.0.0-beta*`    | `beta`                                              |
   | `0.0.0-staging*` | `beta`                                              |
   | `0.0.0-pr-?<d>*` | `pr-<d>`, or `pr` when `<d>` has more than 7 digits |
   | anything else    | `stable`                                            |

3. **Header** (`normalizeChannelHeader(header, version)`):

   | `X-PKey-Channel`               | Becomes                                             |
   | ------------------------------ | --------------------------------------------------- |
   | `stable`, `latest`             | `stable`                                            |
   | `beta`, `staging`              | `beta`                                              |
   | `dev`                          | `dev`                                               |
   | the literal `pr`               | the build's `pr-<n>` if it has one, else `pr`       |
   | `pr-<d>`, `pr<d>`              | `pr-<d>`, or `pr` when `<d>` has more than 7 digits |
   | any other name in the alphabet | itself                                              |
   | anything else                  | refused with `channel-not-entitled`                 |

   An unknown well-formed name is never a free pass: it must be granted by name (R3-01, R3-13).

4. **Predicate** (`channelEntitled(granted, channel)`):
   - `stable` is always granted;
   - otherwise the grant list must contain the name exactly;
   - two exceptions: a `staging` grant also covers `beta`, and a `pr` grant also covers `pr-<n>`.

   Nothing else widens a grant:
   - `dev` and manual names are granted only by their exact name;
   - a `beta` grant never covers a manual channel named `staging`.

   Grants are matched as stored and never rewritten.

5. **Gate order is unchanged.** The server checks, in order:
   1. the dev bypass (`allowDevBuilds ?? granted includes "dev"`);
   2. the version window;
   3. a malformed header, which is refused;
   4. every channel in {build-implied, header} other than `stable`, each of which must pass rule 4.
6. **Release selectors keep their grammar.** The grammar is `latest`, `stable`, `beta`,
   `pr-<1–7 digits>`, a manual name, or a pinned `X.Y.Z`. `staging` is added as `beta` and checked
   **after** the manual names, so a declared manual `staging` channel wins.

§9 gains one sentence: the counters are unchanged, and gate-matrix v2 retired one carried row (D6).
§10 gains the class "channel vocabulary and aliases (§5.1)", covered by gate-matrix.

### 2.2 `packages/shared-protocol`

These are added to `src/core.ts` and re-exported from `src/index.ts` like `HEADER_CHANNEL`:

- `CHANNEL_STABLE = "stable"`, `CHANNEL_BETA = "beta"`, `CHANNEL_PR = "pr"`, `CHANNEL_DEV = "dev"`;
- `CHANNEL_ALIASES = { staging: "beta", latest: "stable" } as const`;
- `CHANNEL_NAME_PATTERN = "^[a-z0-9][a-z0-9-]{0,63}$"`;

### 2.3 `packages/client-core`

`semver.ts` `channelForVersion(version): BuildChannel` returns:

- `dev` for `0.0.0-dev*`;
- `beta` for `0.0.0-beta*` or `0.0.0-staging*`;
- `pr` for `/^0\.0\.0-pr-?\d+/`. Keep that exact literal: `R3-licensing.test.ts:280` greps for it;
- `stable` for anything else.

`gate.ts` does not change. Clients never compute the build gate; they record the Worker's 403.

### 2.4 `PROTOCOL_VERSION`, stated against `AGENTS.md` rule 2

Rule 2 bumps `PROTOCOL_VERSION` for a wire change. This change reaches the wire only through two
things:

- the values the unsigned `X-PKey-Channel` header may carry;
- the value SDKs send by default for `0.0.0-staging*` builds.

No signed document, `typ`, claim, envelope, cache record (`CACHE_VERSION` 3) or encoding changes.
So **`PROTOCOL_VERSION` stays 3**. The other counters stay too: `corpusVersion` 2,
`gateMatrixVersion` 2, `fingerprintVersion` 1, and djdl's catalog `schemaVersion` 1.

A scratch differential compared today's `checkBuildGate` with these rules over 8 versions, 16
headers, 9 grant sets and 2 windows. Old clients keep every decision except these:

- **Wider:**
  - `beta`, `latest`, manual names and per-PR grants (`pr-42`) now work;
  - a legacy `staging` grant covers `beta`, and so, under `entitled`, the beta feed;
  - a `beta` grant covers `staging` headers and `0.0.0-staging*` builds.
- **Tighter, in one case:** a `0.0.0-beta*` build now implies `beta`; before, it was `stable`.
  - Only products with no `compatMin` floor reach that check, because `0.0.0-*` sorts below
    `0.0.0`. djdl's floor is `0.0.0`.
  - No known client emits a `0.0.0-beta*` version.

## 7. Rollout

**Order:**

1. One implementation PR, in wave order (contract → catalog → corpus → SDKs).
2. **Deploy the Worker, to `staging` and then production, before any SDK is published.**
   - An old Worker refuses `beta`. A new SDK's `0.0.0-beta*` or `0.0.0-staging*` build would get
     `channel_not_allowed` there.
   - As a stopgap, a host can pass `channel: "staging"`.
3. Publish to npm and PyPI, and tag the SwiftPM release.
4. djdl's owner adds `beta` to the `channels` enum in the `.pkey/schema` of `vladzaharia/djdl`.
   This does not block anything: the licence and tier pickers can already grant `beta`.

**Effects:**

- **Old clients** keep working (§2.4). Documents, ETags and cache v3 records are untouched.
- **Grants** need no migration. `staging` grants stay valid, and the console labels them.
- **`public` products:** `/<p>/update/staging/…` stops returning 404. Only 200s are edge-cached, so
  there are no stale entries.
- **`entitled` products:** licences that hold `staging` gain the beta feed. This is intended: djdl
  labels that grant "Pre-release builds".
- **No feature flag.** The change only widens, and rollback is a Worker redeploy.

**Follow-ups:**

- make `noncanonical_channel_name` an error;
- drop `staging` from `{{channels}}`;
- remove the alias itself, which is a wire removal (plan-mode, wire v4 at the earliest).
