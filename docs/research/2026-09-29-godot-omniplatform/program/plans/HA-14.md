## 1. Summary

- `core.discovery_manifest["core"]["presentation"]` is already kept verbatim by `PKeyDiscovery.parse`.
  HA-14 adds the consumer: parse (the HA-12 rules), pick one icon size, fetch, verify with
  `HashingContext` SHA-256, cache under `user://`, expose it, and feed the kit.
- The kit shows the product's verified icon and accent only when the integrator passes nothing. The
  integrator's `ui_product_name`, `ui_product_icon` and `ui_accent` always win.
- No wire, corpus, Worker or other-SDK change. `core.presentation` flips to `implemented` in
  `sdks/godot/parity.json` only.

## 2. Contract, catalog, Worker

No change to WIRE-CONTRACT-V4.md (§5.5 stands), shared-protocol, shared-jws, client-core,
shared-catalog, shared-manifest or the Worker. A bug found in client-core's presentation module goes
back to the planner (it moves the corpus). **Already deployed:** old addons ignore the member; a new
addon against an old Worker sees no member and renders today's output (project name and icon, ink or
icon-derived accent). Nothing migrates.

## 3. What is there today

- `core/discovery.gd`/`core.gd discover()` keep the document verbatim in `discovery_manifest`; nothing reads
  `core.presentation`.
- `ui/theme/pkey_ui_theme.gd`: `accent_hex()` resolves `accent` (ui_accent), then
  `presentation_accent` (a stub the brief names as HA-14's seam, never set), then the icon-derived
  accent (`PKeyAccent.derive`), then ink. `product_identity()` returns the integrator's name/icon, else
  `application/config/name` (hidden when it is `DEV_PROJECT_NAME` and `hide_dev_project_name`) and
  `application/config/icon`. There is no dark accent field.
- `ui/product/pkey_product_header.gd` renders `product_identity()` (icon, else monogram tile) and
  sizes from theme constants; `ui/settings/settings_controller.gd product_name()` reads raw
  `developerName`/`name` from the manifest; `brand_node()` is only the "Powered by" mark.
- `core/transport.gd` follows redirects by hand (4.7.2 `HTTPRequest` forwards `Authorization` across
  hosts, so it runs `max_redirects = 0`), owns the wall-clock deadline and body cap, and is https only
  (loopback http allowed).

## 4. Design

**New files** (each `.gd.uid` committed, the untracked-`.uid` check in `run_tests.sh` applies):

- `core/presentation_rules.gd` (`PKeyPresentationRules`, pure, static): `parse(core, doc)`,
  `pick_icon_size(icon, px, scale, decodable)`, `icon_matches(bytes, sha256)`, the usable-URL and
  safe-link checks. Ports client-core `presentation.ts` rule for rule (HA-12 §5.5: text rule drops
  C0, DEL, C1 and lone surrogates only, bidi kept; URL rule 5 with port, host and `{w}` placement;
  strictly ascending `w`; `url` on `original`'s origin). Every limit is read from
  `PKeyConstants.PRESENTATION_*`, never a literal. A Godot `String` carries no U+0000 and no lone
  surrogate; that is pinned in the unit test.
- `core/presentation.gd` (`PKeyPresentationSource`, `RefCounted`): `current()` returns the parsed
  member or `{}`; `icon(px, scale = 1.0)` is a coroutine returning an `ImageTexture` or `null`;
  signal `changed`. `PolarisKey.presentation()` and `PolarisKey.presentation_icon(px, scale)` forward
  to it; `core.presentation` is the Dictionary. Decodable set: `image/png`, `image/jpeg`,
  `image/webp`. An AVIF or GIF original with no sizes yields `null` (monogram).

**Hook.** After a successful `discover()` the source reparses the manifest, then: stores
`presentation.json`, prunes, and emits `changed` only when the member differs. A manifest with no
member (or an invalid one) clears the current member (matching the transcript's second step) and
`changed` fires. A failed `discover()` keeps the last member. Cold boot loads `presentation.json`
through the same parser (so a corrupt or tampered file is dropped) so an offline start still shows the
product.

**Fetch** (rules from HA-13 §3, shared): a second `PKeyTransport` for icons, `timeout =
PRESENTATION_ICON_FETCH_TIMEOUT_SECONDS`, `body_limit = PRESENTATION_ICON_MAX_BYTES`, `local_only`
inherited, and **one additive transport option `follow_redirects = false`** (a 3xx comes back as a
status, the fetcher treats any non-200 as a miss). No headers are passed, so no `Authorization` and no
`X-PKey-*`; the redirect-leak risk therefore cannot arise and any hop away from the origin is refused
besides. Before the request the source applies the safe-link rule: https (or loopback http) and the
expanded `{w}` URL still on `original`'s origin. No error is surfaced and nothing retries. On web
`HTTPRequest` is the browser's fetch, which follows redirects itself and cannot be told not to; the
SHA-256 check is the guard there and the unit test records that as a typed N/A for the 3xx row.

**Verify and decode.** Bytes are shown and cached only when `HashingContext.HASH_SHA256` equals the
pick's `sha256` (the SDK's own hasher; Godot has no SHA-512 and none is needed). Then the content
type is checked against the magic bytes, the header dimensions (PNG IHDR, WebP VP8/VP8L/VP8X, JPEG
SOF) are read **before** decode and refused above `PRESENTATION_ICON_MAX_DIMENSION` or above a local
decode budget of 16 megapixels (a 10 MiB file can inflate to gigabytes), and only then
`Image.load_{png,jpg,webp}_from_buffer`. Mipmaps are generated; the `ImageTexture` is memoised per
sha in memory. A decode failure is a silent monogram fallback and nothing is cached.

**Cache.** `user://polaris_key/presentation/<sha256>` and `presentation.json` beside it (approved
HA-11 row 6; the store's `user://pkey/<product>/` is untouched and nothing enters the Core cache
record). Files are written to a temporary name and renamed. After each successful discovery files the
member no longer names are removed, keeping at most `PRESENTATION_CACHE_MAX_FILES` (4) hash files. A
cached file is re-hashed on read; a mismatch deletes it. On web `user://` is IndexedDB and may not
persist; the memory memo still serves the session.

**Kit.**

- Name: `product_identity()["name"]` = `ui_product_name`, else `presentation.name`, else the project
  name (the UK-50 dev-project hide applies only to this last fallback, so a presentation name always
  shows). Icon: `ui_product_icon`, else the fetched texture, else the project icon, else the
  monogram. `PKeyProductHeader` asks `icon(side_px, content_scale)` for the size it is already
  computing from the theme (scales with the title; hero, card and splash differ), keeps the previous
  texture until the next resolves, and re-renders on `changed` through `PKeyUiTheme.refresh_views()`.
  The name label is drawn bidi-isolated (`U+2068` + name + `U+2069`) in the header and the settings
  "Set by" line; `product_name()` still returns the plain name.
- Accent: `PKeyUiTheme.presentation_accent` and a new `presentation_accent_dark` are set from the
  source. `accent_hex()` keeps the approved order (integrator `ui_accent`, then product: `accentDark`
  when `scheme == "dark"` and present, else `accent`, then the icon-derived accent over the fetched
  icon, then ink). `PKeyAccent.resolve` still makes the contrast-safe solid, on and fg; no second
  resolver. The icon-derived step gets the fetched icon because `product_identity()["icon"]` is it.
- `settings_controller.gd product_name()` reads `current()["developerName"]`, else `["name"]`, else the
  identity, instead of the raw manifest.
- The "Powered by" badge and `brand_node()` are unchanged: the product leads, never a Polaris Key mark.

## 5. Corpus and regeneration

**No corpus change.** Both runners read existing rows: `presentation-matrix.json` (131 parse, 32 pick
including the four `...-on-godot` rows, 6 verify) from the generator-owned mirror
`sdks/godot/tests/corpus/v2/`, and `conformance/transcripts/discovery-presentation.json` via its
mirror. If a runner finds a gap the porter does not regenerate: the row goes to the HA-13 §4 batch
(after UK-03, one `pnpm gen corpus`, append-only).

**Drift gates run, all clean with no regeneration:** `gen corpus --check`, `gen transcripts --check`,
`gen constants --check` (the Godot `constants_generated.gd`), `parity:check` (the flip to
implemented), and `--filter @polaris-key/docs gen:check` (the SDK-parity and corpus reference pages).

## 6. Tests (sdks/godot/tests/)

- `suite_presentation.gd` (`# @pkey-feature core.presentation`, added to the `ci` list in `runner.gd`):
  the matrix runner over the mirror (parseCases deep-equal, pickCases with each row's own
  `decodable`, verifyCases), the Godot-decodable rows as an extra assertion with `decodable` =
  png/jpeg/webp; fetch rules against `PKeyFakeServer` (no `Authorization`, no `X-PKey-*`, 3xx fails and
  no second request is made, non-200 fails, over-cap fails, wrong hash not cached, right hash cached,
  prune to 4, tampered cache file deleted, cold boot from `presentation.json`, lone-surrogate and
  NUL pinning, header-dimension bomb refused, AVIF original falls back); the transport option test.
- `suite_transcripts.gd`: the `discover` action asserts `expect.presentation` (the normalised member,
  then `null`), so `discovery-presentation` runs the moment the manifest flips.
- `suite_ui.gd` + `tests/ui/scenarios.gd`: header snapshots for a product with presentation (icon
  node visible, name, bidi isolates), without it (project icon or monogram, dev-project name still
  hidden), and with `ui_product_name` set (integrator wins). Accent rows follow the theme rows of
  `ui-matrix.json`: "Drift Kart's own accent, dark by default", the light-scheme row, the integrator
  wins, "no presentation, ink and a monogram", plus a dark accent row. Snapshots rewritten with
  `... -- --pkey-test ui update` and reviewed.
- **Engines.** Run `GODOT_BIN=<4.7.2> sdks/godot/tools/run_tests.sh` and again with the 4.4.1 floor
  editor (the `Godot SDK (4.4.1 editor, floor)` CI job). 4.4 hands a 303 or 307 back as a plain
  success, 4.7 reports REDIRECT_LIMIT_REACHED; both must read as a miss. `Image.load_webp_from_buffer`
  is exercised on both.

## 7. Rollout

Ships in the next addon release; no Worker deploy. Kill switches are server-side
(`assets.hosting.enabled` drops the icon; removing `presentation` from the manifest drops the accent
at the next resync). A game that sets `ui_accent`, `ui_product_name` or `ui_product_icon` looks as
before. Docs, in this PR: the Godot part of build/ui/theming and `sdks/godot/README.md` /
`CHANGELOG.md` (the `user://` cache path, the decodable set, the web caveat).

## 8. Decisions for the human

| #   | Question                                                                                                                | Recommendation                                                                                                                      |
| --- | ----------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Reach the redirect rule by a second transport plus `follow_redirects = false`, or a separate `HTTPRequest` helper?      | **Second transport plus the option**: it reuses the deadline, cap and https checks.                                                 |
| D2  | Decode budget: refuse above 16 megapixels (a local constant, not wire) or only the wire's 16384 px per side?            | **16 MP budget.** 16384² RGBA is 1 GiB.                                                                                             |
| D3  | `presentation.json` is one file for the install (approved HA-11 path), though a game may talk to more than one product. | **Keep the approved path**; one product per game is the case. Revisit as `presentation/<product>.json` if a second product appears. |
| D4  | Dark accent: add `presentation_accent_dark` so `accentDark` applies in the dark scheme (matches HA-13's order).         | **Yes.**                                                                                                                            |
| D5  | Web builds cannot refuse a redirect (browser fetch). Accept, relying on the hash, or skip the icon on web?              | **Accept**, with the typed N/A in the test; no credentials are sent and the hash gates the bytes.                                   |
