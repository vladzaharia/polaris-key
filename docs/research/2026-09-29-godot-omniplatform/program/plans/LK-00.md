## 0. Ground facts (checked 2026-10-19)

1. **The domain is registered and delegated, but serves nothing.** WHOIS: created 08:16 UTC today
   at Namecheap (registry Orange Domains, `addPeriod`). `.locker` is in the root zone, and its
   servers delegate `polaris.locker` to `ed.ns.cloudflare.com` and `lily.ns.cloudflare.com`. 1.1.1.1
   answers the zone's SOA with no A or AAAA record, so nothing serves yet. A resolver that cached
   the earlier NXDOMAIN keeps answering it until the entry expires. `plrs.im` uses another
   nameserver pair (`daphne`, `zeus`). Cloudflare usually gives one account one pair, so the zone
   may sit in a different account from the Worker (O2).
2. **One host does everything.** `key.plrs.im` serves the console (`/manage`), the portal (`/`,
   hash routes), the card, `/docs` and the API (`/<p>/…`). The customer origin is `portalOriginOf`
   (`W/core/licensing/manageUrl.ts:109-139`: `CONSOLE_ORIGIN`, else the request's). Other sites
   build it directly from the request's origin (`passthrough/authorize.ts:261`,
   `passthrough/choice.ts:186,217`, `licenseChoice.ts:351`, `productOidc/deviceFlow.ts:123`) or
   from a raw `CONSOLE_ORIGIN` (`identity/maintenance.ts:34`, `notify/send.ts:51,122`).
3. **`/signin`, `/device` and `/tv` have no route** (as written; A1 and A2 add them on the API host ahead of LK-03). `matchRoute` (`W/router.ts:150-215`) has no
   entry for them (`git log -S` finds none ever), and none is a reserved slug. Each falls to the
   bare-slug download alias and gets a 404. Yet `authorize` 303s to `/signin`, and `signInUrl`, the
   licence-key email and §12.8 all link to it. Five SDKs fall back to `key.plrs.im/device|tv` (§6).
   LK-03 routes all three, whatever happens to Locker.
4. **Passkeys are bound to the console host.** `passkeyRelyingParty`
   (`W/services/identity/passkeys/webauthn.ts:84-97`) takes the RP ID from `CONSOLE_ORIGIN` and
   runs a ceremony only on that origin. `account_passkeys.rp_id` is stored per credential
   (`migrations/0068_a_accounts.sql:151`).
5. **Locker coral cannot be a section accent.** These figures were measured with `B/src/color.ts`.
   It is too close to the danger status, and its dark value is too close to the reserved rose
   (§5.1 asks ΔEOK ≥ 0.12). Light coral is under 4.5:1 on `surface.sunken`.

   `surface.page`, `surface.raised`, `text.default` and `text.muted` in both themes. Only `accent`

## 1. Summary

- **A second customer domain on the same Worker.** `CUSTOMER_ORIGIN` (`https://polaris.locker`) is
  confined to the customer routes, the way the bytes, registry and image hosts are confined.
- **One switch for links, brand and redirects.** `customer.host` (`off` → `on` → `permanent`) moves
  all three together. It can turn on only after the host passes a health check. It is off by
  default, and stays off in every environment until the owner turns it on.
- **One source for every customer URL.** `customerOrigin()` builds the refusal links, discovery's
  `accountPortal`, the device-code page and the card redirects. Nothing signed changes, and every
  SDK already accepts any https host.
- **Passkeys keep their RP ID.** It stays `key.plrs.im`, and passkeys work on Locker through
  Related Origin Requests.
- **The kit gets its own brand namespace.** `@polaris-key/brand` imports it under `--pk-locker-*`,
  `kind: "locker"` and `data-brand="locker"`. No Key or service token changes.

## 7. Worker: the host move

1. **The customer host.**
   - `W/core/hosts.ts` gains the kind `customer` (`CUSTOMER_ORIGIN`), last in precedence. Its
     hostname is `null` when the origin is unset, unusable or the console host.
   - `W/dispatch.ts` sends the host to a new `dispatchCustomerHost` (`W/core/customerHost.ts`)
     before `matchRoute`.
   - It serves only the customer routes: `/`, `/index.html`, `/activate`, `/signin`, `/device`,
     `/tv`, `/assets/*` (one admin build; the console bundle is public code, useless without a
     console session), `/login[/…]`, `/callback`, `/logout`, `/magic/verify`, `/api/*`, `/media/*`,
     `/download/<token>`, `/.well-known/polaris-host.json`, `/robots.txt` (Disallow while `off`),
     `/<slug>` (LK-12) and `/docs/help/*` (D7).
   - Anything else gets the plain 404: product routes, `/manage`, other `/docs`.
2. **`customerOrigin(env, mode, req)`** in `W/core/hosts.ts`.
   - It answers `CUSTOMER_ORIGIN` when `mode` is not `off` and the host is usable, and today's
     `portalOriginOf` otherwise. Every site in §0.2 calls it; `portalOriginOf` and
     `portalOriginFor` become wrappers.
   - `test/customerOrigin.test.ts` fails on any customer path literal (`/#/p/`, `/activate`,
     `/signin`, `/device`, `/tv`, `/magic/verify`) built on another origin.
3. **The switch.**
   - A platform setting `customer.host` in `W/core/settings/platform.ts`, on the `LAZY_DELTAS`
     precedent: `[vars]` `CUSTOMER_HOST` is `runtime` (the console decides) or `off` (a hard off
     that no console value overrides). Unset means `off`, so turning it on takes a deploy (LK-11)
     and a console action.
   - Values `off`, `on` and `permanent`; `confirm` L2 (step-up) both ways; audited.
   - It is effectively `off` while `CUSTOMER_ORIGIN` is unusable. `CUSTOMER_ORIGIN` is deploy-time
     only (the `DENIED_PLATFORM_NAMES` origin category).
   - The console refuses `on` until `https://<customer>/.well-known/polaris-host.json` answers
     `{host: "customer", environment, version}` matching `/manage/api/me`. That document gets
     CORS for the console origin only, without credentials.
4. **Cookies.**
   - Both hosts use the same names, and `__Host-` makes each host-only. The customer realm leaves
     the console's site entirely, so THREAT-MODEL R1-09's shared-origin caveat stops covering
     customers. `withoutAccountCookies` stays on the API host.
   - No session crosses hosts (D10). With the switch on, the old host's redirects expire
     `__Host-pkey_portal` and the five flow cookies (`Max-Age=0`).
5. **CSP and CORS.**
   - The portal policy (`appSecurityHeaders`: `'self'` plus `IMG_ORIGIN`) works unchanged on the
     new host. `img.plrs.im` is CORP `cross-origin`.
   - The shell's theme script is unchanged, so `ADMIN_SCRIPT_HASHES` and `adminCspParity` do not
     move. The Locker variant of the branded-page stylesheet adds one hash
     (`brandPageStyleSource`).
   - The JSON API stays same-origin (`browserRequestGuard`).
6. **Sign-in providers.**
   - Provider flows build their redirect URIs from the request's origin
     (`providers/flow.ts:254,267`). On the new host they become
     `https://polaris.locker/login/{google,apple,steam}/callback` with no code change, and Steam's
     `openid.realm` follows. Portal SSO and I-30 connections use `<customer>/callback`.
   - Google, Apple and Steam keep the same subject for each person, so account links are
     unaffected.
   - Apple's notifications URL stays on `key.plrs.im`. The new URIs are owner registrations
     (O5–O9), and the old ones stay registered for rollback.
7. **Passkeys (D2).** Keep RP ID `key.plrs.im` and add Related Origin Requests:
   - `key.plrs.im` answers `GET /.well-known/webauthn` with `{"origins":["https://polaris.locker"]}`.
     Staging and dev list their own hosts. The response is built from `CUSTOMER_ORIGIN`, never
     from stored data.
   - `passkeyRelyingParty` accepts the console origin or the customer origin and always answers
     `rp.id` = the console host. Both verifications pin the exact origin list. New registrations
     name `rp.name` "Polaris Locker".
   - The card feature-detects `PublicKeyCredential.getClientCapabilities()` → `relatedOrigins`.

## 14. Amendment A3: the v1.3 brand architecture

Sources: kit v1.3 `README.md` ("Public brand architecture"), `docs/brand-alignment.md`, `tokens/locker.tokens.json` `architecture` (`attribution: "Powered by Polaris Locker"`), `badges/index.json` (16 labels, `minimumDisplayWidthCssPx` 320). ### 14.1 The rule

- **Locker names the place and the brand; Key names the machinery.** A string that tells the reader where they are, what they open, or whose site, mail or badge it is says Polaris Locker. A sentence about what the API, CLI or server does may say Polaris Key (kit: "Key can be named accurately in an explanation of the underlying platform"; "public top-level identity never switches to Key simply because the surface is technical").

### 14.3 Not adopted

- **Renaming `@polaris-key/*`, PyPI `polaris-key`, SwiftPM `PolarisKey`, `pkey`, `PKEY_*`, `X-PKey-*`, the token prefixes or `.pkey/`:** it breaks every install, import, CI secret and stored token, and the kit itself keeps technical identifiers.
- **Serving the console or developer docs on `polaris.locker`:** §7.1 keeps the customer host to customer routes so console cookies and CSP never share the customer realm (THREAT-MODEL R1-09).
- **Changing `ISSUER`, the discovery hosts or the RP ID:** they are signed or stored (A1, D2).
- **The "Login with" label:** the glossary verb is "sign in", so we offer "Sign in with", which the kit names as the alternative.
- **The Locker mark or coral as a kit's look:** kits stay host-owned (kit: "host-owned brands are preserved"). The mark appears only in the opt-in attribution.
- **Owner-registered display names** (GitHub App, App Store Connect, Pocket ID, Apple Services ID): these are owner steps (O14), not code.

### 14.4 D1 and timing

**Decided (lead, 2026-10-19): customer surfaces keep D1; developer surfaces ship independently.**

- Customer surfaces: brand and host still move together on `customer.host`. Kit copy and the attribution ship in the first SDK release after prod is `on`.

- Why: these surfaces never change host, so waiting buys no single event. Gating them would need a second brand path in the console and a docs redeploy at cutover.
- Words about the customer site's address keep following `customerOrigin()` (LK-10), and the docs keep saying "once the switch is on" (LK-02 practice).
- Accepted gap: until prod is `on`, a developer's Locker console links to a customer site on `key.plrs.im` that still says Polaris Key.
- `key.plrs.im`'s root favicon and manifest become Locker with LK-14. The portal keeps its own `<link>` icons until the switch.
- Alternative (not taken): gate the console and docs on the switch too.
