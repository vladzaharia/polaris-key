## 0. Owner decisions encoded (binding)

- **S-20 D10.** Presentation is an **unsigned** `core.presentation` member. Through it, every UI
  kit defaults to the product's icon and accent with **no integrator code**.
- **S-20 D2, D4.** Images come from `img.plrs.im` (`IMG_ORIGIN`) at content-addressed, immutable
  URLs. The WebP width ladder is built once at ingest. Without the Images binding, only the
  original exists.
- **S-20 D5, D11.** The icon and accent are declared in `.pkey/product` `presentation`. A console
  upload claims the icon slot, and Revert returns it to the manifest. `hosted_assets` already
  models this, so discovery reads only the slot's current copy.
- **UI-KITS Q1, Q2, §1.2.**
  - Identity is resolved in this order: the integrator's theme, then presentation, then the
    bundle, then a monogram tile. Ink is the fallback, never Polaris violet.
  - The accent is resolved in this order: the integrator's colour, then `accent` (`accentDark` in
    the dark scheme), then the colour derived from the icon, then ink.
  - Kits read presentation only through the SDK's accessor. They never fetch discovery or cache
    the icon themselves.

## 1. Summary

- Discovery gains `core.presentation`: `name`, `developerName`, `accent`, `accentDark`, and an
  `icon` with the original's `sha256`, a `{w}` URL template and a per-width `sizes` list that
  carries each variant's own `sha256`. The member is **omitted** when the product has nothing to
  show beyond its name, so every existing transcript stays byte-identical.
- Every SDK parses the member **field by field**. A malformed field is dropped, and discovery is
  never refused because of it. The SDK then fetches one icon size, unauthenticated, verifies it
  against its `sha256`, and caches it by that hash. Any failure falls back silently to today's
  output.
- `presentation-matrix.json` pins the parse rule, the size choice and the verification check. All
  six languages must agree on those. The new transcript pins what the Worker emits and how each
  SDK exposes it.
- `core.presentation` replaces ST-06's placeholder storage with a manifest-only **column**,
  `products.presentation_json`.

## 2. Contract

### 2.1 The member (HA-12 writes it as `WIRE-CONTRACT-V4.md` §5.3, marked [C])

```jsonc
"core": {
  "registration": "open", "compat": { … }, "endpoints": { … },
  "presentation": {                                   // optional; absent ⇒ today's behaviour
    "name": "DJDL",                                   // always present in the member
    "developerName": "Vlad Zaharia",                  // optional
    "accent": "#2ed6e6",                              // optional, lower-case #rrggbb
    "accentDark": "#5ee6f0",                          // optional
    "icon": {                                         // optional
      "sha256": "1e7d…64aa4",                         // the original's, lower-case hex
      "contentType": "image/png",                     // sniffed at ingest
      "width": 512, "height": 512,                    // optional (Images .info())
      "original": "https://img.plrs.im/djdl/a/1e7d…64aa4",
      "url": "https://img.plrs.im/djdl/a/1e7d…64aa4/{w}.webp",   // present iff sizes is non-empty
      "sizes": [{ "w": 64, "sha256": "…" }, { "w": 128, "sha256": "…" }, … ]   // WebP, ascending
    }
  }
}
```

**What the Worker emits (normative for HA-12):**

- `name` is the listing's `name` when Distribution has one, else `products.name`. That is the
  same rule as the portal's `presentationFor`.
- `developerName` is the listing's `developerName` (Q2).
- `accent` is `presentation.accent`, else the listing's `tintColor` (Q3). `accentDark` is
  `presentation.accentDark`. Both are lower-cased.
- `icon` comes from the `hosted_assets` row for `presentation.icon`, else `listing.icon` (Q4),
  both with locale `''`. The row must have status `ready` or `stale` and a non-null `sha256`, and
  `IMG_ORIGIN` must be set.
  - `sizes` lists the WebP entries of `variants_json`, at most 8.
  - The icon is omitted when `assets.hosting.enabled` is off.
- The member is emitted only when at least one of `developerName`, `accent`, `accentDark` or
  `icon` resolves (Q8).

**What every SDK accepts (the `parseCases` of `presentation-matrix.json`).** Unknown members are
ignored at every level.

1. **Not an object.** The member is treated as absent.
2. **Text fields.** `name` and `developerName` must be strings of 1 to
   `PRESENTATION_TEXT_MAX_BYTES` (1024) UTF-8 bytes with no C0 or C1 control character. An invalid
   `developerName` is dropped. An invalid `name` falls back to the document's top-level `name`,
   then to the slug.
3. **Colours.** `accent` and `accentDark` must match `^#[0-9A-Fa-f]{6}$`. They are lower-cased;
   anything else is dropped. Either one may appear without the other.
4. **Icon.** `icon` is dropped unless all of these hold:
   - `sha256` matches `^[0-9a-f]{64}$`;
   - `contentType` is one of `PRESENTATION_ICON_TYPES` (`image/png`, `image/jpeg`, `image/webp`,
     `image/gif`, `image/avif`);
   - `original` is a usable URL (rule 5).

   Within a kept icon:
   - `width` and `height` are integers from 1 to 16384, or they are dropped.
   - `sizes` must have at most `PRESENTATION_MAX_ICON_SIZES` (8) entries, each `{w, sha256}`. Each
     `w` is an integer from 1 to 4096, and the `w` values strictly ascend. If any entry is bad,
     both `sizes` and `url` are dropped and the original stays.
   - `url` must be a usable URL with exactly one `{w}`, on the same origin as `original`.
     Otherwise, or when `sizes` is empty, both are dropped.

5. **Usable URL.** An absolute URL of at most 2048 bytes, with no userinfo and no fragment. The
   scheme is `https`, or `http` only on `localhost`, `127.0.0.1` or `[::1]`. There is no pinned
   host, because staging and dev use `media-staging` and `media-dev`.

**Size choice (`pickCases`).** The input is `(icon, px, scale, decodable)`, and
`need = ceil(px × scale)`.

1. If `sizes` is non-empty and `image/webp` is decodable, take the smallest `w ≥ need`, else the
   largest `w`. Expanding `url` gives the URL.
2. Use the original instead when it is decodable, its `width` is known and exceeds the largest
   `w`, and `need` exceeds the largest `w`.
3. With no usable size, take the original if it is decodable.
4. Otherwise, take none.

The result is `{source: "size", w, sha256, url}`, `{source: "original", sha256, url}` or
`{source: "none"}`.

**Verification (`verifyCases`).** Bytes are shown only if their lower-case hex SHA-256 equals the
chosen `sha256`. Bytes that do not match are neither shown nor cached.

**Fetch rules** (unit-tested in each SDK; not corpus, because they are I/O):

- A plain `GET`. It sends no `Authorization`, no cookies or credentials, and no `X-PKey-*`
  headers: the media host is public, and a header would only leak a device id.
- Redirects are not followed, so any `3xx` is a failure. Only `200` succeeds.
- Timeout 10 s. Body cap `PRESENTATION_ICON_MAX_BYTES` (10 MiB, the icon slot's cap).
- **Fetch failures.** No error is surfaced and nothing retries. The next discovery refresh may try
  again.
- **Persistence.** The bytes are stored under the SDK's data directory as
  `presentation/<sha256>`. The last parsed member is stored beside them as `presentation.json`,
  so a cold boot with no network still shows the product. After each successful discovery, files
  the current member no longer names are removed, keeping at most 4.
- **No Core cache record.** None of this goes into the Core cache record: §4.1 keeps that record
  to signed artifacts only, so `CACHE_VERSION` stays 3.

### 2.2 Signing and versions

- **Unsigned, on purpose.** Discovery is unsigned JSON over TLS. The member carries no authority:
  no gate, entitlement or trust decision reads it. The icon's integrity comes from the `sha256`
  in the same TLS response, and the media host serves only content-addressed bytes.
  - Signing would need a new `typ` and a key that every SDK pins, and it would buy nothing over
    discovery's existing trust.
  - A party that can rewrite discovery can already turn services off. Changing a logo adds
    nothing to that.
- **`PROTOCOL_VERSION` stays 4.** The change is additive and optional, with no verification
  semantics. This follows the §9 precedent of SP-00's `update.endpoints` templates and P4-29's
  `deltas`.
- **`DISCOVERY_VERSION` stays 2.** Every SDK parser keeps or ignores unknown members:
  - Node's `DiscoveryCore` has an index signature;
  - Swift's `parseCore`, Kotlin's `obj["core"]`, Python's dictionary and Godot's
    `discovery_manifest` read only the members they know.
- **Contract text.** HA-12 adds three things to `WIRE-CONTRACT-V4.md`:
  - **§5.3**: the text in §2.1.
  - **§9**: one sentence saying that HA-12 changes no counter and adds
    `presentationMatrixVersion = 1`.
  - **§10**: one new divergence class, "display members parsed field by field, never refusing
    discovery, and icon bytes verified before display", covered by `presentation-matrix.json`.

## 3. Catalog, manifests and settings

- **`shared-catalog`, `shared-manifest`: no change.** HA-04 already ships `ManifestPresentation`
  with its validator rules, mutation entries and schemas. Rule 9 is not engaged.
- **Settings storage, replacing ST-06's placeholder** (Q5). In
  `packages/worker/src/core/settings/core.ts`, the `core.presentation` entry changes:
  - `storage: { kind: "scalar" }` becomes
    `{ kind: "column", table: "products", column: "presentation_json" }`;
  - `readers: ["core/presentation.ts", "core/discovery.ts"]`;
  - `pending` is removed;
  - `ownership: "manifest"` stays. The accent is manifest-only, and the icon's console claim lives
    in `hosted_assets` (S-20 D11), not in this setting.
- **Why a column.** S-18 makes column-backed storage permanent for hot-path product fields
  (ST-01b design notes), and discovery is the hottest read there is.

    Using it would put HA-12 behind both.
  - Deriving the value from `product_manifest_snapshot` would parse up to 256 KiB of JSON on
    every request, and that table is the revert source, not a read path.
- **Drift gate:** `pnpm gen settings --check`. It regenerates `reference/settings.mdx` and
  `settings.generated.ts`, and the `settings-coverage` test then sees one fewer pending entry.

## 4. Corpus and transcripts

- **`presentation-matrix.json`** (new, hand-authored rows, append-only like `headers.json`).
  - Shape: `{presentationMatrixVersion: 1, description, parseCases, pickCases, verifyCases}`.
  - `parseCases` are `{name, core, doc, expect}`, where `expect` is the normalised member or
    `null`. They cover every rule in §2.1, a member from the future with extra keys, and a
    `{w}`-less template.
  - `pickCases` cover hero sizes from 32 to 120 px at scales 1, 2 and 3; no sizes; a Godot-style
    `decodable` set without AVIF or GIF; and the original winning above the ladder.
  - `verifyCases` are about four small byte strings (base64) with matching, upper-case and wrong
    hashes.
  - The rows live in `tools/presentation-matrix.ts`, imported by `tools/sign-corpus.ts` and added
    to its `files` map. That puts the file in the source, in

    stray-file guard then expects it.
  - **Self-check.** `buildPresentationMatrix` runs every row through

## 7. Rollout

1. **HA-12 deploys after HA-02, HA-03 and HA-07.**
   - Old SDKs ignore the member.
   - With the media host unbound or hosting switched off, the member carries no icon, and SDKs
     show today's output.
2. **HA-13, then HA-14, release their SDKs.**
   - A new SDK against an old Worker sees no member and keeps today's behaviour.
   - A kit whose integrator already passes a logo or accent looks exactly as before.
3. **Kill switches.**
   - `assets.hosting.enabled` (HA-10) drops the icon.
   - Removing `presentation` from the manifest drops the accent at the next resync.

   No SDK release is needed for either.

**Already deployed.** Workers and clients in the field need no change. No signed document, cache
record or verification path moves.

## 8. Decisions (all recommendations accepted, 2026-10-06)

| #   | Question                                  | Recommendation                                                                                      | Alternative                                                                                                                 |
| --- | ----------------------------------------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Q1  | How is a resized icon verified?           | **`sizes[{w, sha256}]`**: each WebP variant carries its own hash from `variants_json`               | Only the original's hash, so every SDK downloads the original (up to 10 MiB) to show a 32 px icon                           |
| Q2  | Where does `developerName` come from?     | **The Distribution listing's `developerName`**, through the delivery hook, with no manifest change  | A new `.pkey/product` `presentation.developer` (rule 9 work in an HA-04 follow-up). It can be added later as a first source |
| Q3  | Accent fallback                           | **`presentation.accent`, else the listing's `tintColor`**, as the portal does today                 | Manifest `presentation` only                                                                                                |
| Q4  | Icon fallback                             | **The `presentation.icon` slot, else `listing.icon`**, so DJDL shows its icon with no change        | `presentation.icon` only                                                                                                    |
| Q5  | Settings storage                          | **The `products.presentation_json` column, manifest-only**                                          | A `product_settings` row (waits for ST-01b and ST-04), or deriving it from the snapshot (a hot-path parse)                  |
| Q6  | Cross-SDK proof                           | **`presentation-matrix.json`** plus the transcript                                                  | The transcript and per-SDK unit tests only, which leave the parse and size rules unpinned across six languages              |
| Q7  | Where the `PresentationSource` type lives | **`client-core/presentation`, ported to each SDK**. UK-03, UK-07, UK-09, UK-11 and UK-12 consume it | Each UK kit defines its own seam                                                                                            |
| Q8  | When the member is emitted                | **Only when something beyond the name resolves**, so existing transcripts do not change             | Always (re-records every discovery transcript)                                                                              |

**Risks.**

- **Browser CSP.** Web kits need `blob:` and the media origin in the integrator's CSP. A blocked
  image fires `onerror`, which falls back to the monogram, and the requirement is documented in
  §6.
- **Images quota.** If the account's Images allowance is exhausted (error 9422), `sizes` is empty.
  SDKs then download the original. Godot cannot decode an AVIF or GIF original, so it shows the
  monogram.
