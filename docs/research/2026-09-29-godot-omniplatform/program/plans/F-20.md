## 1. Summary

- **A new credential, `pkeyr_`.** It is 256 random bits, stored only as an HMAC under
  `KEY_HASH_PEPPER`, shown once, and always bound to one owner (product). Every token expires,
  after at most 365 days. Its scope is `read` (`publish` is reserved for F-22 and F-23), and it
  can be narrowed to some ecosystems. A token is either **owner-bound** (minted in the console) or
  **licence-bound** (minted by a licensee in the portal, or by an operator for them). AGENTS.md
  rule 8 gains the prefix.
- **The access ladder decides, and a token only identifies.** `authorizeFeedRead` keeps its order.
  The credential is looked up only when the mode is not `public`, so the public hot path does no
  D1 read and is unchanged. Licence-bound principals reuse the byte routes' decisions:
  `licenseUsable` for `authenticated` and `licensed`, and the deliverable's gate flag for
  `entitled`. A token for another owner, or outside its ecosystems, counts as no credential.
- **Each client authenticates natively.**
  - Bearer: npm, pnpm, Yarn and Bun, SwiftPM after `POST /login`, and Gradle header credentials.
  - Basic: pip, uv, Poetry, Gradle password credentials and Maven.
  - OCI: `docker login` feeds a token service at `/v2/token`, which issues 5-minute HMAC pull
    tokens, including anonymous tokens for public repositories.
  - Godot: the editor sends no credentials, so it gets a per-user URL holding a narrow URL-only
    token.
- **Revocation takes effect within 30 s, and no credentialed answer is ever shared-cached.** The
  same 30-second per-isolate window bounds token revocation, licence suspension, feed tightening
  and product deletion. A credentialed answer is always `private, no-store` and never enters the
  Cache API.
- **No device-wire change.** No signed document, discovery field, `PROTOCOL_VERSION`, corpus file,
  error code or SDK changes (§2).

## 6. Worker

### 6.1 The token (Core: `core/registryTokens.ts`, `core/registryVocabulary.ts`)

- **Shape.** `pkeyr_` followed by `b64url(randomBytes(32))`: 43 characters, matched by
  `/^pkeyr_[A-Za-z0-9_-]{43,}$/`. The length is a floor, as for `isDeviceToken`. The prefix
  collides with no existing prefix (`pkey_`, `pkeyt_`, `pkeyci_`).
- **Storage.** Only `hashKey(token, KEY_HASH_PEPPER)` is stored, as for `ci_tokens`, through a
  global unique index on the hash. The last four characters are kept as `hint` for the list UI.
  The plaintext is returned once by the mint call and never logged, echoed or stored.
- **Ownership.** The store lives in Core because two services mint tokens: Distribution, from the
  console, and Identity, from the portal. Both reach Core, and neither may import the other
  (rule 6).

```sql
-- 00NN_registry_tokens.sql (number at rebase), owner: core
CREATE TABLE IF NOT EXISTS registry_tokens (
  product        TEXT NOT NULL REFERENCES products(slug),
  token_id       TEXT NOT NULL,                       -- rtok_<12>
  token_hash     TEXT NOT NULL,
  hint           TEXT NOT NULL,
  label          TEXT NOT NULL,                       -- ≤ 64 chars
  scopes_json    TEXT NOT NULL,                       -- ["read"]; "publish" refused until F-22
  ecosystems_json TEXT,                               -- NULL = every feed of the owner
  binding        TEXT NOT NULL CHECK (binding IN ('owner','license')),
  license_id     TEXT,
  presentation   TEXT NOT NULL DEFAULT 'header' CHECK (presentation IN ('header','url')),
  created_by     TEXT NOT NULL,                       -- admin:<email> | portal:<accountId>
  portal_account_id TEXT,
  created_at     INTEGER NOT NULL,
  expires_at     INTEGER NOT NULL,
  last_used_at   INTEGER,
  revoked_at     INTEGER, revoked_by TEXT, revoke_reason TEXT,
  PRIMARY KEY (product, token_id),
  CHECK ((binding = 'license') = (license_id IS NOT NULL)),
  CHECK (presentation = 'header' OR (ecosystems_json = '["godot"]' AND scopes_json = '["read"]'))
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_registry_tokens_hash ON registry_tokens(token_hash);
CREATE INDEX IF NOT EXISTS idx_registry_tokens_license ON registry_tokens(product, license_id);
```

- **Rules enforced at mint.**
  - Expiry is required: at least 1 day and at most 365, with a default of 90 (Q6). For URL tokens
    the default is 30.
  - Licence-bound tokens are `read` only.
  - URL tokens are `read`, licence- or owner-bound, and narrowed to `["godot"]`.
  - At most 10 live tokens per licence and 500 per owner.
- **Revocation paths**, each audited (§6.6):
  - manual revocation, in the console or the portal;
  - "revoke all" for an owner;
  - a licence deleted (License service calls Core);
  - a portal link removed by `syncAccountLicenseLinks`, or a portal account deleted. Identity
    revokes the tokens that account minted for that licence.
  - A deleted product needs no write: the lookup joins `products.status <> 'deleted'`.
  - A **suspended or expired** licence also needs no write. Its tokens stop at the next check,
    because `licenseUsable` fails, and they work again if the licence is reinstated.
- **Retention.** The cron purges rows 90 days after `expires_at` or `revoked_at`.

`AGENTS.md` rule 8 changes **[naming]** from "license keys `pkey_`, device tokens `pkeyt_`" to
"license keys `pkey_`, device tokens `pkeyt_`, CI tokens `pkeyci_`, registry tokens `pkeyr_`".
`pkeyci_` was missing from the list; this fixes that omission in the same edit. `start/concepts.md`
gains "registry token" (rule 4).

### 6.2 Principals and the ladder (`services/distribution/registry/authorize.ts`)

**[change]** F-02's comment promised no signature change. Resolution needs D1, though, so
`feedPrincipal(req)` (sync, always anonymous) is replaced. The extractor `extractFeedCredential`
stays as it is, and the ladder resolves the principal **only at step 5**:

```ts
authorizeFeedRead(ctx, credential: FeedCredential | null, owner, ecosystem, deliverableId)
type FeedPrincipal =
  | { kind: "anonymous" }
  | { kind: "owner";   product; tokenId; ecosystems: string[] | null }   // pkeyr_, binding owner
  | { kind: "ci";      product; tokenId }                                 // pkeyci_ of this product (any scope)
  | { kind: "license"; product; tokenId; license: LicenseRow; ecosystems: string[] | null }
```

Steps 1 to 4 are unchanged: the kill switch, enablement, `stricter(feed, dist_access)`, and
`public` admits anyone with `cache: "public"`. **A credential on a public read is never looked
up.** Step 5:

| Principal (after resolution)                                                                                                         | `authenticated`, `licensed` (one strictness, as `access.ts`) | `entitled`                                                                                                                                                                                                                                                                                          | Answer if refused                                              |
| ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| none, malformed, unknown, expired or revoked; another owner's; an ecosystem outside its list; a URL token in a header or the reverse | refuse                                                       | refuse                                                                                                                                                                                                                                                                                              | the native challenge (§6.3), 401                               |
| `owner`, `ci`                                                                                                                        | admit                                                        | admit (Q4)                                                                                                                                                                                                                                                                                          | n/a                                                            |
| `license`                                                                                                                            | `licenseUsable(license, now)`                                | the deliverable's `dist_access.entitlement` flag, held by the licence through the new `licenseHoldsFlags()` in `core/entitledAccess.ts` (the licence-only twin of `entitlementFlagRefusal`). No gate fails closed, as packs do. A list document (`deliverableId: null`) needs only a usable licence | 403, natively: `forbidden`, OCI `DENIED`, Swift `problem+json` |

- Every admit at step 5 is `cache: "private"`. `serve.ts` already forces `private, no-store`,
  drops the ETag and skips `cachedRegistryAnswer`. F-21 adds a test that `cache.put` is never
  called for a credentialed request.
- **A token never widens past the mode.** It is judged only where the mode is not `public`, and
  only for its own owner and ecosystems.
- **The resolution cache.** It is per isolate, with `REGISTRY_TOKEN_TTL_SECONDS = 30` (the
  settings constant), keyed by the token hash. An entry holds the principal and the licence row,
  and unknown hashes are cached as negative entries. A revoke or mint calls `forgetRegistryToken`
  on its own isolate.
- `last_used_at` is written through `waitUntil` only when an entry is reloaded and the stored
  value is more than an hour old.
- **Device trust** (P6-02) does not apply, because a token has no device. This is the portal
  download's rule, and the threat model records it.

where a client needs one, is `__token__` everywhere. The extractor takes the password as the token.

- **Per-host credentials.** docker, SwiftPM and netrc hold **one credential per host**, so one
  machine can hold a token for only one owner on `pkg.plrs.im` (Q2). npm, uv, Gradle and Maven
  scope credentials per path or repository and have no such limit.
- **Godot tokenised URLs** are the one exception to "credentials travel only in `Authorization`".
  The routes accept an optional `/t/<token>/` segment after the owner; F-09 builds the segment, or
  F-21 adds it. `serve.ts` takes the segment as a `{scheme: "path"}` credential, which only
  `presentation = 'url'` tokens satisfy. For a tokenised request, it rewrites absolute URLs in the
  JSON body that start with `${PKG_ORIGIN}/godot/<owner>/` (`download_url`, icons) to carry the
  same segment. The rewrite happens at serve time, so renderers and stored objects do not change.
  Any log line the Worker writes redacts the segment.

### 6.4 New registry routes (rule 10) and host changes (`core/registryHost.ts`)

| Route                                  | Behaviour                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /v2/token?service=&scope=…` (oci) | **[change]** The dispatcher admits one route flagged `ownerless`. The handler loads each `repository:<owner>/<repo>:pull` scope's owner itself (at most 4 scopes). `push` and `registry:catalog:*` are refused. The route grants pull for a scope when the ladder admits the principal: with no credential, only for public repositories (an anonymous token); with Basic `__token__:<pkeyr_ or pkeyci_>`, per §6.2. The answer is `{token, access_token, expires_in: 300, issued_at}`. A refusal is 401 Basic, the same for an unknown, disabled or private owner, so it is no oracle. A valid token asking for another owner's scope gets 403 `DENIED`. `POST` stays 405, and containerd falls back to `GET` on that because the username is set |
| The pull token                         | `v1.<b64url(claims)>.<b64url(HMAC-SHA256)>` under the new secret `REGISTRY_TOKEN_KEY`. `REGISTRY_TOKEN_KEY_PREVIOUS` is accepted for verification during a rotation. Claims: `{sub: tokenId \| "ci:<id>" \| "anonymous", own, repos[], iat, exp}`. It carries **identity only**: every OCI request re-runs the ladder with the re-resolved principal, through the 30 s cache. A revoked token or a tightened mode therefore stops it within 30 s, although `exp` is 300 s                                                                                                                                                                                                                                                                          |
| `GET /v2/`                             | Today it answers 200. Once `REGISTRY_TOKEN_KEY` is set, it answers the standard 401 Bearer challenge to a request with no `Authorization`, and 200 to a valid pull token. Anonymous tokens keep public pulls working, and `docker login` then really checks the credentials (Q1)                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `POST /swift/<owner>/login`            | **[change]** `RegistryRoute` gains `methods?: readonly "POST"[]`. The method check still runs **before** an owner loads, and admits a method only for a route of that ecosystem that declares it and whose `match` passes. Only `swift.login` declares one. The route replaces F-06's placeholder 501                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `…/godot/<owner>/t/<token>/…`          | Mirrors F-09's paths (§6.3)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

- Each route gets an OpenAPI entry under `servers: [{url: https://pkg.plrs.im}]`, tag `registry`,
  and a row in `REGISTRY_PATHS` in `routeCoverage.test.ts`.
- A missing `REGISTRY_TOKEN_KEY` makes `/v2/token` answer 503 OCI `UNAVAILABLE`, and `/v2/` stays
  at 200.
- The cookie stripping, CSP, type allowlist and no-CORS rules are untouched. `/v2/token` answers
  `application/json`, which is already on `REGISTRY_HOST_TYPES`.

### 6.5 Console, portal and admin API (F-21, building on F-11 and F-12)

  - `entitled` lists the package deliverables that have no gate, because licence tokens will be

### 6.6 Rate limits, audit, threat model, docs

- **Rate-limit buckets** (`core/rateLimit.ts` `FAIL_MODE`). On the registry host the limiter
  object is keyed by the owner slug.

| Bucket                   | Key      | Fail mode | What it counts                                                         |
| ------------------------ | -------- | --------- | ---------------------------------------------------------------------- |
| `registryOciToken`       | IP       | closed    | each `/v2/token` call (it mints)                                       |
| `registryLogin`          | IP       | closed    | each Swift `/login`                                                    |
| `registryCredentialMiss` | IP       | closed    | lookups that missed the cache **and** D1; only bad tokens can spend it |
| `registryPrivateRead`    | token id | open      | credentialed reads, which bypass the Cache API; a cost budget          |
| `portalRegistryToken`    | account  | closed    | portal mints                                                           |

A refusal answers 429 natively: OCI `TOOMANYREQUESTS`, or `rate_limited` with `Retry-After`.

- **Audit.**
  - Console actions: `registry_token.create`, `registry_token.revoke` and
    `registry_token.revoke_all`, recorded under the owner. Platform-scope actions go to
    `platform_audit`.
  - Portal actions: `portal.registry_token.create` and `portal.registry_token.revoke`, through
    `portalAudit`.
  - Cascade revokes record their `revoke_reason`: `license_deleted`, `link_removed` or
    `account_deleted`.
  - Reads are not audited. `last_used_at` and the metrics `registry.auth.{admit,refuse,miss}`
    stand in for that.
- **THREAT-MODEL.** A new subsection, "Registry credentials (F-20/F-21)", sits under the F-02
  registry section and covers:
  - bearer tokens as a new asset: hashed at rest, shown once, expiring, owner-bound;
  - licence-bound tokens extend a licence's rights to a string that can be shared, a residual
    risk equal to sharing a licence key;
  - the Godot URL token: it appears in Cloudflare's own request logs and in editor settings files,
    which is why that class is narrow and short-lived;
  - the HMAC pull-token key and its rotation;
  - cross-owner tokens counted as anonymous;
  - device trust not applied;
  - tightening a feed does not recall bytes already served publicly, nor anything held in client
    caches;
  - in-flight streams finish after a revocation.

  **§9 review triggers** gain:
  - a new principal kind;
  - a token accepted in a URL outside Godot;
  - any increase of `REGISTRY_TOKEN_TTL_SECONDS` or of the pull-token lifetime;
  - a credentialed answer reaching the Cache API;
  - a registry method other than GET, HEAD or Swift's `POST /login`.

  The existing trigger "a registry route answers … a method other than GET and HEAD" is reworded

## 7. Rollout

1. **F-21 lands after F-11 and F-12.** F-12 is added to F-21's `dependsOn`, because the snippets
   need `renderFeedSetup`. F-21 merges in one change: migration, Core store, ladder, routes, UI.
2. **Set the secret before deploying.** In each environment (dev, then staging, then production),
   run `wrangler secret put REGISTRY_TOKEN_KEY --env <env>` (32 random bytes, base64), then deploy.
   No feature flag is needed: every feed is `public` by default, and nothing changes until an
   operator switches a mode.
3. **Old Workers** ignore the new table, and `pkeyr_` tokens mean nothing to them. A feed set to a
   non-public mode on a Worker older than F-21 refuses every read, which is the landed tier-1
   behaviour. So a rollback **fails closed**, never open. Switching the mode back to `public`
   restores anonymous reads within 30 s.
4. **Deployed registry clients** keep working on public feeds. When an operator switches a feed,
   its clients get the native 401 and need the §6.3 configuration. The confirmation dialog says so.
5. **Platform feeds stay `public`.** Adopters of our SDKs, F-10's whole audience, are unaffected.
6. **Optional owner action:** add a GitHub secret-scanning custom pattern `pkeyr_[A-Za-z0-9_-]{43}`
   at organisation level.

## 8. Risks and open questions

The first three need the owner's answer. The rest are confirmations of a default.

**Q1. Should `/v2/` challenge anonymous callers?** **Recommendation: yes**, once
`REGISTRY_TOKEN_KEY` is set. That is the Docker Hub and GHCR behaviour. Anonymous pull tokens keep
public pulls working, and `docker login` then rejects a bad token at once instead of at the first
private pull. The cost: F-08's matrix and DEPLOYMENT's curl check move from "200" to "401 plus the
header". Alternative A: keep 200, so `docker login` always reports success. Alternative B: drop the
token service and use Basic challenges, as ECR does. That means no secret and no route, but it
departs from the approved F-01 §6.6.

**Q2. One owner per host for docker, SwiftPM and netrc.** A machine that needs private images or
Swift packages from **two** products on `pkg.plrs.im` cannot hold both tokens. **Recommendation:**
accept this for F-21 and document it. Every token stays bound to one owner, and platform feeds are
public, so they never take the slot. Account-scoped portal tokens can follow if a real customer
hits the limit. Alternative: per-owner hostnames (`acme.pkg.plrs.im`), which is a host-isolation
change and large.

**Q3. Portal self-service.** **Recommendation:** a licensee can mint a licence-bound read token
whenever the product has an enabled non-public feed, with no extra per-product setting. Vendors
control access through the feed's mode and revoke from the licence page. Alternative: a per-product
`portal.registryTokens` opt-in, off by default.

**Q4. Owner and CI principals pass every mode, `entitled` included,** because the operator can
already read its own bytes. Recommendation: confirm.

**Q5. Neither device tokens (`pkeyt_`) nor licence keys (`pkey_`) are registry credentials.**
A licence key would end up in plain text in `.npmrc` and `gradle.properties`. The device token is
a wire principal that is never shown, and no consumer needs it. Recommendation: confirm. The owner
brief's "device or customer licence" is met by licence binding: per-seat and per-customer licences
alike.

**Q6. Expiry is required, at most 365 days; there is no non-expiring token.** Recommendation:
confirm.

**Risks** (each mitigated above):

- Clients behave differently on challenges, for example Yarn needs `npmAlwaysAuth` and Gradle needs
  the Basic challenge. Mitigation: F-21's authenticated matrix in `registry-clients.yml`, one row
  per client in §6.3.
- `authenticated` and `licensed` are one strictness, as in `access.ts`. This is stricter than the
  portal's download meaning of `authenticated`. Mitigation: documented in `admin/feeds.md`.
- A package stricter than its feed is omitted from list documents. A licence holder therefore
  finds it in Godot search or the PyPI project list only by its direct name. Mitigation:
  documented.
