## Goal

Define and land the W-LX contract increment only: the licensing document's additive expiry and grant metadata, licence and sign-in refusal reasons, and the shared protocol/parity/corpus registries that describe them. This package does **not** port SDK behavior; that is LX-19's all-language wave.

## Evidence and boundaries

- [S-19 §7.10](../../notes/S-19-licensing-model.md#710-wire-impact-plan-mode) names the exact licensing additions: `entitlements[k].expiresAt`, `licenseExpiresAt`, `grants`, 401 reasons `expired|revoked|refunded|superseded`, and sign-in's 403 `not_entitled` reasons `no_base_licence|device_limit`.
- The same source constrains each grant to `{source, keys[], expiresAt?, trial?, shared?}`, at most 32 entries, and forbids an additional licence id, store tokens, order refs, account id, and store-identity hash.
- Existing `packages/shared-protocol/src/license.ts` has `LicenseDoc.entitlements` and `ManagedEntry`, but none of the new members. `packages/worker/src/services/license/document.ts` resolves and signs the document. `packages/worker/src/core/licensing/authz.ts` supplies the entitlement map.
- `packages/worker/src/services/license/document.ts:88-105` currently emits the specified nested 403 build-gate shape; any new reason work must preserve that established error envelope.
- CM-20 §3.3 assigns this package the W-LX store-commerce contract types, registries and WIRE-CONTRACT numbering; CM-29 already owns Commerce discovery and device-route wording. Do not reimplement either owner.

## Preconditions and decisions

1. **Plan-mode decision — protocol version.** S-19 §7.10 says the members are outside signed claims and follows the P4-13/P4-19/P4-29 precedent of retaining `PROTOCOL_VERSION = 4`; its explicit decision 9 requires lead confirmation during review. Record the decision and the compatibility rationale in the contract amendment before implementation.
2. **Dependency proof.** Before mutation, verify each graph dependency's landed contract. In particular, LX-09 must provide the effective entitlement semantics; LX-12/LX-41/LX-35 must define the lifecycle, term and quantity source data; CM-20 and CM-29 must provide the Commerce payload and route contract. If an input has not landed or differs, stop and amend this plan rather than inventing a wire field.
3. **Open source-to-wire mapping.** Repository evidence currently identifies neither the canonical storage/query for every `grants[]` property nor the exact ownership of `licenseExpiresAt`. The implementer must record the resolved producer for each member (or a blocking decision) before adding Worker output.

## Contract work

1. Amend `docs/security/WIRE-CONTRACT-V4.md` §2.1, §3.2, §3.6 and its error-body material with the S-19 semantics and forward-compatibility rule: the added members are outside claims; an old verifier ignores them; a malformed added member is ignored rather than making the signed document invalid.
2. Define the document members in `@polaris-key/protocol`:
   - a typed per-entitlement expiry representation compatible with the existing `ManagedEntry` map;
   - `licenseExpiresAt` and the bounded `grants` collection;
   - total, defensive accessors including `licenseGrantsOf(doc)` rather than requiring SDKs to parse unknown JSON themselves;
   - refusal-reason types for the applicable 401 and `not_entitled` 403 bodies.
     Preserve existing exported contracts and byte-stable property order for existing corpus fields. Do not introduce a duplicate entitlement model or change claims.
3. Add the Commerce protocol subpath and registry additions that CM-20 §3.3 assigns to LX-18. It must point to CM-29's published discovery/routes rather than restating or moving those routes. Add only the named unsigned members/features/constants; transcript authors remain LX-11 and CM-25.
4. Change the Worker only after the producer mapping is proven: document construction uses the canonical effective-entitlement/lifecycle data; relevant licence and sign-in failure paths emit the approved nested `reason` without widening disclosure. Preserve existing status codes and envelopes unless the approved contract expressly changes them.

## Corpus, parity and generated artifacts

1. Add the `errors.json` and `features.json` rows named in S-19: `license.entitlementInfo`, `license.grants`, and `license.statusReason`; add only the constants required by the approved W-LX contract.
2. Append (never rewrite historical) `licenseCases` showing old V4 verification of populated additive members, `licenseContentCases` with `expect.entitlements` after expiry, and gate-matrix cases for `isEntitled` after a 401 and after an entry expires.
3. Regenerate corpus/constants/transcripts using the repository generators and review the resulting SDK mirrors as generated artifacts. LX-18 does not claim the behavior implementation or UI snapshots that LX-19 owns.

## Explicitly out of scope

- SDK and UI-kit behavior, migration guide and release notes (LX-19).
- Commerce route moves, discovery, Worker handlers, and transcript recording (CM-29, LX-11, CM-25).
- New claims, a `typ` change, signed-claim changes, an unrelated discovery change, or a protocol-version bump without the recorded lead decision.
- Changes to entitlement combining/storage semantics owned by the dependencies.

## Acceptance criteria

- [ ] WIRE-CONTRACT-V4 names every S-19 §7.10 member, bounds and malformed/old-client behavior, with a recorded protocol-version decision.
- [ ] `@polaris-key/protocol` exposes typed, defensive licence-grant/expiry and refusal-reason contracts without a second entitlement model.
- [ ] Every new server reason uses the established status/envelope and has a targeted Worker test proving both the reason and non-disclosure behavior.
- [ ] Parity feature/error registries and appended corpus/gate cases cover the contract; generated corpus/constants/transcripts are fresh.
- [ ] No new wire change escapes this train: changes to claims, `typ`, discovery or route ownership are rejected or redirected to their owner package.
