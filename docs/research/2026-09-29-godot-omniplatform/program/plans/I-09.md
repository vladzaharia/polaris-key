## 7. Security: account takeover via attach

The holder is the account of `devices.subject` only, set by a completed sign-in; never taken from the request,
never `licenses.account_id`. Attach is scoped to the path product and to the device's own authorised licence.

1. **First claim wins (inherent).** A leaked key can be attached by an attacker's account before the buyer's.
   Mitigations: an email-bound licence needs a _verified_ matching email (`onAccountEmailVerified`) unless
   `claimByKey` (default **off**); a licence in an account never moves by key (CAS statement; the loser gets
   `license_owned`); enrolled devices keep working (step 2); the owner or console can detach and relink
   (`stmtMoveLicenseAccount`, I-12). New: every attach writes audit `license.attach` (account, device,
   `via:"device"`), shown on the licence in the console (Q4).
2. **Race:** two accounts, one CAS statement, no double owner. Account deletion detaches (existing hook).
3. **Oracle/enumeration:** `license_owned` answers only after a valid key and the existing rate limit; it carries
   no account detail and no key in `signInUrl`. Preview returns only the device's own licence.
4. **Sign-out cannot evict others:** `released` only for a sign-in-bound seat of the signing-out account;
   key-bound seats are never released by sign-out.
5. **No ambient auth:** bearer plus device header, no cookies, CORS without credentials.
6. **A stolen device token** can attach or sign out only the licence that device already holds: no new capability.
