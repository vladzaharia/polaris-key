# S-01: Apple-hosted Background Assets from a Godot 4.7 iOS export

Evidence markers: **[V]** primary source read raw, **[M]** measured here, **[S]** summary of a
source, **[I]** inference.

## Question

The brief asks four things, with evidence from a real TestFlight install:

1. Can a CI script add an Apple-hosted **Background Download extension** and an **App Group** to
   the Xcode project that Godot's iOS export writes, and does the result pass TestFlight processing?
2. Can the Godot app obtain an asset pack through `AssetPackManager` and mount a `.pck` from it with
   `ProjectSettings.load_resource_pack`?
3. Are asset-pack version updates differential on the wire (CONTENT §17 Q1)?
4. How long does each asset-pack state take, and which ASC states and webhook events appear?

## Method

All commands are in [`prototype/apple-ba/run.sh`](../prototype/apple-ba/run.sh) and its README.

1. **Source of truth for the extension.** Read Xcode 27's iOS template
   `Background Download Extension.xctemplate` and its ancestors (`iOS ExtensionKit Extension Base`,
   `ExtensionKit Extension Base`, `XPC Service Base`) raw [V]. The option "Apple-Hosted, Managed"
   writes: product type `com.apple.product-type.extensionkit-extension`; Info.plist
   `EXAppExtensionAttributes = { EXExtensionPointIdentifier = com.apple.background-asset-downloader-extension }`
   (the XPC base's `XPCService` key is overridden to empty); entitlements
   `com.apple.security.application-groups = [group.<app bundle id>]`; `LD_RUNPATH_SEARCH_PATHS`
   adding `@executable_path/../../Frameworks`; one Swift file,
   `struct DownloaderExtension: StoreDownloaderExtension` with an optional `shouldDownload(_:)`. The
   template cannot be instantiated headlessly, so the patch reproduces those keys.
2. **Export and patch.** `godot --headless --export-release iOS` with `export_project_only=true`,
   then copies: `unpatched/` built as is; `patched/` after `ruby patch/patch_ba.rb <proj> --app-group
group.dev.polariskey.research.pkba`, run twice with a hash of every project file in between.
   Each copy is built with `xcodebuild … -sdk iphoneos CODE_SIGNING_ALLOWED=NO` and `-sdk
iphonesimulator CODE_SIGN_IDENTITY=-` (ad-hoc, so the App Group entitlement is embedded).
3. **Shim.** `shim/pkba.m`: a GDExtension written against the C interface only, in Objective-C,
   calling `BAAssetPackManager` directly; built as an xcframework. GDScript sends JSON commands and
   drains events. It refuses to touch `sharedManager` unless `BAAppGroupID` and
   `BAHasManagedAssetPacks` are in the Info.plist, because `sharedManager` traps (a Swift
   `fatalError`, not an `NSError`) in an unconfigured process [M, macOS 27].
4. **Packs.** `packs/make_packs.py` builds four data-only packs with unique prefixes
   `pkba/<role>/` and a `.pkey/pack.json` marker: essential (1 MiB), prefetch (8 MiB), onDemand
   (4 MiB), and onDemand "big" (A6's 36 MiB v1/v2 pair). v2 of the small three changes one 40-byte
   JSON file; v2 of big is A6's realistic change (21 changed, 6 added, 3 removed source files).
5. **Simulator sessions.** `xcrun ba-serve` needs a TLS identity in the Mac's keychain; adding one
   was refused by this environment's permission policy, so `mock/serve.py` re-implements the
   server from files: it serves the manifest that `xcrun ba-package download-manifest create`
   writes and the `.aar` files (with Range support), and logs every request and byte. The
   simulator trusts a throwaway CA (`simctl keychain add-root-cert`) and gets the URL override that
   `ba-serve url-override` writes on macOS (`MBAURLOverride` in `com.apple.backgroundassets.managed`,
   read with `defaults` after running the tool) [M]. Both were removed afterwards. Plans: `install`
   (fresh install), `mount` (relaunch, no ensure), `update` (server moved to v2), `live` (update
   while mounted; server moved to v3 = v1 bytes), `emulate` (no Background Assets; PCKs copied into
   the App Group container).
6. **Differential, offline.** `packs/aar_diff.py` parses the `.aar` container and measures block
   reuse and `zstd -19 --long=27 --patch-from` bounds. A static scan of the simulator runtime's
   Background Assets binaries looked for delta, patch, differential, incremental or bsdiff strings.
7. **ASC.** Read the App Store Connect OpenAPI spec 4.5 (Apple's download) for the Background Asset
   schemas, states, webhook events and review endpoints [V]; wrote `asc/upload_pack.mjs` and ran it
   with `--dry-run`.

The patch writes, on the app target: the App Group in `probe/probe.entitlements`; `BAAppGroupID`,
`BAHasManagedAssetPacks = YES`, `BAUsesAppleHosting = YES` in `probe/probe-Info.plist`; a target
dependency and an "Embed ExtensionKit Extensions" copy phase (`dstSubfolderSpec = 16`,
`dstPath = $(EXTENSIONS_FOLDER_PATH)`, `RemoveHeadersOnCopy`). It adds target `PKBADownloader`
(`<app id>.BackgroundDownload`, Swift 5, `SKIP_INSTALL`, `APPLICATION_EXTENSION_API_ONLY`,
`MARKETING_VERSION`/`CURRENT_PROJECT_VERSION`/team/signing style copied from the app) with its
Swift file, Info.plist and entitlements. The product: `probe.app/Extensions/PKBADownloader.appex`,
84 KB, `CFBundlePackageType = XPC!`, linking BackgroundAssets, ExtensionFoundation and StoreKit
[M]. The app is 83 MB either way.

Tool choice: **Ruby `xcodeproj`**. It edits the project Godot wrote in place and additively, so
every Godot-generated setting survives; it ships with CocoaPods/fastlane and runs on the system
Ruby of every macOS runner. XcodeGen and Tuist generate a whole project from a spec, which would
mean re-describing Godot's project (libraries, `LD_CLASSIC`, `-Wl,-U,_<entry>` flags, resources)
and tracking it across Godot releases. The gem has no symbol for the ExtensionKit product type, so
the script sets the string; saving rewrites `project.pbxproj` formatting (a 345-line diff), which
Xcode accepts [M].

**Finding: the official 4.7.2 iOS template cannot link for an Apple Silicon simulator.** Its
`ios-arm64_x86_64-simulator/libgodot.a` is x86_64 only (`lipo -info`), so an arm64 simulator link
fails with 2,290 "ignoring file … found architecture 'x86_64'" warnings and undefined
`register_dynamic_symbol`, `add_apple_embedded_platform_init_callback` and `_main` [M]. Rosetta
is not installed on this Mac. Building the slice from the same tag (`scons platform=ios
target=template_release arch=arm64 simulator=yes`, 5 min 52 s, 168 MB) and merging it with `lipo`
fixes it [M]. The simulator template also has no Metal or Vulkan, so the probe uses the
Compatibility renderer [V, `platform/ios/detect.py`].

**Finding: a GDExtension framework must not share the app's bundle id.** The first install failed
with "The parent bundle has the same identifier … as sub-bundle at …/Frameworks/pkba.framework"
because the shim's Info.plist reused the app id [M]. P5-05's xcframework needs its own id.

### 2. Runtime, download and mount [emulated]

Without a server, on a fresh install: `getAllAssetPacks` returns an empty set;
`getAssetPack(withID:)` fails with `BAManagedErrorDomain 0: No asset pack with the ID … was
found`; `contents(at:)` fails with `ManagedBackgroundAssetsXPC.XPCInvocationError 1: No record of
the asset pack …` [M].

**`url(for:)` returns a path even when the file does not exist** (`…/Containers/Data/InternalDaemon/
<uuid>/Library/Caches/<app bundle id>/Staging/pkba/essential/content.pck`); `load_resource_pack`
then returns `false` in 0.1–0.2 ms [M]. The files live in the Background Assets daemon's staging
directory, not in the App Group container, and the path is the same for every version [M]. On a
simulator there is no sandbox, so whether a device app can open that path directly is
**unmeasured**; Apple documents `url(for:)` for reading, so it is expected to work [I].

With the mock server:

Other runtime observations [M]:

- `checkForUpdates` returned all four ids as updating (1.0–3.2 s); before it, `getLocalStatus`
  already reported `outOfDate, downloaded`, because the daemon refetches the manifest on most calls (6
  manifest GETs beside the 4 pack GETs in one update session).
- **Update while mounted is safe for the running session.** After v3 replaced v2 at the same path,
  the existing mount still read v2 (`hello.json` and the 8 MiB `padding.bin` both intact); a second
  `load_resource_pack` of the same path mounted v3 [M]. The system replaces the file rather than
  rewriting it in place, and Godot's open handle keeps the old inode [I]. Remounting over a mounted
  pack keeps entries the new version removed (A6 §2.7), so P5-05 should apply updates at the next
  launch.
- A pack downloaded in an earlier session is readable (`contents(at:)`, `url(for:)`) without
  calling `ensure` again, so reading a prefetch pack's marker before `ensure` works once the system
  has the pack. Before any download it fails (notes/E8 §6 Q1, partial). Whether install-time
  prefetch finishes before first launch needs a TestFlight install: `simctl install` fires no
  install event, and `backgroundassets-debug --simulate` does not accept simulators ("The requested
  device … is not available").
- `emulate` plan (no Background Assets at all): the same PCKs copied into the App Group container
  mount in 0.48 ms and 2.17 ms, confirming the GDScript half independently.

### 3. Are updates differential? [emulated + measured offline + static]

The `.aar` format [M]: an Apple Archive stream in a `pbze` container (LZFSE), 1 MiB independent
blocks. Paths are `Contents/<file selectors>` plus the pack's `Manifest.json` with a
`toolsVersion`. Entries carry uid, gid, mode and times; the root, `Contents` and the embedded
manifest carry the packaging time even when every input mtime is pinned, so **two `ba-package`
runs never produce the same bytes** (30 differing bytes on a 1 MiB pack) [M].

| v1 → v2                                                 | essential (40 B change) | prefetch (40 B) | onDemand (40 B) | big (A6 realistic change)                                                      |
| ------------------------------------------------------- | ----------------------- | --------------- | --------------- | ------------------------------------------------------------------------------ |
| v2 `.aar` (what a whole-pack update costs)              | 1,050,096               | 8,390,237       | 4,195,811       | **11,705,478**                                                                 |
| **bytes on the wire, managed client → mock** [emulated] | **1,050,096**           | **8,390,237**   | **4,195,811**   | **11,705,478**                                                                 |
| 1 MiB LZFSE blocks reusable from v1                     | 0 of 2                  | 7 of 9          | 3 of 5          | 0 of 36                                                                        |
| `zstd --patch-from` over the `.aar` files               | 303                     | 931             | 578             | 10,425,454                                                                     |
| `zstd --patch-from` over the decoded streams            | 307                     | 935             | 580             | **606,274**                                                                    |
| A6 baseline (same 36 MiB pair)                          |                         |                 |                 | full zstd 9.8 MB; native delta **602 KB**; file-aware 64 KiB chunks **985 KB** |

- The managed client downloaded every v2 pack whole, with no `Range` header, after a manifest that
  gives one URL and one `downloadSize` per pack version [M]. `ba-package download-manifest create`
  writes exactly that shape (`id`, `version`, `url`, `downloadSize`, `downloadPolicy`,
  `host.thirdParty`) [M].
- The iOS 26.5 simulator runtime's `backgroundassets.user` daemon, `BackgroundAssets.framework`
  and the four `ManagedBackgroundAssets*` private frameworks contain no "delta", "patch",
  "differential", "incremental" or "bsdiff" strings (excluding "dispatch") [M]. Apple-hosted
  packs may still be fetched through store infrastructure that does have app-update deltas; that
  is what the TestFlight measurement must settle [I].
- Even a perfect server-side binary delta over compressed `.aar` files is useless for a realistic
  change (10.4 MB of 11.7 MB), because the content shifts across LZFSE block boundaries. Only a
  delta over the decoded stream (606 KB, matching A6's 602 KB) would help, and nothing in the
  documented protocol can carry one.

**Answer: plan for whole-pack.** The whole-pack cost of `apple-ba` for the A6 pair is 11.7 MB,
19% more than `pkey-cdn`'s full zstd pack and 19× A6's delta. Keep packs small and split by change
rate (CONTENT §6), because the pack is the unit of every update. CONTENT §7's "no documented
differential; plan for whole-pack" stands, now with measurements behind it.

Webhook events (`WebhookEventType`, 12 values) include the four Background Asset ones notes/E1

Two spec findings for P5-08 [V]:

- **App Store review** of an asset-pack version goes through `POST /v1/reviewSubmissions` plus
  `POST /v1/reviewSubmissionItems` with a `backgroundAssetVersion` relationship.
- **External beta review has no API.** `BetaAppReviewSubmissionCreateRequest` relates only to a
  `build`, so submitting a pack version for external TestFlight appears to be App Store Connect UI
  only [I from the spec]. notes/E1 §E5's "`POST /v1/betaAppReviewSubmissions` (beta asset-pack
  review)" is wrong for 4.5.
- **Archiving is in the API**: `PATCH /v1/backgroundAssets/{id}` with `archived: true`
  (`BackgroundAssetUpdateRequest`) [V]. An Apple engineer confirms an archived pack cannot be
  unarchived and **its id cannot be reused** (forum thread 810341, December 2025) [V].

### 5. Asset-pack id rules [measured + primary source]

- `xcrun ba-package` accepts **any** string, including empty, 256 characters, spaces, slashes,
  dots and non-ASCII [M, `packs/id_rules.sh`].
- **App Store Connect accepts only alphanumerics and hyphens; periods are unsupported** (Apple
  Frameworks Engineer, forum thread 818337, April 2026, answering a Transporter `-19243` "Found
  invalid values: distill.pipeline.zh-baseline") [V].
- No length limit is documented; the ASC OpenAPI schema has no pattern or `maxLength` [V].
- Ids are unique per app and cannot be reused after archiving [V].

## Recommendation

**GO for P5-05's Background Assets part**, with these defaults so P5-05, P5-02 and P5-08 can
proceed before the device run.

**Patch recipe (P5-05 turns `patch/patch_ba.rb` into a product):**

1. Run after `godot --export-release <preset>` with "Export Project Only", only for store presets
   (App Store, TestFlight); the sideload preset skips it.
2. Add target `<Name>` of type `com.apple.product-type.extensionkit-extension`, bundle id
   `<app id>.BackgroundDownload`, one Swift file with a `StoreDownloaderExtension`
   (`shouldDownload(_:)` is where `contentApi` gating goes), Info.plist with
   `EXAppExtensionAttributes.EXExtensionPointIdentifier = com.apple.background-asset-downloader-extension`
   and `CFBundleVersion`/`CFBundleShortVersionString` from the app's
   `CURRENT_PROJECT_VERSION`/`MARKETING_VERSION`.
3. App Group `group.<app id>` on both targets' entitlements; app Info.plist `BAAppGroupID`,
   `BAHasManagedAssetPacks = YES`, `BAUsesAppleHosting = YES`, and no other `BA*` keys.
4. Embed into `$(EXTENSIONS_FOLDER_PATH)` with a copy phase (`dstSubfolderSpec 16`) and a target
   dependency; copy team, signing style and deployment target from the app.
5. Idempotent: detect the target by name and change nothing on a second run.
6. CI then archives and exports with two provisioning profiles (app and extension), both with the
   App Group.

**Shim shape:** a GDExtension over the C interface with no godot-cpp, in Objective-C calling
`BAAssetPackManager` directly (no Swift runtime inside the extension), built as a two-slice
xcframework with its own bundle id. P5-05 may still put the logic in Swift behind `@_cdecl` for
reuse by the Swift SDK. Lessons for `PolarisKeyApple`:

- `pack_progress(id, bytes, total)` maps to the download delegate's `NSProgress`
  (`completedUnitCount`/`totalUnitCount`, bytes of the `.aar`).
- `pack_ready(id, path)`: after `ensure` completes **or fails**, re-check `getLocalStatus`; treat
  `downloaded` without `outOfDate` as ready. Then resolve `url(for:)` and check the file exists,
  because `url(for:)` returns a path for missing files.
- `pack_failed(id, err)`: only when the status is not `downloaded`. Carry the `domain code:
message` string.
- Never call `sharedManager` unless the Info.plist keys are present, because it traps.
- Resolve paths fresh every launch off the main thread (3–8 ms here); mount at boot and apply
  updates at the next launch.
- For simulator CI, ship or build an arm64 simulator `libgodot.a` (or run under Rosetta).

**Asset-pack id rule:** `^[A-Za-z0-9]+(-[A-Za-z0-9]+)*$`, lower case by convention, at most 64
characters until Apple documents a limit, and never reused. The Polaris Key convention becomes
**`<pack>-c<contentApi>`** (`foes-c3`); a dotted pack id such as `diceroll.foes` maps to
`diceroll-foes-c3`.

**If the device run fails** (the extension is rejected in processing, or a device app cannot
read the staging path): `apple-ba` falls back to `pkey-cdn` with a background `URLSession` in
P5-05, as the brief says, and nothing else in the design changes.
