# E7 - Server-side libraries, CI tooling and reference platforms for omni-platform Godot distribution

Research track E7, 2026-09-29. Repo untouched (read-only skims of AGENTS.md, README.md, CONCEPTS, release store/migrations, Diceroll RELEASE.md and the content-streaming design doc). Scratch experiments live in `(scratch path, not kept){wtest,gitmeta}`.

## 0. Executive summary (the 14 things that matter)

1. **Do not build store uploaders. Wrap them.** Every store has a maintained, permissively licensed CLI/Action (asc, fastlane, r0adkll/upload-google-play, msstore, butler, game-ci/steam-deploy, winget-releaser, Flathub PR flow). Polaris Key's value is the _control plane_: artifact registry, channels, entitlement-gated download, signed feeds, store-link records. Store tools stay in CI.
2. **Split "bytes" from "control".** Binaries (IPA/AAB/DMG/EXE, 100 MB - 2 GB) must never transit a Worker: request-body cap is 100 MB on Free/Pro (200 MB Business), memory is 128 MB [V]. CI uploads to R2 via presigned PUT (or store CLIs upload to the store); the Worker only records metadata, verifies hash after the fact, and serves/redirects downloads. The Worker _should_ call small-JSON store APIs (ASC review status, Play track promotion, notary status) with `jose` + `fetch`.
3. **New, tested in workerd 1.20260929.1 (today's runtime):** `jose` (ES256 ASC JWT, RS256 Google service-account JWT, remote-JWKS verification of GitHub Actions OIDC tokens) works and is ~30-45 KB bundled. fflate/unzipit/zip.js + bplist-parser + plist + two AXML parsers read IPA `Info.plist` and APK `AndroidManifest.xml` in-Worker. node-forge and pkijs both produced PKCS#7/CMS detached signatures that `openssl cms -verify` accepts (=> F-Droid `entry.jar` signing is _feasible_ in-Worker, though the key should stay in CI/HSM). `crypto.DigestStream` hashes a 32 MiB R2-style stream correctly (SHA-256 matched). WebCrypto Ed25519 signed 32 MiB in 111 ms and verified under Node.
4. **Apple's official App Store Server Library (Node, v3.1.0, MIT) works in Workers only if imported lazily.** A top-level `import` crashes at load ("Disallowed operation ... generating random values ... within global scope") because its dependency `jsrsasign` (npm-deprecated: "no longer maintained") does random generation at module init. A dynamic `await import()` inside the request handler works: `SignedDataVerifier` verified a synthetic x5c chain with Apple marker OIDs, and `AppStoreServerAPIClient` reached Apple's sandbox API (401 with a fake key, as expected). ~0.9 MB bundle. Use it, lazily, for StoreKit-2 / App Store Server Notification v2 verification; do not use it just to mint ASC JWTs (10 lines of jose).
5. **Avoid the googleapis stack in the Worker.** `@googleapis/androidpublisher` 42.1.0 imports only with a `process` shim, is ~1.08 MB, and a failed service-account exchange returned an undecoded gzip body (gaxios/fetch mismatch). Raw REST + jose was 31 KB and returned clean JSON errors. Note: this was an esbuild-bundled harness, not wrangler; treat as indicative.
6. **Sparkle's `sign_update` is macOS-only but the signature is just pure Ed25519 over the entire file** (`Data(contentsOf: .mappedIfSafe)` -> vendored `ed25519_sign`; key via Keychain or `--ed-key-file -` on stdin) [V]. A ~30-line Node/Python signer in the `pkey` CLI is a byte-compatible replacement; sign in CI (whole file needed; WebCrypto has no Ed25519ph/streaming). This matches the existing `appcast.ts` design (`.sig` sidecar, Worker never holds the key).
7. **Linux CI can do almost everything except build the iOS binary.** macOS: `rcodesign` (Godot's own supported path) or `quill`; Windows: `osslsigncode` (Godot's supported path) or `jsign` (adds Azure Artifact Signing/Key Vault/AWS-GCP KMS/HSM; Microsoft's own Action is Windows-runner-only); Android: `apksigner`; iOS: Godot only exports an Xcode project and needs macOS+Xcode, but _upload_ is now possible from anywhere via the App Store Connect **Build Upload API** (buildUploads/buildUploadFiles; ASC API 4.1+).
8. **rcodesign is the one important tool with a maintenance smell:** latest crates.io/GitHub release is 0.29.0 from 2024-11-29 (MPL-2.0); main still gets Dependabot bumps and one human commit in Apr 2026; 111 open issues. Pin the version, keep `quill` as fallback.
9. **Date-sensitive platform change: Android developer verification enforcement starts 2026-09-30** (tomorrow) in Brazil, Indonesia, Singapore, Thailand on certified devices; global in 2027. Package name + signing key must be registered (Play Console auto-registers Play apps; Android Developer Console for off-Play apps; $25 one-time; free limited-distribution for up to 20 devices; "advanced flow" keeps a sideload path; ADB unaffected; developer APIs launched Aug 2026). This directly hits APK/Obtainium/F-Droid-repo channels (Diceroll's APK is currently debug-signed). Polaris should model "verification registered?" per (package, signing-key) [V - developer.android.com + F-Droid + press].
10. **Keygen.sh is the right data model to copy** (Product -> Package -> Release[DRAFT/PUBLISHED/YANKED, channel, tag, semver, constraints] -> Artifact[filename, filetype, platform, arch, size, checksum, signature, status WAITING/UPLOADED/FAILED/YANKED]; `GET /releases/{v}/upgrade?constraint&channel` semver-sorted; entitlement constraints; policy `expirationStrategy` giving perpetual-fallback; 307-to-presigned upload). Polaris already has ~60% of it (release_artifacts has platform/arch/kind/sha256/storage_key/sparkle_signature/access). Missing: upload API + artifact status lifecycle, release status/yank, channel precedence, a generic upgrade endpoint, packages/engines, license-expiry-aware access.
11. **For downloadable content packs copy Unity Cloud Content Delivery + Expo Updates**: bucket -> entries (content hash) -> immutable **release snapshot** -> named **badge** (pointer, e.g. `latest`, `beta`); plus Expo's `runtimeVersion` compatibility gate and `rollBackToEmbedded`/`noUpdateAvailable` directives. Godot 4.4+ already supports delta-encoded patch PCKs.
12. **Godot's built-in `Crypto` supports RSA sign/verify (SHA-256/SHA-1/MD5 hashing) only - no Ed25519, no ECDSA** [V - docs]. That is almost certainly why Diceroll's updater manifest is RSA-3072 PKCS#1 v1.5. A GDScript client cannot verify Polaris's Ed25519 JWS without a GDExtension (libsodium/monocypher/ed25519-dalek) or an RSA sidecar signature (WebCrypto in workerd supports RSASSA-PKCS1-v1_5).
13. **Public package managers need public, immutable, hash-pinned URLs** (winget InstallerSha256, Homebrew cask sha256, Scoop hash, Flathub extra-data sha256). The entitlement-gated gateway is incompatible with them; add a stable public path (content-addressed or version-pinned) for artifacts flagged `public`.
14. **GitHub immutable releases** (tags + assets locked after publish; recommended draft -> upload -> publish) break Diceroll's "rolling `channels` release" (mutated assets) if the repo setting is enabled. Moving feed hosting to the Worker removes that mutation entirely.

## 1. Method and evidence quality

- Web research via WebSearch/WebFetch, plus direct registry queries (npm, PyPI, RubyGems, crates.io, Homebrew formulae API) and **shallow git fetches of upstream repos** for tag dates, last-commit dates and LICENSE headers (the GitHub REST API is not reachable from this sandbox). WebFetch's summarizer got several years wrong on GitHub release pages (e.g. it reported Sparkle 2.10.0 as 2024; the tag is 2026-09-13), so **all "last release" dates below come from git tags / registries, not from page summaries.**
- Runtime feasibility was **tested, not guessed**: a scratch project with `workerd 1.20260929.1` (the current runtime), esbuild bundles, compat date 2026-09-01. Note workerd itself now says `nodejs_compat` "became the default as of 2026-08-04". Harness details: bundles built with esbuild `--platform=node`, `createRequire` banner for CJS `require()`, both "node-like" and "wrangler-like" (browser-first main fields, `workerd,worker,browser` conditions) variants; results were the same unless noted. Real Wrangler may differ slightly on Node-builtin shimming.
- Worker repo facts (read-only): `packages/worker` deps are `jose ^5.9.6` and `yaml`; there is **no R2 binding yet** (D1/KV/DO only); the release truth store (`release_metadata`, `release_artifacts`, `release_channels`, `release_health`, `release_download_tokens`) already exists; Sparkle appcast is rendered on the fly from GitHub release data with a sibling `.sig` asset for `sparkle:edSignature`.

- **F-Droid `entry.jar` signing in the Worker is technically feasible (pkijs/node-forge tested) but not advisable**: repo keys belong in CI/HSM. Serve fdroidserver's static output from R2 instead.

## 5. Hosted services and reference platforms

### 5.1 Keygen.sh - schema extracted from official docs [V]

Pricing (keygen.sh/pricing): Dev (free): 100 active licensed users, 10 product releases, **no Distribution API**; Standard tiers add the Distribution API and engines (OCI/Docker, npm, RubyGems, Tauri, PyPI, raw/binary), audit + request logs; Enterprise adds SSO/SAML, SLA. "Never a percentage of revenue." Self-host: Keygen CE (free, Rails + Postgres + Redis + S3/R2) and paid EE; the repo license is **Fair Core License v1.0 with ALv2 future license** (keygen-api LICENSE.md). Relay (offline license leasing server, MIT) exists but is licensing-only. Keygen Dist v1 is deprecated and folded into the main API (Dist v1 limits: 100 MB standard uploads, RELEASES file 5 MB, single-range only).

**Product**: `name`, `code`, `url`, `platforms[]`, `permissions`, `metadata`, **`distributionStrategy` = LICENSED (default; license required) | OPEN (no auth; public downloads page/open source/freemium) | CLOSED (admin only; generate links server-side)**.

**Package** (scoped stream within a product): `key` (required), `name`, `engine` (`pypi|npm|rubygems|oci|tauri|raw`|null), `metadata`. Releases may belong to a package; `tag` is unique per product/package. Engines are protocol renderers over the same artifact store: `.../engines/tauri/<package>` (needs platform/arch/version query params), `.../engines/raw/<product>[/@<package>]/<release>/<artifact>`, plus npm/pypi (PEP 503)/rubygems/oci; an Electron engine for electron-builder.

**Release**: `version` (semver, no `v`, unique per product), `name`, `description`, `tag` (e.g. `latest`, unique per product/package), **`channel` = stable|rc|beta|alpha|dev**, **`status` = DRAFT (initial) | PUBLISHED | YANKED** (yank = delist but retain), read-only `semver{major,minor,patch,prerelease,build}`, `metadata`, `backdated` (lets expired licenses reach patch releases), `created/updated/yanked`. Relationships: product, package, artifacts, **constraints** (entitlements required), entitlements, upgrade. Actions: `publish`, `yank`, `constraints` attach/detach. Retrieve by UUID **or version or tag**. Filters: product, package, channel, status, `entitlements[]`, engine. "Releases represent versioned buckets to put artifacts into."

**Artifact**: `filename` (unique per release, may contain dir prefixes), `filetype` (must match extension), `filesize` (max 5 GB), **`platform`**, **`arch`** (free strings; `/platforms` and `/arches` are read-only listings derived from artifacts; typical `darwin|linux|windows`, `amd64|arm64`), `signature` (Ed25519ph, base64), `checksum` (SHA-512, base64), `metadata` (extra checksums, engine requirements like `requiresPython`), read-only **`status` = WAITING|UPLOADED|FAILED|YANKED** (fails if not uploaded within 1 h; auto-pruned after 24 h). **Create** = `POST /artifacts` -> `307` redirect to a presigned S3 upload URL (`Prefer: no-redirect` to get JSON instead); **download** = `303` to a presigned URL (default TTL 10 min; `ttl` 1 min - 1 week for admin/product callers). Auth by license key/token, user, product, admin; OPEN strategy needs none. Access rule: the license must satisfy the release's entitlement constraints and pass the policy's `expirationStrategy` check (see below).

**Policy `expirationStrategy`** (this is the killer feature for perpetual-fallback licensing): `RESTRICT_ACCESS` (default; expired licenses keep releases _published before expiry_, upgrades only to those), `REVOKE_ACCESS` (no releases at all), `MAINTAIN_ACCESS` (like RESTRICT but validation keeps passing), `ALLOW_ACCESS` (all releases).

**Upgrade**: `GET /v1/accounts/{acct}/releases/{release}/upgrade?product=&package=&constraint=1.0&channel=` -> latest release **sorted by semver (not creation time)**, default channel = current release's channel (so a stable client only sees stable; a beta client sees beta+ per precedence stable < rc < beta < alpha; dev standalone), only entitlement-eligible releases, **404 when no upgrade**. Response is JSON:API with links to artifacts; the client then fetches the artifact by filename. `constraint` lets a licence cap at a major (`1.0` -> 1.x).

**What Keygen lacks that Polaris Key should not copy**: no artifact manifests/attestations, no per-download analytics beyond request logs, no delta updates, no rollout percentages, no store-link records.

Godot facts that shape the design [V from docs.godotengine.org]:

- macOS: export from Linux with **rcodesign** (signing PKCS#12, notarization via ASC API key); DMG creation is macOS-only in the exporter.
- Windows: sign with SignTool, or **osslsigncode** on other OSes; `GODOT_WINDOWS_CODESIGN_IDENTITY_TYPE/IDENTITY/PASSWORD` env overrides; no first-class Azure Artifact Signing hook -> run jsign/Artifact Signing as a post-export step.
- iOS: macOS + Xcode required; Godot outputs an Xcode project only.
- **PCK patching**: patch PCKs with delta encoding (compression level default 19; `Base Packs` must be the exact files loaded at runtime); `ProjectSettings.load_resource_pack()` with `replace_files`. This is the native mechanism behind "content packs with channels".
- `Crypto`: RSA only for sign/verify; `HashingContext`: MD5/SHA-1/SHA-256 with streaming update - fine for verifying pack hashes, insufficient for Ed25519.

**Should Polaris Key publish an official Action `polaris-key/publish`? Yes, but narrow.** It should be the _registry/promotion_ step, not an export or store-upload framework (Diceroll already has a composite `setup-diceroll` action for Godot+templates+asset cache; do not duplicate `setup-godot`).

Proposed Action responsibilities:

1. **Authenticate by GitHub OIDC** (`permissions: id-token: write`, audience `polaris-key`); Worker verifies with jose against GitHub's JWKS (tested) and binds to repo/workflow/ref claims. No long-lived publish secrets.
2. **Discover + classify** files (reuse `assets.ts` classifier; shared vocabulary above), compute sha256/size, optionally extract metadata (plutil/aapt2 or the tested JS parsers).
3. **Sign sidecars client-side** with `pkey sign` (Sparkle/WinSparkle Ed25519 file signature; optional RSA-PKCS1 sidecar for Godot GDScript clients; minisign optional). Keys via secrets/KMS.
4. **Upload** using presigned R2 PUT (or "register-only" when bytes stay on GitHub Releases/store), with retry/resume; **finalize** so the Worker verifies size+sha256 with `DigestStream` and flips WAITING->UPLOADED.
5. **Create/publish release, attach to channel(s)/package**, set rollout %, `critical`, `min_binary`, `runtime_version`; support `draft` for gated publish.
6. **Record store listings** from other steps (`pkey release link-store --store steam --branch beta --build-id ...`), and **notify** (webhook/Discord/Slack).
7. Optionally record a GitHub artifact attestation reference.

Explicitly not in the Action: exporting, building, signing binaries, store uploads. Ship **recipes** (composable snippets) for `setup-godot`, `rcodesign`/`quill`, `jsign`/`osslsigncode`, `apksigner`, `asc`/fastlane, `r0adkll/upload-google-play`, `setup-msstore-cli`, `butler`, `game-ci/steam-deploy`, `flatpak-github-actions`, `winget-releaser`, Homebrew bump.

Contract-first caveat (CLAUDE.md/AGENTS.md): new artifact-upload/finalize routes and any new signed document shape (pack manifest, `signatures[]`) are wire-touching -> plan mode, contract -> catalog -> corpus regen -> SDKs (Node, Python, Swift, React); a Godot addon adds a sixth consumer. `pnpm gen corpus --check` and `typecheck:workerd`/`test:workerd` are the relevant drift gates.

## 7. Content hosting: R2, GitHub Releases, B2, and "byte providers"

### 7.1 Cloudflare R2 [V unless tagged]

- **Pricing**: Standard $0.015/GB-mo; Infrequent Access $0.01/GB-mo (30-day minimum, $0.01/GB retrieval); Class A $4.50/M (IA $9.00/M), Class B $0.36/M (IA $0.90/M); free tier 10 GB-mo, 1 M Class A, 10 M Class B; **egress free** (Workers API, S3 API, r2.dev/custom domains).
- **Limits**: 5 TiB per object; 5 GiB single-part PUT; multipart up to 10,000 parts (4.995 TiB); key 1,024 bytes; metadata 8,192 bytes; 1 write/s per identical key (429); 100 custom domains/bucket; 1,000,000 buckets; uncompleted multipart auto-abort after 7 days.
- **Presigned URLs**: GET/HEAD/PUT/DELETE, max 7 days, **S3 domain only - not custom domains** (use WAF HMAC validation for custom-domain auth); no POST form uploads; treat as bearer tokens; CORS needed for browser use. Generate with `aws4fetch` (tested) or AWS SDK.
- **Worker binding**: `get(key, {range, onlyIf})` streams the body (range accepts headers), `put` with checksum option (md5/sha1/sha256/sha384/sha512), multipart create/resume/complete, `list` (1000), `delete` up to 1000 keys. Worker request bodies are still capped, so large uploads go presigned/multipart from CI.
- **Event notifications**: `object-create` (Put/Copy/CompleteMultipartUpload) and `object-delete` -> Cloudflare Queues; prefix/suffix filters; <=100 rules/bucket; payload has account, action, bucket, object{key,size,eTag}, eventTime. Good for the WAITING->UPLOADED transition; hash verification is a separate step (`DigestStream` in a Queue consumer, note CPU limits).
- **Cache Reserve**: R2-backed persistent CDN tier, $0.015/GB-mo + ops, needs TTL >=10 h and Content-Length, 30-day retention. Rarely needed when the origin _is_ R2; useful in front of GitHub/B2 origins.
- Cost sketch for Diceroll: ~73 MB PCK + ~160 MB macOS binary + others, say 2 GB stored across versions ~ $0.03/mo, zero egress; Workers Paid $5/mo covers 10 M requests.

### 7.2 GitHub Releases [V]

2 GiB per asset, up to 1000 assets per release, no limit on release size or bandwidth. REST rate limits: 60/h unauthenticated, 5,000/h authenticated, **GitHub App installation 5,000/h baseline (+50/h per repo >20 and per org user >20, cap 12,500)**, `GITHUB_TOKEN` in Actions 1,000/h per repo; secondary limits (100 concurrent, 900 points/min, 80 content-creating/min). **Immutable releases**: after publish the tag is locked (cannot move/delete while the release exists) and all assets are protected; title/notes/prerelease/latest flags remain editable; a release attestation is generated automatically; recommended flow draft -> attach all assets -> publish. Consequence: mutable rolling releases (Diceroll `channels`) conflict.

### 7.3 Backblaze B2 [V pricing page]

$6.95/TB-mo; free egress up to 3x stored data, then $0.01/GB; **unlimited free egress to CDN partners (Cloudflare, bunny.net, Fastly)**; Class A/B/C calls free, Class D $0.004/10k (first 2,500/day free); first 10 GB free; S3-compatible. Useful as a second S3-compatible provider or cheap large-archive tier, but R2 already gives free egress without a partner hop.

### 7.4 Should the release server support multiple "byte providers"? Yes.

Model each artifact as `locations[]` (priority-ordered, health-checked) with a provider interface:

```
ByteProvider { id; capabilities{range, presign, publicUrl, immutable, maxObject};
  head(ref) ; open(ref, range?) -> stream ; redirect(ref, ttl?) -> URL | null }
```

| Provider   | Use                                                        | Notes                                                                                                                                                                                                                                    |
| ---------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `r2`       | Default for first-party builds and content packs           | Stream via binding for gated downloads (auth + range + ETag=sha256) or 302 to a public custom domain for `access=public` (CDN-cacheable, no Worker cost) or presigned S3 URL (<=7 d) for gated large files that should bypass the Worker |
| `github`   | Open-source projects, mirror, current behavior             | Proxy with App installation token for private repos; 302 to `browser_download_url` when public; 2 GiB cap; App API rate ceiling 12.5k/h; immutable-release aware                                                                         |
| `s3`       | B2/S3/MinIO/Wasabi                                         | SigV4 presign via aws4fetch; B2 + Cloudflare = free egress                                                                                                                                                                               |
| `store`    | Steam, App Store/TestFlight, Play, MS Store, Flathub, itch | **Link-out only**: `itms-apps://`, `market://`, `ms-windows-store://`, `steam://`, `https://flathub.org/apps/<id>`; record state + external id; no bytes                                                                                 |
| `external` | Anything else with a stable URL                            | Keygen-style "external file" (sha256 pinned)                                                                                                                                                                                             |

Rules: hash-pin every location (all providers must return the same sha256); public package-manager URLs must be immutable; store the _preferred_ provider per (channel, access level); optionally emit `mirrors[]` in JSON feeds (Sparkle cannot).
