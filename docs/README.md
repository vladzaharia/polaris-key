# docs

Operator material, design specs, the security record and research for the repository; the published site lives in `packages/docs`.

## Where it sits

- People read it: operators (`RUNBOOK.md`, `DEPLOYMENT.md`), UI authors (`design/`), reviewers (`security/`) and planners (`research/`).
- `packages/docs` imports `RUNBOOK.md` and `DEPLOYMENT.md` into the Operate → Platform pages and `PRIVACY.md` into the Reference page "What apps collect". The site reads the file in place, so there is one copy.
- `design/BRAND.md` is implemented by `packages/brand`; `design/UI-KITS.md` by the UI kits and `packages/ui-qa`.
- `security/WIRE-CONTRACT-V4.md` is the normative wire spec that `conformance/` pins.
- Long-form adopter and authoring material is not here; it lives in `packages/docs/src/content/docs/`.

```
    UI-KITS.md        one design system for every SDK's UI kit; UI-KITS-LANGUAGE-MATRIX.md compares kits
    admin/            console component and page inventories

    ui-kits/          per-platform kit mockups and the design review checklist
    console-product-card/, flows/, licenses/, portal/, setup/, sign-in/, experience/   static boards and screenshots
  security/         repo only; never published to the site
    THREAT-MODEL.md   the threat model
    WIRE-CONTRACT-V4.md   normative wire contract; V2 and V3 are the superseded record
    arch/             architecture reviews: multi-tenant blast radius, operational resilience
  legal/            unreviewed drafts of the privacy policy, terms and help page, with review notes
  research/         dated plans and research, one folder per topic
    2026-09-29-godot-omniplatform/   research, parity, content notes and the execution program (program/)
    2026-10-07-dx-consolidation/     the developer and administrator consolidation plan
    2026-10-08-docs/                 the docs site plan and the style guide

    2026-10-08-sdk-usability/        SDK and UI-kit usability findings

```

Entry points:

- Program: `research/2026-09-29-godot-omniplatform/program/README.md` (`INDEX.md` there is generated from `workpackages.json`).
- Agent-readability plan: `research/2026-10-08-llm-audit/README.md`.
- Docs plan: `research/2026-10-08-docs/README.md`; the writing rules are `research/2026-10-08-docs/style-guide.md`.

`superpowers/` is historical. Read the spec's closeout, not the plan, for shipped state.

## Rules here

- Terminology comes from the concepts page, not from these files; when a file and the glossary disagree, the glossary wins. `pnpm --filter @polaris-key/docs lint:docs` checks the published pages. See [AGENTS.md](../AGENTS.md).
- The naming is Polaris Key; the `@plrs`, `polaris-suite` and `.polaris/` states in `superpowers/` are dead. See [AGENTS.md](../AGENTS.md).
- Raw hardware values are hashed on-device and never transmitted; `PRIVACY.md` is where that is written. See [AGENTS.md](../AGENTS.md).
- The docs site is tiered and the repo is the agent-readable source: Platform pages, which include the runbook, need `can(platform, docs)`. `packages/worker/test/docsGate.test.ts` holds the tiers. See [AGENTS.md](../AGENTS.md).
- Generated files carry a GENERATED banner. `pnpm gen registry-docs` writes the generator table in AGENTS.md and `pnpm gen graph-index` writes the program `INDEX.md`; `pnpm gen --check` fails on a hand edit. See [AGENTS.md](../AGENTS.md).
