pkey login

The CLI signs in to the console with a personal token that has the admin scope. You approve it in the browser with your passkey; the token can never do more than your roles allow, lasts 30 days and lives in the system keychain. PKEY_ADMIN_COOKIE is gone.

What stays true

The admin API checks the token against Priya’s roles at each call, so removing a role takes effect on the token too.
A token is admin or packages-only, never both: the package registry refuses admin tokens and the admin API refuses packages tokens.
No browser here (SSH, CI): the terminal says so and shows only the code to enter at key.plrs.im/manage/device on another device. CI uses a service token, not pkey login.
--json prints one object per state (pending, then signedIn or cancelled) and never prompts.
