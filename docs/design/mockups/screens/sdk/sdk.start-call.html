polaris-key.json and the start call

One file holds DJDL’s product facts. Every SDK reads it from the app’s own files, never the network, then starts with fromConfig() and boot(). The same file and the same two calls in all six SDKs.

The file

polaris-key.json
{
  "$schema": "https://key.plrs.im/schemas/v1/sdk-config.schema.json",
  "configVersion": 1,
  "productSlug": "djdl",
  "baseUrl": "https://key.plrs.im",
  "pinnedKeys": {
    "djdl-2026": "P0nMyA9QpvpspaIXBjtb6PfXZu4jIiGPlNzkRm28_6E"
  },
  "pinnedReleaseKeys": {
    "djdl-rk-2026": "u4Xw9QeLr2Tn7VbK0cJm5HsZ1yAfD8gPq3oWi6NtE_k"
  },
  "expectedServices": ["license", "config", "release",
    "distribution", "update", "identity", "sync"]
}
Public keys only. Nothing in it is secret, so it is checked in with the app.

How it gets into the project

pkey sdk add swift --dir macos/ --expect djdl-2026@sha256:3f9a0c…e41b Adds the SDK from pkg.plrs.im and writes the file. It pins a key only when it matches the fingerprint Integration shows. Run in DJDL’s repository, so the product comes from .pkey/product. Anywhere else, add --product djdl, as the command Integration copies does.
Download on Integration The same file, with the active and the staged signing keys, for adding the SDK by hand.
Import file… in the Godot dock Writes res://polaris-key.json and adds it to the export filter. No Node needed.

The start call

NodeReactPythonSwiftmacOSKotlinWindowsGodot5 more
import PolarisKey

// Reads polaris-key.json from the app bundle. The version is
// CFBundleShortVersionString, so there is nothing else to pass.
let pk = try await PolarisKeyClient.fromConfig()
await pk.boot()

if await pk.isLicensed() {
  openLibrary()
} else {
  showSignIn()   // or .polarisKeyGate(pk) from PolarisKeyUI
}
boot() checks the license, syncs managed config and registers this Mac, in one call. create(options) stays for apps that build their options by hand.

Never fetched from the network. A bad pin or an unknown service fails at start, with doctor() saying which.

The other five SDKs

Each SDK’s golden start, compiled in that SDK’s CI. Names follow api.json: one spelling per concept, cased for the language.

Node · main.ts
import { PolarisKeyClient } from "@polaris-key/node";

// polaris-key.json beside package.json.
const pk = await PolarisKeyClient.fromConfig();
await pk.boot();

if (!(await pk.isLicensed())) {
  await showSignIn(pk);
}
React · main.tsx
import polarisKey from "../polaris-key.json";
import { PolarisKeyProvider, PolarisKeyGate }
  from "@polaris-key/react";

// The provider runs fromConfig() and boot().
createRoot(root).render(
  <PolarisKeyProvider config={polarisKey}>
    <PolarisKeyGate><App /></PolarisKeyGate>
  </PolarisKeyProvider>,
);
Python · app.py
from polaris_key import PolarisKeyClient

# Python has no app version to read.
pk = PolarisKeyClient.from_config(
    "polaris-key.json", version="4.2.1"
)
pk.boot()

if not pk.is_licensed():
    show_sign_in(pk)
Kotlin · Main.kt (Windows)
// Reads polaris-key.json from the classpath.
// Android: PolarisKeyAndroid.client(context),
// which reads assets/polaris-key.json.
val pk = PolarisKeyClient.fromConfig()
pk.boot()

if (!pk.isLicensed()) showSignIn(pk)
Godot · main.gd
# The PolarisKey autoload reads
# res://polaris-key.json itself.
func _ready() -> void:
  await PolarisKey.boot()
  if not PolarisKey.is_licensed():
    $SignIn.show()

When start fails, doctor() says why

A debug build prints the report once, on the first refusal: which pin, feature or clock is wrong, and the console page that fixes it. pk.doctor() returns the same checks, typed.
