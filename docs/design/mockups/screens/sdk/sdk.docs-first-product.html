Your first product

Create a product, add the SDK to your app, and watch each feature turn Verified: the same steps the console walks you through. The examples use Tidewater Studio, a macOS and Windows app; put in your own product’s slug.

About 15 minutesUpdated Oct 7, 2026Polaris Key 0.9
  1. 1

    Create the product

    In the console, choose New product. It asks three things, then creates everything in one go and opens the product’s Integration page.

    Name and slugTidewater Studio, tidewater. The slug is in every URL and can’t change later.
    What it’s forPick the features you need from Licensing, Managed config, Ship builds, Sign-in, Cloud Sync and Commerce. Tidewater starts with Licensing and Managed config; add the rest later. A feature turns on only after the ones it needs: Cloud Sync needs Managed config and Sign-in, Commerce needs Licensing, and turning Licensing off later turns Commerce off with it.
    PlatformsmacOS and Windows. Integration picks the SDK that fits each one.

    Polaris Key makes the signing key, the package feeds and a test license for you. There is nothing to configure per platform.

    Keep the product in your repository?
    Run pkey init, push, and link the repository on the product’s Settings. The console then reads .pkey/ on every push.
  2. 2

    Add the SDK

    Run the command Integration shows, in your app’s folder. It adds the SDK from pkg.plrs.im, writes polaris-key.json and pins Tidewater’s keys, but only after checking them against the fingerprint the console shows.

    NodeReactPythonSwiftKotlinGodot5 more
    $ pkey sdk add swift --product tidewater \
    --expect <fingerprint from Integration>
    Copy the full command from your product’s Integration page; it has your fingerprint.
    What polaris-key.json holds

    No terminal? Choose Download polaris-key.json on Integration, add it to your app, and add the SDK with your package manager: Install from the package feeds

  3. 3

    Start the SDK

    Every SDK starts the same way. fromConfig() reads polaris-key.json from your app’s own files, and boot() checks the license, syncs managed config and registers the device.

    NodeReactPythonSwiftKotlinGodot5 more
    import PolarisKey

let pk = try await PolarisKeyClient.fromConfig()
await pk.boot()

if await pk.isLicensed() {
  openProject()
} else {
  showSignIn()   // or .polarisKeyGate(pk) from PolarisKeyUI
}

    Want the screens too? Each UI kit’s gate does sign-in, activation and device limits in your product’s look: UI kits

  4. 4

    Use each feature

    Integration shows the code for each feature you turned on, written with your product’s own names: its entitlements, settings and packs. Each feature’s guide has the same code, with a tab for every SDK.

    LicensingGate on a license and read what it entitles. Managed configRead settings, secrets and minted tokens. Ship buildsPublish from CI and update installed copies. Sign-inLet people sign in with their account. Cloud SyncKeep settings the same on every device. CommerceSell tiers and add-ons on storefronts.
  5. 5

    Check it’s Verified

    Run your app. Integration marks a feature Verified on a platform as soon as the SDK gets an answer from it there. From a terminal, pkey doctor reports the same, with what’s left to do:

    zsh — tidewater
    ❯ pkey doctor

  Managed config   ✓ Verified     ○ Not seen yet

If something’s missing

Not seen yet
No SDK has reached Polaris Key from that platform. Run the app there once.
Waiting
The console steps are done. Use the feature once in the app: sign in, or check for updates.
A key doesn’t match
Run pkey sdk add again, or download polaris-key.json again from Integration.
Still stuck
Run a debug build. On the first refusal the SDK prints doctor() once: what is missing and the console page that fixes it.

The code on this page comes from the same source as Integration and is compiled in each SDK’s CI.
