One command table drives the parser, this help, shell completion and the CLI reference in the docs, so none of them can drift. Run in DJDL’s repository, the product and base URL come from the folder, and the words are the console’s: a channel is where builds reach people, a release track is stable, beta or dev.

❯ pkey help sdk add
pkey sdk add · Add an SDK to an app and pin the product's keys

Usage  pkey sdk add <sdk> [--expect <kid>@sha256:<hex>]
                         [--dir <path>] [--product <slug>]
                         [--dry-run] [--json]

Arguments
  <sdk>             node, react, python, swift, kotlin or godot

Options
  --expect <fp>     Required the first time in a folder: the
                    signing key fingerprint Integration shows,
                    as <kid>@sha256:<hex>. pkey pins a key only
                    when it matches; it never trusts a key on
                    first use. Later runs trust keys signed by
                    the pinned key.
  --dir <path>      The app's folder. Default: this folder
  --product <slug>  Default: .pkey/product here (djdl)
  --dry-run         Show what would change and write nothing

What it does, for swift in macos/
  1  Adds PolarisKey from pkg.plrs.im to DJDL.xcodeproj
  2  Writes macos/polaris-key.json for djdl on key.plrs.im
  3  Pins djdl-2026 once it matches --expect, the staged
     djdl-2026b it signed, and the release key
     djdl-rk-2026 from .pkey/release

Examples
  pkey sdk add swift --dir macos/ \
      --expect djdl-2026@sha256:3f9a0c…e41b
  pkey sdk add kotlin --dir windows/ \
      --expect djdl-2026@sha256:3f9a0c…e41b

See also  pkey doctor · key.plrs.im/docs/start/first-product

One command table

  • Each command is declared once: its group, words, usage, flags, environment and what it says. Parsing, help and completion all read it.
  • The docs’ CLI reference is generated from the same table and checked in CI.
  • --product and --base-url default from .pkey/product and PKEY_BASE_URL for every command that takes them.
  • Removed commands are gone from the table, so they are gone from help and completion: no pkey trust, no pkey sdk --lang, no PKEY_ADMIN_COOKIE, and no pkey storefront: delivery commands are channel commands, and “storefront” is kept for selling.
