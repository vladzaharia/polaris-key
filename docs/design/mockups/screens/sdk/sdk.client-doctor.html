doctor() says what’s missing

In a debug build the SDK runs doctor() once, on the first refusal, and prints what is missing with the console page that fixes it. The same checks come back typed, so an app can show them on its own support screen. Shown for Diceroll, run from the Godot editor on a Mac.

The call

NodeReactPythonSwiftKotlinGodot5 more
# Debug builds print the report once, on the first refusal.
# For a support screen, ask for it yourself:
var report := await PolarisKey.doctor()
for check in report.checks:
  if not check.ok:
    support_log.add(check.title, check.fix, check.console_url)
Each check has id, ok, severity (todo or warning, printed “to do” and “warning”), title, detail, fix and a console link. The ids are the same in every SDK.
CheckWhat it compares
Serverkey.plrs.im, or the file’s baseUrl, answers. The checks that compare with it say so when it can’t
polaris-key.jsonFound, valid against its schema, and for this product
VersionThe app version the platform reports is a semver
Signing keyThe pins against the keys key.plrs.im advertises, a staged key included
Release keyA release key is pinned, so updates and packs can be verified
FeaturesWhat the file expects against the features the product has on
StoreThe store check this build can run: StoreKit, Google Play, Steam
ClockThis device’s time against Polaris Key’s
Web originReact and the elements only: the page’s origin is one of the product’s web origins

Release builds never print it, and a debug run with no refusal prints nothing; pk.doctor() still returns every check, all ok. The report holds no license key, device token or secret, so it is safe to paste into a support email.
