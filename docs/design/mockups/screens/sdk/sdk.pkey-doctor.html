✓Verified: an SDK got a 2xx from that feature on that platform, or CI published a release. ●Waiting: the console steps are done; the first call from the app hasn’t come yet. ○Not seen yet: no SDK has reached Polaris Key from that platform. ✗To do: a console step or a key that is missing, with the fix on the next line. !Warning: works today, needs action before a date. The summary: red while anything is to do (exit 1, and the prompt turns red), amber for warnings alone, green when clear (exit 0). With --no-color the words are the same.

How it behaves

  • Reads the same facts as the Integration page, so the two never disagree.
  • --product and --base-url come from .pkey/product and PKEY_BASE_URL; pass them to check another product.
  • Exits 1 while anything is left to do; warnings alone exit 0.
  • Console links are built from the base URL, so a deployment set by PKEY_BASE_URL gets links to its own console (/manage).
  • A staged signing key gets one fix line per app folder, each with that folder’s SDK.
  • --json prints the same checks for CI, with the shared envelope every command uses.
  • Outside a repository it checks only what it can: sign-in, the base URL and polaris-key.json in this folder.
