# UI kits: the design language, kit by kit

How each UI-kit package applies the [design language](UI-KITS.md#design-language-v2-2026-10-08)
(rules DL1–DL18, 2026-10-08). There is one row for every UK package that is not done or dropped,
optional and parked ones included. Each package's brief carries its row in a
`## Design language v2 (2026-10-08)` section; this file is the one place to compare them.

- **Rules** lists the rules that apply, and says why any do not.
- **In this kit** says what the language looks like in that toolkit. Where a platform has no built
  precedent, it says what to evaluate instead of drawing a look nobody has reviewed.
- **Minimum check** names the size rows (§7.1, by row name) and the presets the kit's
  matrix must render. The acceptance for every kit is the same unless its brief says otherwise:
  the matrix rows pass, and a UX review (`pkey-ux-reviewer`) of the built screens gives each a
  quality verdict of good or better.

Section signs (§) refer to UI-KITS.md. Three forms are shared by several rows, so they are stated
once here.

## Terminal form

The language in a terminal (UK-32, UK-43's terminal half, UK-45, UK-46, UK-48 and UK-51 to UK-54),
as the Node and Python terminal kits' review round settled it.

| Rule       | In a terminal                                                                                                                                                                                                                                                                                                                    |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DL1        | Columns and rows decide the layout: 80 columns, degrading to 60, 40 and a 32-column floor. Below 32 the rail and indents drop and lines wrap at the real width. A resize lays the whole flow out again. With room for the text, the QR and 4 columns (about 100), the offline QR sits beside the text.                           |
| DL2        | No overlays: a flow replaces its live region in place and ends in one result block.                                                                                                                                                                                                                                              |
| DL3        | One rail rhythm: blank rail rows are the spacing. A live frame taller than the screen gives way in this order: the key hints onto the spinner line, the blank rows between prose, the code check line, the blank rows around the code, the expiry line, then the header scrolls away. Printed output never compacts; it scrolls. |
| DL4        | One Enter action per prompt. The other keys are hints: the key in strong, a lower-case verb in muted.                                                                                                                                                                                                                            |
| DL5        | The product chip heads every flow (`┌ <Product> · <verb>`). At narrow widths the verb goes first; the name is shortened only when the chip alone does not fit.                                                                                                                                                                   |
| DL6        | A refusal is ▲ with its fix (Enter or a command row), never ✗.                                                                                                                                                                                                                                                                   |
| DL7        | A failure is ✗ with what happened, then the fix line or a command row. Esc and Ctrl+C cancel every flow with one cancelled line (exit 1 or 130).                                                                                                                                                                                 |
| DL8        | Catalog keys only. A suggested command uses the verb the person ran.                                                                                                                                                                                                                                                             |
| DL9        | Focus is the prompt's cursor or selection, and every screen has a key that leaves it.                                                                                                                                                                                                                                            |
| DL10, DL11 | Text reflows at the terminal's own size. Keep-units (a name, an email, a date, "3 of 3", "38 MB", a key with its label) never split, and a code breaks only at its hyphen.                                                                                                                                                       |
| DL12       | One bold: 500 and 600 map to bold, 400 to normal.                                                                                                                                                                                                                                                                                |
| DL13       | ANSI-16 roles, with truecolor only for the product chip and the resolved accent. `native` keeps the terminal's palette. `NO_COLOR` drops colour but keeps bold, reverse video and OSC 8 links.                                                                                                                                   |
| DL14       | No QR for sign-in (SIGN-IN.md D-68); the offline-request QR when it fits. OSC 8 links only for https URLs.                                                                                                                                                                                                                       |
| DL15       | §7.1's terminal rows, plus 24, 28 and 32 columns and resize sequences (80×24 to 40×12, and back to 120×40).                                                                                                                                                                                                                      |
| DL16       | No animation when stdout is not a TTY or `CI` is set. The spinner turns at 80 ms a frame.                                                                                                                                                                                                                                        |
| DL18       | One call mounts the verbs into a host CLI, with `--json` on every verb.                                                                                                                                                                                                                                                          |

DL17 (safe areas) does not apply.

## Desktop chrome

The Windows, GNOME and macOS rows of UI-KITS.md §1.4, used by UK-06, UK-10, UK-12 and UK-21, plus:

- **DL1 at window sizes.** A resizable window runs the same shape rule, and §7.1's phone and tablet
  rows are window sizes.
- **Keyboard is the default input.** The ring shows on keyboard focus from launch, and Tab reaches
  every control.
- **Button order.** Windows: primary first, at equal width. macOS: Cancel directly left of the
  default, in title case. GNOME: the suggested action as a pill, at the end.
- **No QR** (SIGN-IN.md D-67). Links open through the kit's one validating opener.
- **Update and settings are real windows** (§1.4, desktop model).

## Hosted surfaces

UK-23, UK-24 and UK-28 host another kit's views, and UK-29 wraps another kit's scenes. They add no
screen of their own, so the hosted kit's row is theirs. The host must not fix the hosted view's
size (DL1 measures the container), add its own frame or padding (DL3), or cover its safe areas
(DL17). Their check is pixel equality with the hosted kit's baselines.
