# tools

The repository's generators, drift gates and release scripts: everything that writes a committed file or checks one.

## Where it sits

- `pnpm gen` (`gen.ts`) runs the generators declared in `generators.ts`; CI, the pre-commit hook and the green gate all read that registry through `pnpm gen --check`.
- Generators read the workspace packages (`@polaris-key/protocol`, `catalog`, `client-core`, `jws`, `cli`, `zstd-wasm`) and write into `conformance/`, `packages/*` and `sdks/*`.
- The release workflows in `.github/workflows/` call the `.mjs` scripts and `check-feed-download.sh`.
- The tool's own tests (`*.test.ts`) run under `pnpm --filter @polaris-key/tools test`.

## Layout

```
tools/
  generators.ts            the registry: one entry per generator family, with its inputs, outputs and commands
  gen.ts                   the `pnpm gen` driver: runs, checks or lists the registry
  gen-generators-doc.ts    renders the registry as reference/generators.mdx and the AGENTS.md table
  sign-corpus.ts           the corpus driver: signs and writes conformance/corpus/v2 and the Godot mirror
  corpus/                  one module per corpus family, plus shared fixtures
    reference/             independent reference implementations that recompute every verdict
  sync-scenarios.ts        sync-scenarios.json (literal data)
  presentation-matrix.ts   presentation-matrix.json
  portal-matrix.ts         portal-matrix.json
  ui-matrix.ts             ui-matrix.json
  gen-content-corpus.ts    content/cases.json and plan-matrix.json; the only writer of content/blobs
  gen-content-chunks.ts    the reference chunker, bundle packer and chunk applier for the content corpus
  gen-transcripts.mjs      runs the Worker's transcript test, with or without write mode
  gen-sdk-constants.ts     every SDK's generated constants module, from conformance/parity and services.json
  capabilities.ts          each SDK's capability table and its digest, from its parity manifest
  gen-services.ts          every language's service slugs, from services.json
  services.json            the opt-in service table
  gen-channels.ts          the distribution-channel table in @polaris-key/manifest, from channels.json
  channels.json            the one catalogue of channels builds reach customers through
  gen-mirrors.ts           front end over packages/cli/src/mirrors.ts: typed config mirrors for a catalog
  parity-check.ts          the parity gate: every SDK's parity.json against conformance/parity/features.json
  sdk-version.mjs          derives the lockstep SDK version from git and stamps it into every SDK
  feed-closure.mjs         checks every published version pins only versions the feed lists
  feed-drift.mjs           checks every published package shows the lockstep version on its feed
  maven-publication-check.mjs  checks the local Gradle repo holds the POM each maven deliverable needs
  check-feed-download.sh   publish-package.yml's guard that a downloaded artifact is whole
  mockups/                 build, check and screenshot scripts for docs/design/mockups
  fixtures/                recorded input for tests (an npm feed listing)
  *.test.ts, *.d.mts       tests beside each tool, and types for the .mjs scripts
```

Which family writes which files is in the registry and in the generated map under Work on it; this page does not repeat it.

## Rules here

- Generated files carry a GENERATED banner: regenerate, never hand-edit. `pnpm gen --check` is the drift gate, and `generators.test.ts` fails when a banner has no registry entry. A new generator is one entry in `generators.ts`; see [AGENTS.md](../AGENTS.md).
- Never hand-edit generated corpus files: `sign-corpus.ts` is the only writer, and `pnpm gen corpus --check` fails on drift. See [AGENTS.md](../AGENTS.md).
- A wire change bumps the protocol version and regenerates the corpus; `pnpm gen --check` fails until it does. See [AGENTS.md](../AGENTS.md).
- A new error code needs an entry in `conformance/parity/errors.json` first; `gen-sdk-constants.ts` refuses a Worker code it lacks. See [AGENTS.md](../AGENTS.md).
- The service table is one declaration, `services.json`; `pnpm gen services` writes every language from it and `gen-services.test.ts` names what a new row lacks. See [AGENTS.md](../AGENTS.md).
