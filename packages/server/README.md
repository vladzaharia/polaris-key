# @polaris-key/server

Gate a server route with the app's signed licence document, verified offline. The root is a Fetch
core, `createPolarisKey().authenticate(request)`, that runs on Node, Bun, Deno and Workers.
`./express`, `./hono` and `./next` are drop-ins over it, and `./testing` signs documents for your
unit tests. The package is private until the lead releases it.

## Where it sits

The app sends its licence document in `X-PKey-License`. The core decides it in the six steps of
[WIRE-CONTRACT-V4 §14](../../docs/security/WIRE-CONTRACT-V4.md) against the product's pinned keys
and the signed trust manifest, and answers a refusal as `application/problem+json`. It depends on
`@polaris-key/client-core`, `@polaris-key/jws` and `@polaris-key/protocol`, and on no framework:
Express, Hono and Next are optional peers.

```ts
import { polarisKey, requireEntitlement } from "@polaris-key/server/express";

app.use(polarisKey({ config: polarisConfig }));
app.get("/api/export", requireEntitlement("export.pdf"), handler);
```

- The verdict, `Problem` and copy come from client-core's `backend` module and the generated
  `src/copy.generated.ts`.
- The trust manifest refreshes every 900 s on a request, and an unknown `kid` fetches at most once a
  minute. A failed fetch keeps the last verified set and the pinned keys always verify.
- Verified documents sit in an LRU of 1 000, keyed by the header's SHA-256, until their freshness
  deadline.
- `verifyLicenseDocument` lives here; it moved from `@polaris-key/node/server` in 0.9 with no alias.

## Layout

```
src/
  index.ts         the Fetch core's exports
  core.ts          createPolarisKey: authenticate, require, refuse, the cache
  trust.ts         the trust manifest fetch and its schedule
  context.ts       PolarisLicense, PolarisAuth, Problem (no holder in toJSON)
  express.ts       polarisKey, requireLicense, requireEntitlement, requireSignIn
  hono.ts          the same four, as middleware
  next.ts          createNextPolarisKey for App Router route handlers
  testing.ts       createTestKit: a throwaway key, pins and a clock
  copy.generated.ts the refusal copy in eight locales (pnpm gen constants)
test/
  matrix.test.ts   every verdict and problem row of backend-matrix.json
  adapters.test.ts the §5.2 verdicts through Express, Hono and Next
  examples.test.ts boots examples/server-* against a test kit
```

## Rules here

Rules live in [AGENTS.md](../../AGENTS.md).

- Terminology comes from the concepts page.
- Generated files carry a GENERATED banner.
- The corpus is read in place and never edited.
- No secret reaches a log line or a `toJSON`: the header, the JWS, the holder's name and email.
- The package imports no framework at runtime beyond a type.
