## Before you start

1. The **Platform admin** role in the console. Creating a product needs it.
2. Node 22.13 or later. The `pkey` CLI runs on it, whatever language your app uses.
3. A project for your SDK, in its own directory: `npm init -y` starts a Node one and `swift package init --type executable` a Swift one.

## 1. Create the product

**Console** Open the console at `https://key.plrs.im/manage/` (on a platform at its own address, `/manage/` on that address) and sign in. Open **Products → New product** and choose **From scratch**. Enter the name `Tidewater Studio`. The form fills in the slug `tidewater-studio`: replace it with `tidewater`, then select **Continue**. Keep **Licensing** and **Ship builds** on and select **Create Tidewater Studio**. You land on **Integration**. The slug is permanent and appears in keys and URLs, so use your own for a real product.

You should see **Tidewater Studio is ready** on the product's **Integration**, with its signing key.

Create also made the Default profile and a Free tier, so you can issue a license without more setup.

## 2. Check that License is on

**Console** Open **Core → Services**. A product starts with **License** and **Config** on. If the **License** switch is off, switch it on. Each switch saves on its own.

You should see the **License** switch on.

## 3. Install the CLI and an SDK

**CLI** The first block installs the CLI. The blocks after it each install one SDK: use the one for your SDK and skip the rest. Each block routes the `@polaris-key` scope, or its ecosystem's equivalent, to `pkg.plrs.im` before it installs, because the packages exist nowhere else.

<InstallSteps sdk="cli" />

In a Node project, put the routing line in the project's `.npmrc`, install the CLI there and run it through your package manager: `npx pkey` with npm, `pnpm exec pkey`, `yarn pkey` or `bunx pkey`. For any other app, put the routing line in `~/.npmrc`, add `--global` to the install and run `pkey` directly. Never run `npx pkey` before the CLI is installed: that name resolves from npmjs.

For Python, the pip block installs the package alone, so install its dependencies from your usual index first: `pip install "cryptography>=41" "httpx>=0.24" "zstandard>=0.22; python_version < '3.14'"`. The uv and Poetry blocks resolve them for you.

For Swift, save the routing block as `.swiftpm/configuration/registries.json` in the package's root, creating the folders. In `Package.swift`, add the package line to the package's `dependencies`, give the package `platforms: [.macOS(.v15)]`, and add `.product(name: "PolarisKey", package: "polaris-key.PolarisKey")` to your target's dependencies. SwiftPM also fetches the SDK's one dependency, `Sparkle`, from GitHub.

Other package managers and age gates are on [Install the SDKs and the CLI](/docs/build/install/). The product's **Integration** page shows the same lines for the SDK you pick.

You should see the commands listed by `pkey help`. In a Node project, run it as `npx pkey help` or the form for your package manager:

```sh title="Terminal"
pkey help
```

## 4. Generate the config file

**CLI** Run `pkey sdk` in your app's directory. It reads the product's discovery document and writes a config file with the slug, the base URL and the trust pins.

```sh title="Terminal"
pkey sdk --lang <lang> --product <slug> --write
```

Replace `<slug>` with the slug from step 1. For a platform that isn't at `key.plrs.im`, add `--base-url <console origin>`: the console's address without `/manage/`. The table gives `<lang>` for each SDK and the file it writes:

| SDK    | `<lang>` | File written          |
| ------ | -------- | --------------------- |
| Node   | `node`   | `polaris.config.ts`   |
| React  | `react`  | `polaris.config.ts`   |
| Python | `python` | `polaris_config.py`   |
| Swift  | `swift`  | `PolarisConfig.swift` |
| Kotlin | `kotlin` | `PolarisConfig.kt`    |
| Godot  | `godot`  | `polaris_key.tres`    |

The file lands in the current directory. For Swift, run the command in your target's folder (`Sources/<Target>`), or add `--out Sources/<Target>/PolarisConfig.swift`, so the target compiles it. For Godot, run it in the project; it updates `polaris_key.tres` beside `project.godot`.

You should see the file written and each pin's key id and SHA-256 fingerprint:

```text title="Output"
Product tidewater at https://key.plrs.im
Services: license, config
Trust pins (compare each fingerprint with the console before you ship):
  tidewater-2026  sha256:9f2c…
Release keys: none
Wrote /path/to/polaris.config.ts
```

The pins are the product's public signing keys. Compare each key in the file with **Public key** under **Core → Keys & secrets**. A new product has one signing key, so the command also warns on stderr to stage a second before you ship.

## 5. Gate the app

**App** Create the client from the generated config, then check the license. Your SDK's quickstart has the code for the drop-in screens and for your own UI:

- [Node](/docs/build/quickstart/node/)
- [React](/docs/build/quickstart/react/)
- [Python](/docs/build/quickstart/python/)
- [Swift](/docs/build/quickstart/swift/)
- [Kotlin](/docs/build/quickstart/kotlin/)
- [Godot](/docs/build/quickstart/godot/)

[Choose your integration](/docs/start/choose-your-integration/) compares the two lanes.

You should see the app stay locked: the client's license status is `needs-activation`, and a drop-in kit shows its activation prompt.

## 6. Issue a test license and activate it

**Console** Open **License → Licenses** and select **Create license**. Enter any name and an email such as `test@example.com`, select **Continue to terms**, then select **Create license**. Copy the license key, or tick **I've stored it**: the console shows it once.

**App** Enter the key where the app asks for it.

You should see the app unlock. The device appears under **Core → Devices**.

## What you built

A product with a signing key and License on. A config file that pins that key. An app that activates a license, and the device record it created.

## If it isn't working

- [Troubleshoot your integration](/docs/build/troubleshooting/): the code in the app's error, and web apps and CORS.
- `pkey: command not found`: the CLI is installed in a project, so run it through your package manager (step 3).
- `pkey sdk` reports a 404: check the slug, and add `--base-url <console origin>` if your platform isn't at `key.plrs.im`.
- [pkey CLI](/docs/reference/cli/): every flag of `pkey sdk`.
- [Install the SDKs and the CLI](/docs/build/install/): feeds and package managers.
