## Before you start

1. The **Platform admin** role in the console. Creating a product needs it.
2. Node 22.13 or later. The `pkey` CLI runs on it, whatever language your app uses.
3. An app project for your SDK. An empty directory works.

## 1. Create the product

**Console** Open **Products → New product**. Keep **Start from** on **Nothing**. Enter the name `Tidewater Studio` and the slug `tidewater`, then select **Create Tidewater Studio**. The slug is permanent and appears in keys and URLs, so use your own for a real product.

You should see **Tidewater Studio is ready** on the product's **Overview**, with its signing key.

## 2. Check that License is on

**Console** Open **Core → Services**. A product starts with **License** and **Config** on. If the **License** switch is off, switch it on. Each switch saves on its own.

You should see the **License** switch on.

## 3. Install the CLI and an SDK

**CLI** The first block installs the CLI. The picker then selects one SDK's install. Each block routes the `@polaris-key` scope, or its ecosystem's equivalent, to `pkg.plrs.im` before it installs, because the packages exist nowhere else.

<InstallSteps sdk="cli" />

Outside a Node project, put the routing line in `~/.npmrc` and add `--global` to the install. Run the CLI as `pkey`, or through your package manager (`pnpm exec pkey`) in a Node project. Never run `npx pkey` without installing the CLI first: that name resolves from npmjs.

## 4. Generate the config file

**CLI** Run `pkey sdk` in your app's directory. It reads the product's discovery document and writes a config file with the slug, the base URL and the trust pins.

```sh title="Terminal"
pkey sdk --lang <lang> --product <slug> --write
```

Replace `<slug>` with the slug from step 1. For a console that isn't at `key.plrs.im`, add `--base-url <console origin>`. The table gives `<lang>` for each SDK and the file it writes:

| SDK    | `<lang>` | File written            |
| ------ | -------- | ----------------------- |
| Node   | `node`   | `polaris.config.ts`     |
| React  | `react`  | `polaris.config.ts`     |
| Python | `python` | `polaris_config.py`     |
| Swift  | `swift`  | `PolarisConfig.swift`   |
| Kotlin | `kotlin` | `PolarisConfig.kt`      |
| Godot  | `godot`  | `polaris_key_config.gd` |

You should see the file written and each pin's key id and SHA-256 fingerprint:

```text title="Output"
Product tidewater at https://key.plrs.im
Services: license, config
Trust pins (compare each fingerprint with the console before you ship):
  tidewater-2026  sha256:9f2c…
Release keys: none
Wrote /path/to/polaris.config.ts
```

Compare each key id with the one under **Signing keys** on **Core → Keys & secrets**. A product with one signing key also prints a warning to stage a second before you ship.

## 5. Gate the app

**App** Create the client from the generated config, then check the license. Your SDK's quickstart has the code for the drop-in screens and for your own UI:

- [Node](/docs/build/quickstart/node/)
- [React](/docs/build/quickstart/react/)
- [Python](/docs/build/quickstart/python/)
- [Swift](/docs/build/quickstart/swift/)
- [Kotlin](/docs/build/quickstart/kotlin/)
- [Godot](/docs/build/quickstart/godot/)

**Choose your integration** compares the two lanes.

You should see the app report that it needs activation.

## 6. Issue a test license and activate it

**Console** Open **License → Licenses** and select **Create license**. Enter a name and an email such as `test@example.com`, select **Continue to terms**, then select **Create license**. Copy the license key: the console shows it once.

**App** Enter the key where the app asks for it.

You should see the app unlock. The device appears under **Core → Devices**.

## What you built

A product with a signing key and License on. A config file that pins that key. An app that activates a license, and the device record it created.
