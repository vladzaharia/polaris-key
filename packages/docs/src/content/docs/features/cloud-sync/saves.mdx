A save is a record in a collection declared with `template: "saves"`, plus one file. The SDK writes the file first and the record after it, so a save that fails halfway is never read. A save file is at most 32 MiB, the last 5 versions are kept, and a person has at most 16 slots. Saves sync across the person's devices through [Cloud Sync](/docs/features/cloud-sync/#records-and-saves), and they are end-to-end encrypted unless the product opts out.

There is no implicit `saves` collection: the app declares it in its catalog.

```json title=".pkey/schema"
{
  "schemaVersion": 4,
  "entries": [],
  "cloudSync": { "collections": [{ "name": "saves", "template": "saves" }] }
}
```

A save id is 1 to 128 characters of `[A-Za-z0-9._:-]`. Saves need a signed-in person and the Cloud Sync service. The Worker serves their files only while [files](/docs/features/cloud-sync/files/) are on.

## The calls

<Tabs syncKey="sdk">
  <TabItem label="Node">

`client.cloudSync.saves` has `list()`, `read(id)`, `write(id, bytes, metadata)`, `delete(id)` and `revisions(id)`. `write` resolves at once with a transfer: `transfer.done` settles on `done`, `cancelled`, `failed` or `conflict` (with the `request` to answer), and never rejects. `transfer.pause()`, `resume()` and `cancel()` control it, and `client.cloudSync.transfers()` lists the writes in flight. The SDK journals each transfer, so an interrupted one resumes.

```ts
import type { PolarisKeyClient } from "@polaris-key/node";

export async function saveGame(client: PolarisKeyClient, bytes: Uint8Array) {
  const transfer = await client.cloudSync.saves.write("slot-1", bytes, {
    chapter: 3,
    formatVersion: 2,
  });
  const outcome = await transfer.done;
  if (outcome.state === "failed") {
    // "transfer-failed" with detail "quota_exceeded", or "sync-file-invalid"
    console.log(outcome.error.code, outcome.error.detail);
  }
  if (outcome.state === "conflict") {
    // Keep this device's copy; "remote" keeps the other, "both" needs a free slot.
    await outcome.request.keep("local");
  }
}

export async function loadGame(client: PolarisKeyClient, id: string) {
  const save = await client.cloudSync.saves.read(id);
  if (save.ok) return save.bytes;
  return save.reason; // "not-found" or "newer-format"
}

export function watchTransfers(client: PolarisKeyClient) {
  client.events.on("cloudSync", (event) => {
    if (event.type === "transferProgress") console.log(event.done, event.total);
    if (event.type === "transferDone") console.log(event.id, event.state);
    if (event.type === "transferFailed") console.log(event.id, event.code);
  });
}
```

The app's settings go in the client options: `cloudSync: { saves: { saveFormatVersion: 2 } }`. `maxBytes` and `delta` are there too, and default to 32 MiB and on.

  <TabItem label="React">

`useSaves()` returns `saves` (as `list()` last read them), `list`, `read`, `write`, `delete`, `revisions` and `unsupported`, which says why saves cannot run here, such as on a cookie-only page. `useTransfers()` returns `transfers` (each with `id`, `state` and `progress`), `pause`, `resume` and `cancel`. A hook re-renders on every transfer event. A save's bytes never pass through hook state. `useConflicts()` lists the open conflicts and settles one with `keep(request, choice)`; the [SaveConflict](/docs/build/ui/components/save-conflict/) screen does it for you.

```tsx
import { useSaves, useTransfers } from "@polaris-key/react";

export function SaveButton({ bytes }: { bytes: Uint8Array }) {
  const { saves, list, write } = useSaves();
  const { transfers, cancel } = useTransfers();
  return (
    <div>
      <button
        onClick={async () => {
          const transfer = await write("slot-1", bytes, { chapter: 3 });
          const outcome = await transfer.done;
          if (outcome.state === "failed") console.log(outcome.error.code);
        }}
      >
        Save
      </button>
      <button onClick={() => list()}>{saves?.length ?? 0} saves</button>
      {transfers.map((t) => (
        <button key={t.id} onClick={() => cancel(t.id)}>
          {t.id} {t.state} {t.progress.done} of {t.progress.total}
        </button>
      ))}
    </div>
  );
}
```

`client.cloud_sync.saves` is synchronous: `list()`, `read(id)`, `write(id, data, metadata)`, `delete(id)`, `revisions(id)` and `transfers()`. Calls return plain dicts with the same members as Node. `write` returns a transfer at once; `transfer.wait()` blocks until it settles, and `pause()`, `resume()` and `cancel()` control it. `client.events.on("cloudSync", …)` receives `transferProgress`, `transferDone` and `transferFailed`.

```python
from polaris_key import PolarisKeyClient


def save_game(client: PolarisKeyClient, data: bytes) -> None:
    transfer = client.cloud_sync.saves.write("slot-1", data, {"chapter": 3, "formatVersion": 2})
    outcome = transfer.wait()
    if outcome["state"] == "failed":
        # code "transfer-failed" with detail "quota_exceeded", or "sync-file-invalid"
        print(outcome["error"].code, outcome["error"].detail)
    if outcome["state"] == "conflict":
        # Keep this device's copy; "remote" keeps the other, "both" needs a free slot.
        outcome["request"].keep("local")


def load_game(client: PolarisKeyClient, id: str) -> object:
    save = client.cloud_sync.saves.read(id)
    if save["ok"]:
        return save["bytes"]
    return save["reason"]  # "not-found" or "newer-format"
```

The app's settings go in the client options: `cloud_sync={"saves": {"save_format_version": 2}}`. `max_bytes` and `delta` are there too, and default to 32 MiB and on.

  <TabItem label="Swift">

`client.cloudSync.saves` has `list()`, `read(_:options:)`, `write(_:bytes:metadata:options:)`, `delete(_:baseVersion:)` and `revisions(_:)`, all `async throws`. `write` returns a `SaveTransfer` at once: `await transfer.outcome()` settles on a `SaveOutcome` (`done`, `cancelled`, `failed` or `conflict`, which carries the request to answer) and never throws. `pause()`, `resume()` and `cancel()` control it, `state` and `progress` read it, and `client.cloudSync.transfers()` lists the writes in flight. The SDK journals each transfer, so an interrupted one resumes.

Metadata is a `JSONValue`, or any `Codable` of your own: `write(_:bytes:encoding:options:)` takes an `Encodable`, and `decodeMetadata(_:)` on a `SaveSummary` or `SaveContent` reads it back. A struct ignores the `savedAt` and `deviceLabel` members the SDK adds unless it declares them.

```swift
import Foundation
import PolarisKey

struct SaveMeta: Codable {
    var chapter: Int
    var formatVersion: Int
}

func saveGame(_ client: PolarisKeyClient, bytes: Data) async throws {
    let saves = client.cloudSync.saves
    let transfer = try await saves.write(
        "slot-1", bytes: bytes, encoding: SaveMeta(chapter: 3, formatVersion: 2))
    switch await transfer.outcome() {
    case .done(let id, let version, _, _):
        print("saved", id, version)
    case .failed(let error):
        // .transferFailed with detail "quota_exceeded", or .fileInvalid
        print(error.code.rawValue, error.detail ?? "")
    case .conflict(let request):
        // Keep this device's copy; .remote keeps the other, .both needs a free slot.
        _ = await request.keep(.local)
    case .cancelled:
        break
    }
}

func loadGame(_ client: PolarisKeyClient, id: String) async throws -> Data? {
    switch try await client.cloudSync.saves.read(id) {
    case .ok(let save):
        let meta = try save.decodeMetadata(SaveMeta.self)
        print("chapter", meta.chapter)
        return save.bytes
    case .notFound:
        return nil
    case .newerFormat(let formatVersion, let supported):
        print("save is format", formatVersion, "this build reads", supported)
        return nil
    }
}

func watchTransfers(_ client: PolarisKeyClient) async {
    for await event in client.events {
        guard case .cloudSync(let sync) = event else { continue }
        switch sync {
        case .transferProgress(let id, let done, let total): print(id, done, total)
        case .transferDone(let id, let state): print(id, state)
        case .transferFailed(let id, let code): print(id, code)
        default: break
        }
    }
}
```

The app's settings go in the client options: `PolarisKeyClientOptions(cloudSync: CloudSyncOptions(saves: SavesOptions(saveFormatVersion: 2)))`. `maxBytes` and `delta` are on `SavesOptions` too, and default to 32 MiB and on.

  <TabItem label="Kotlin">

`client.cloudSync.saves` has `list()`, `read(id)`, `write(id, bytes, metadata)`, `writeAs(id, bytes, metadata)`, `delete(id)` and `revisions(id)`, all `suspend`. There are no Java future forms for saves yet. `write` returns a `SaveTransfer` at once: `transfer.await()` settles on a `SaveResult` (`Done`, `Cancelled`, `Failed` or `Conflict`, which carries the request to answer) and never throws. `pause()`, `resume()` and `cancel()` control it, `state`, `done` and `total` read it, and `client.cloudSync.transfers()` lists the writes in flight. The SDK journals each transfer, so an interrupted one resumes.

Metadata is a `JsonObject`, or a `@Serializable` type of your own: `writeAs` encodes one and `metadataAs<T>()` on a `SaveRead.Ok` decodes it. The SDK's `savedAt` and `deviceLabel` members are in the object, so decode with `ignoreUnknownKeys` or declare them.

```kotlin
import im.plrs.key.core.sync.MergeKeep
import im.plrs.key.sdk.PolarisEvent
import im.plrs.key.sdk.PolarisKeyClient
import im.plrs.key.sdk.SaveRead
import im.plrs.key.sdk.SaveResult
import kotlinx.serialization.json.buildJsonObject
import kotlinx.serialization.json.put

suspend fun saveGame(client: PolarisKeyClient, bytes: ByteArray) {
    val saves = client.cloudSync.saves
    val transfer = saves.write(
        "slot-1",
        bytes,
        buildJsonObject {
            put("chapter", 3)
            put("formatVersion", 2)
        },
    )
    when (val result = transfer.await()) {
        is SaveResult.Done -> println("saved ${result.id} ${result.version}")
        // "transfer-failed" with detail "quota_exceeded", or "sync-file-invalid"
        is SaveResult.Failed -> println("${result.error.code} ${result.error.detail}")
        // Keep this device's copy; Remote keeps the other, Both needs a free slot.
        is SaveResult.Conflict -> result.request.keep(MergeKeep.Local)
        SaveResult.Cancelled -> Unit
    }
}

suspend fun loadGame(client: PolarisKeyClient, id: String): ByteArray? =
    when (val save = client.cloudSync.saves.read(id)) {
        is SaveRead.Ok -> save.bytes
        SaveRead.NotFound -> null
        is SaveRead.NewerFormat -> null
    }

suspend fun watchTransfers(client: PolarisKeyClient) {
    client.events.collect { event ->
        if (event !is PolarisEvent.CloudSync) return@collect
        println(event.event)
    }
}
```

A product whose catalog declares no `saves` collection gets the typed product refusal on every call. The newest format your app reads goes in the client options: `cloudSync.saveFormatVersion = 2` on `CloudSyncHostOptions`. `maxBytes` and `delta` come from the collection's declaration.

`PolarisKey.cloud_sync.saves` is a `PKeySaves`. `list()`, `read(id, opts)`, `delete(id, base_version)` and `revisions(id)` are coroutines that answer a `PKeyResult`; the data is in `detail`. `write(id, bytes, metadata, opts)` returns a `PKeyTransfer` at once: `await transfer.wait()` (or the `finished` signal) settles on an outcome Dictionary with a `state` of `done`, `cancelled`, `failed` or `conflict` (with the `request` to answer), and is never an error value. `pause()`, `resume()` and `cancel()` control it, and `PolarisKey.cloud_sync.transfers()` lists the writes in flight. The SDK journals each transfer, so an interrupted one resumes.

Metadata is a Dictionary. `bytes` is a `PackedByteArray`, held whole in memory. A failed call has `code` `sync-file-invalid`, `sync-locked`, `invalid-argument` (a bad id or metadata) or `sync-failed`, with the saves code in `detail.reason`. A write's outcome carries `error.code` as in [Errors](#errors).

```gdscript
extends Node


func save_game(bytes: PackedByteArray) -> void:
	var saves: PKeySaves = PolarisKey.cloud_sync.saves
	var transfer: PKeyTransfer = saves.write("slot-1", bytes, {"chapter": 3, "formatVersion": 2})
	var outcome: Dictionary = await transfer.wait()
	match outcome["state"]:
		"failed":
			# "transfer-failed" with detail "quota_exceeded", or "sync-file-invalid"
			print(outcome["error"]["code"])
		"conflict":
			# Keep this device's copy; "remote" keeps the other, "both" needs a free slot.
			var request: PKeyMergeRequest = outcome["request"]
			await request.keep("local")


func load_game(id: String) -> PackedByteArray:
	var saves: PKeySaves = PolarisKey.cloud_sync.saves
	var result: PKeyResult = await saves.read(id)
	if result.ok:
		return result.detail["bytes"]
	print(result.code, " ", result.detail)  # "not-found" or "newer-format" is detail.reason
	return PackedByteArray()


func watch_transfers() -> void:
	PolarisKey.event.connect(_on_event)


func _on_event(kind: String, data: Dictionary) -> void:
	if kind != "cloudSync":
		return
	match data.get("type"):
		"transferProgress":
			print(data["id"], " ", data["done"], " of ", data["total"])
		"transferDone":
			print(data["id"], " ", data["state"])
		"transferFailed":
			print(data["id"], " ", data["code"])
```

The app's settings are `PKeyOptions` fields: `cloud_sync_save_format_version = 2`, `cloud_sync_saves_max_bytes` and `cloud_sync_saves_delta`, which default to 32 MiB and on.

On iOS and Android saves run with the Polaris Key native plugin. Without it every call answers unsupported with reason `dependency`; `PolarisKey.supports(PKeyConstants.Feature.SYNC_SAVES)` says which. Desktop needs nothing extra.

## Metadata

The metadata you pass is a small JSON object kept in the record. In end-to-end mode it is sealed with the record. The SDK adds two members to every save, so the conflict screen can describe each copy without your help:

| Member        | Value                                                                       |
| ------------- | --------------------------------------------------------------------------- |
| `savedAt`     | When the save was written, in milliseconds                                  |
| `deviceLabel` | The device's display name, never a hardware value. Absent while it has none |

A `savedAt` or `deviceLabel` of your own is overwritten.

`formatVersion` is yours: an integer you raise when the save layout changes. Give the SDK the highest version your app reads (`saveFormatVersion`). A save above it is not opened: `list` marks it `newerFormat: true`, and `read` answers `ok` false with reason `newer-format`, the save's `formatVersion` and the `supported` one. Without `saveFormatVersion` the check is off.

## Conflicts

Two devices that save from the same version conflict. The write is not sent: `transfer.done` settles on `conflict` with a `request`, and the SDK pulls the server's copy first so the other version has its details. A [MergeRequest](/docs/features/cloud-sync/#conflicts) is open for the slot until it is answered, in `cloudSync.conflicts()` and to `onConflict`. Show both versions and let the person choose, which the [SaveConflict](/docs/build/ui/components/save-conflict/) screen does, then call `request.keep`. The SDK holds this device's copy, so the app hands in no bytes.

| Keep     | Result                                                                                        |
| -------- | --------------------------------------------------------------------------------------------- |
| `local`  | This device's save is written over the server's version                                       |
| `remote` | Nothing is written. The SDK pulls the server copy, so the next `read` returns it              |
| `both`   | This device's save is written as a new save in a free slot. Without one it fails `slots-full` |

`request.choices` offers `both` only while a slot is free and the other version exists. A save deleted on another device conflicts too: there is then no other version (`remote` is nil or null), and keeping this device's copy creates the save again.

While a request is open, a write with no base only replaces its local copy and settles `conflict` again without uploading. A write with a base supersedes the request, and `delete()` defaults to the request's base, so it conflicts and the other copy survives. A write with no base is based on the version this device last listed, read or wrote for that slot in this session; a slot not seen this session is create-only. A version learned by a pull is never a base, so another device's newer save is a conflict and not an overwrite; once the app calls `list()`, the versions it lists (the cache a pull refreshed included) are the ones it has seen. Save requests live in memory: a relaunch drops them, and the app's next write raises the conflict again.

## Errors

A failed write or read carries one of these codes. A call that throws carries the code as `code` (`SavesError.code`, `SavesException.code`); a write reports it in the outcome as `error`. Swift spells them `fileInvalid`, `transferFailed`, `slotsFull`, `tooLarge`, `notFound`, `invalidSave` and `rejected`; Kotlin has the same words as constants on `SavesException`. A read of a missing save answers `notFound` instead of throwing, in every SDK.

| Code                | Meaning                                                                                                                |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `sync-file-invalid` | The downloaded file failed a check: a segment tag, the manifest, a chunk, the hash or the binding. Nothing is returned |
| `transfer-failed`   | The transfer ended. `detail` has the Worker's code, such as `quota_exceeded` or `entitlement_required`                 |
| `slots-full`        | `both` with all 16 slots used                                                                                          |
| `too-large`         | The file is over the collection's `maxBytes`                                                                           |
| `not-found`         | No such save                                                                                                           |
| `invalid-save`      | The id or the metadata is not acceptable                                                                               |
| `rejected`          | The Worker refused the record write; `detail` has its code                                                             |

`quota_exceeded` means the file does not fit the person's [quota](/docs/features/cloud-sync/#the-quota); free space or raise the tier. `entitlement_required` means the collection's `requires` flag, or file storage, is not granted. Both are Worker answers listed under [Cloud Sync files](/docs/features/cloud-sync/files/#errors). A canceled transfer is the state `cancelled`, not a failure.

## Save screens

The kits draw the conflict and the transfer strip for you. The [SaveConflict](/docs/build/ui/components/save-conflict/) page has the screen in each kit. Each binds to the saves request, so none asks the app for the save's bytes.

- **SwiftUI** has `SaveConflictView` over `SaveConflictModel(request:)`, and the Cloud Sync row shows a running, waiting or failed transfer.
- **Compose** has `PolarisSaveConflict` over `PolarisSaveConflictState.of(request, …)`, and `PolarisCloudSyncTransfer` for the strip.
- **Godot** wires itself. `PKeySaveConflict` and the Cloud Sync strip follow `PolarisKey.cloud_sync.saves` through `PKeySaveScreensHost`, and `saves.conflicts()` lists what is unsettled.

## What the SDK keeps

A transfer journal and a chunk cache sit on the device, per person, and are removed at sign-out. See [From an SDK](/docs/features/cloud-sync/files/#from-an-sdk).
