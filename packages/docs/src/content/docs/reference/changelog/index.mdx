Changes to the SDKs, the CLI, the manifest and the API, newest version first. The tables of what each removal is replaced by are in [Upgrade to 0.9](/docs/build/upgrade-to-0-9/).

## 0.10.0

### Cloud Sync settings in React

Added · 2026-10-28 · sync · react

`useSetting(key)` returns the value and its `sync` state, and `useCloudSync()` returns the Cloud Sync status, a `flush()` and the sign-in offer. `config.set` syncs through the browser host while a person is signed in. Cloud Sync is not available over the desktop bridge yet.

### Sign-in is one session call

Breaking · 2026-10-27 · identity · node · react · python

**Action required:** replace the old sign-in calls. They are removed with no aliases. Each row is on [Upgrade to 0.9](/docs/build/upgrade-to-0-9/).

`identity.signIn.start()` (Python: `sign_in.start()`) starts a `device-code` or `redirect` sign-in and answers a session with `wait`, `reopen`, `cancel` and `complete(callbackUrl)`. `identity.choice` and `useLicenseChoice` run the license choice. `subject`, `signOut`, `attach` and `openAccount` are the account calls.

A key activation can answer `key-entry-limit` (`manageUrl`, `keyEntries`) or `license-owned` (`signInUrl`). Neither wipes the device's token.

## 0.9.x

### Exit code 4 for a refusal

Added · 2026-10-22

**Action required:** only if a script wraps [`pkey whoami`](/docs/reference/cli/#pkey-whoami) or [`pkey logout`](/docs/reference/cli/#pkey-logout), which are new, or `pkey login`.

These commands exit 4 and print ▲ rather than ✗ when they refuse: not signed in, a sign-in that has ended, no credential store, or a token the server rejects. A network or server failure exits 1, as for every other command. `--json` prints one result line with `ok`, `exit` and `error` either way.

Exit codes: 0 success; 1 failure (an invalid manifest, a network or server error); 2 usage; 4 refused.

## 0.9.18

### Publish from CI sets itself up

Added · 2026-10-26 · release · distribution

With the GitHub App's optional write permissions, **Publish from CI** creates the `release` environment (limited to `v*` tags) and the `v*` tag ruleset, and opens one `pkey/setup` pull request with the release workflow. Polaris Key never merges it. `pkey ci init` is the fallback without the permissions. The new `distribution:pr` scope lets a publish job open Homebrew and Scoop pull requests with a one-hour GitHub token for the declared tap or bucket, so `PKEY_PR_TOKEN` is optional there. Accept the new permissions on each installation. See [Publishing from CI](/docs/features/ship-builds/ci/).

### Swift has one gate

Breaking · 2026-10-24 · swift

`.polarisKey(client)` now draws the same gate as `.polarisKeyGate(client)` and still puts the model in the environment and syncs when the scene becomes active. `PolarisTheme` maps `branding` and `accent` onto the kit theme; its other fields are ignored, so set `.polarisKeyTheme(PolarisKeyTheme(...))`.

### transports.packs: auto

Added · 2026-10-24 · distribution · release

`transports.packs: auto` in `.pkey/distribution` sends each pack through Apple Background Assets on `app-store` and `testflight`, a Steam depot on a `steam` channel whose new `depots` map names the pack, and the CDN elsewhere. It never picks Play Asset Delivery. After a pack publish, the Action's `channels: auto` runs `pkey channel sync --deliverable <pack>`, which packages and uploads the pack and skips a step that lacks a runner or secret. SteamCMD needs its login installed first. See [Ship a pack through an app store](/docs/features/ship-builds/packs/transports/).

### pkey feeds fdroid moved

Removed · 2026-10-24 · distribution

**Action required:** change the command in your CI. `pkey feeds fdroid` exits 2 and runs nothing. The flags are the same.

### pkey channel add and sync

Added · 2026-10-24 · distribution

`pkey channel add <id>` appends a channel to `.pkey/distribution`. `pkey channel sync` runs the steps your declared channels have. The publish Action runs `sync` after an app release unless you set `channels: none`.

### Publish Action takes eight inputs

Breaking · 2026-10-24 · release · distribution

**Action required:** move every removed input into `args`. The Action now takes `command`, `args`, `release-key`, `content-key`, `base-url`, `working-directory`, `dry-run` and `channels`; any other `with:` key fails the step and names the flag to use. The product comes from `.pkey/product`.

```yaml
with:
  args: --tag ${{ github.ref_name }} --channel beta --dir dist
  release-key: ${{ secrets.PKEY_RELEASE_KEY }}
```

After a successful app publish, `channels: auto` (the default) runs `pkey channel sync`. Set `channels: none` to skip it.

## 0.9.0

### The license-override migration is gone

Removed · 2026-10-22 · license · config

**Action required:** none for a manifest. Stop calling the removed routes and stop running the script.

A license's own config and secret overrides stay: they are layer 4 of the merge, and the license overrides route accepts config, secret and flag keys on every license, floating or owned.

Provisioned secrets now live on the owner's account row when the signing identity is linked to the license's owner. The tables `override_migration` and `override_migration_report` are neither read nor written; a later release drops them.

### The declared registration policy is removed

Removed · 2026-10-11 · license · identity

**Action required:** remove `devices.registration` from every `.pkey/product.{json,yaml,yml}` manifest, then run [`pkey validate`](/docs/reference/cli/#pkey-validate) before you resync or ship. Remove `registration` from every services admin API request in the same change.

Do not replace the field with another `devices` value: 0.9 removes it rather than accepting an alias. A manifest that still declares it reports `invalid_registration_policy`.

The settings reference no longer lists `core.registration`, the registry entry for the same field.
