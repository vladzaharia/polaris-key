Every `pkey` command and flag. Run `pkey help` for the same table in your terminal, and `pkey help <command>` for one command.

## Options

| Option | Meaning |
| --- | --- |
| `--product slug` | The product to act on; default from .pkey/product |
| `--base-url url` | The Polaris Key origin; default $PKEY_BASE_URL, else key.plrs.im |
| `--dry-run` | Check and print; upload and write nothing |
| `--json` | One JSON object on stdout, where a command has it |
| `--no-color` | Plain text (also NO_COLOR=1, or a pipe) |
| `--ascii` | ASCII symbols only |
| `-h, --help` | Help for pkey, or for one command |
| `-V, --version` | Print pkey's version (first word only) |

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | Failure: an invalid manifest, a request the server rejected, a server or network error. The message says what to do next. |
| `2` | Usage: an unknown command or subcommand, or a missing or misused flag. The message shows the command's usage. |
| `4` | Refused, by pkey login, whoami and logout: not signed in, no credential store, or a token the server won't accept. The message names the fix. |

Errors go to stderr and `--json` results to stdout, so a pipe or a CI log keeps them apart. No command asks a question: with no terminal, or with `CI=true`, `pkey` never waits for input. A stack trace is never printed; set `PKEY_DEBUG=1` to add one to an unexpected error.

## Account

### `pkey login`

Sign in to the console from this terminal.

```text
pkey login [--base-url url] [--no-browser] [--json]
```

Shows a code, opens the console's approval page in your browser (not over SSH, without a display or with --no-browser: it prints the link instead) and waits. Check that the code in your browser matches the one here before you approve: it is how you know the request is yours. On approval a personal token (admin, 7 days) goes to your operating system's credential store, bound to the origin that issued it. The token is never printed. Keys: Enter opens the page again, c copies the code (not over SSH), Esc cancels.

A second pkey login ends the token it replaces once the new one is saved; if you cancel, are denied, run out of time or lose the network, the old sign-in keeps working. It refuses (exit 4) in CI, where PKEY_ADMIN_TOKEN is the credential; without a credential store; and when you already have the most personal tokens allowed (revoke one at Personal tokens, then run it again). A code canceled in the browser exits 4; an expired code, an unreachable console or a credential store that won't save exits 1. Esc and Ctrl+D cancel and exit 1; Ctrl+C exits 130. A base URL that is not https is exit 2 (http works only on localhost).

--json prints one line when the code is ready, \{"v":1, "command":"login", "event":"started", "host", "code", "url", "expiresIn", "replaces"\}, then one result line, \{"v":1, "command":"login", "event":"result", "ok", "exit"\} with name, email, roles, token (no secret), storedIn and replaced on success, or error and message. error is denied, expired, token_limit, cancelled, interrupted, refused, network, server-error, store-failed, usage or internal. It never prompts or opens a browser.

`--json`: one JSON line on stdout.

### `pkey whoami`

Show who pkey is signed in as.

```text
pkey whoami [--base-url url] [--json]
```

Prints the person, their roles and when the sign-in ends. The token is never printed. It reads the sign-in stored for the origin (--base-url), or PKEY_ADMIN_TOKEN when that is set to a personal token (pkeyp_).

--json prints one line, the result line: \{"v":1, "command":"whoami", "event":"result", "ok", "exit", "host", "name", "email", "roles", "token"\}, with role ids. A refusal is \{"ok":false, "exit":4, "error", "message"\}: not-signed-in, sign-in-ended, sign-in-refused, no-credential-store, keychain-refused, admin-api-token, env-token-refused or redirect. A failure is exit 1: network, server-error or not-a-console. A base URL that is not https is exit 2, error usage.

| Variable | Meaning |
| --- | --- |
| `PKEY_ADMIN_TOKEN` | A personal token (pkeyp_), used instead of the stored sign-in. |

`--json`: one JSON line on stdout.

### `pkey logout`

Revoke the stored sign-in and remove it.

```text
pkey logout [--base-url url] [--json]
```

Revokes the stored token on the server, then removes it from the credential store. The stored sign-in is per operating-system user and origin (--base-url). If the server can't be reached, or won't revoke the token, the stored copy is still removed, and pkey says the token works until its end date and where to revoke it. That exits 1. It refuses (exit 4) while PKEY_ADMIN_TOKEN is set: pkey only ends a sign-in it stored.

--json prints one line, the result line: \{"v":1, "command":"logout", "event":"result", "ok", "exit", "host", "revoked", "cleared"\}. When the token still works it adds error (network, redirect, revoke-refused or server-error), message, tokenEndsAt and revokeUrl.

`--json`: one JSON line on stdout.

## Manifest

### `pkey init`

Scaffold .pkey/ in this directory.

```text
pkey init [--product slug] [--name name] [--modules slugs] [--release-owner owner] [--release-repo repo] [--starter-tier free|none] [--force]
```

Writes product.yaml and schema.yaml, and release.yaml when Release is on. It stops when product.yaml or schema.yaml exists, unless you pass --force, which overwrites them. On a terminal it asks what the product is for and whether to start with a Free tier; --modules and --starter-tier answer instead.

--modules takes service slugs (license, config, release, distribution, update, identity, sync, commerce, connect); the default is license,config. --starter-tier none leaves out the Free tier (default free, with License). The old names licensing, releases, oidc and edgeMint still work. --product (or --slug) defaults to the directory name, --name to that name in title case.

No `--json`: the answer is text.

### `pkey validate`

Check .pkey/ with the rules the platform applies.

```text
pkey validate [path] [--fix] [--json]
```

Checks .pkey/ with the rules the platform applies. Prints the verdict, the features it turns on and the secrets it needs, then each warning and error with the file and field it points at. Exits 1 when it is invalid. path is relative to here; the default is here.

--fix moves a field written in an old spelling to its new place when that place is empty. It keeps your comments, never overwrites a value, and prints each move.

--json prints one line instead; its shape is at /docs/reference/cli/#validate.

--json prints one JSON line on stdout, the terminal kits' result line, its fields beside the envelope's: \{"v":1,"command":"validate","event":"result","ok","exit","valid","modules","requiredSecrets","warnings","errors"\}, each warning and error as \{"code","message","at","file"\}. With --fix, "fixed" lists the moves. When no manifest can be read it is \{"v":1,"command":"validate","event":"result","ok":false,"exit":1,"error":"no-manifest","message"\}, or "error":"unreadable-manifest" when a file is not valid JSON or YAML.

`--json`: one JSON line on stdout.

### `pkey doctor`

Check .pkey/ and the live product.

```text
pkey doctor [--product slug] [--base-url url] [--json]
```

pkey doctor checks the product in four parts and always runs all of them: Manifest (.pkey/, the services the server enables, who is signed in, polaris-key.json), Keys (the signing and release key ids), Integration (per feature and platform Verified, Waiting or Not seen yet, with CI and Commerce) and Left to do, each with its fix. The product is --product, else the nearest .pkey/product; discovery is its .well-known/polaris.json under the base URL (--base-url, else $PKEY_BASE_URL, else key.plrs.im). Outside a repository it still checks sign-in, the base URL and polaris-key.json.

Signed in is pkey login, or $PKEY_ADMIN_TOKEN. Signed out, or refused access, is a warning, and signed out makes no console request. The summary counts what is to do and what is a warning, then the run time. It exits 1 while anything is to do: a manifest error, a failed discovery or an open console step.

--json prints one result line with the same facts: \{"v":1, "command":"doctor", "event":"result", "ok", "exit", "product", "baseUrl", "facts", "summary", "services", "signing", "keys"\}. Each fact is \{"id", "state", "detail"\} with id manifest, discovery, services, signing-keys or config-file and state ok, warn or todo; a network failure also carries "code":"network". "summary" is \{"todo", "warnings"\}. "signedIn" has state in, out, ended or unreadable and when it ends; "integration" has state ok, skipped, denied or unavailable, and ok carries features, platforms, ci, commerce and todo.

`--json`: one JSON line on stdout.

## SDK and tools

### `pkey sdk`

Print an SDK snippet, or one SDK's config file.

```text
pkey sdk --product slug [--base-url url] [--kid kid --public-key key]
pkey sdk add node|react|python|swift|kotlin|godot --expect kid@sha256:fingerprint[,...] [--product slug] [--base-url url] [--out path] [--force] [--release-key kid=key ...] [--package kotlin.package]
pkey sdk --lang node|react|python|swift|kotlin|godot [--product slug] [--base-url url] [--write [--out path] [--force]] [--kid kid --public-key key] [--release-key kid=key ...] [--package kotlin.package] [--dev [--url origin]]
```

pkey sdk add writes the SDK's config file and prints the install and the start. It refuses unless discovery serves exactly the pins --expect names, by fingerprint (copy them from the console's Integration page): it never trusts discovery first. Without --lang, pkey sdk prints a Node example with the pins given. With --lang it reads the product's discovery (and, in the product's repo, .pkey/release's releaseKeys) and prints that SDK's config file; --write writes it to the SDK's default path or --out, and --force replaces a file pkey sdk did not write. For Godot the file is polaris_key.tres beside project.godot: the product, base URL, pins, release keys and services go into it and its other properties stay. --dev reads the product, origin and release keys from a running pkey dev (--url, else ./polaris-key.json) instead.

No `--json`: the answer is text.

### `pkey dev`

Run a local Polaris Key to build against.

```text
pkey dev [--port n] [--auto-approve] [--builtin] [--out file | --no-write] [--json]
pkey dev keys|status [--url origin] [--json]
pkey dev expire|disable|revoke|restore|fill-seats key [--url origin]
pkey dev config name json [--key key] [--url origin]
pkey dev release version [--channel stable|beta|name] [--url origin]
pkey dev offline|online [--url origin]
```

pkey dev runs the Worker's real router in this process (Node 22.13 or newer; no account, no secrets, no install) on 127.0.0.1:8787. It seeds the product in ./.pkey/, else the built-in Tidewater Studio, with throwaway signing and release keys, a license key for each state (ok, expired, disabled, revoked, device-limit-full, key-entry-limit, floating), a fake identity provider, and a signed release on stable and beta. It writes polaris-key.json and prints the pins; nothing outlives the process. --auto-approve signs people in without the approval page; --builtin ignores ./.pkey/. The control commands act on a running server: --url names it (default: the baseUrl in ./polaris-key.json, else http://127.0.0.1:8787). Run Polaris Key locally: /docs/build/local/.

`--json`: one JSON line on stdout.

## Offline bundles

### `pkey bundle`

Mint an offline activation bundle for one device.

```text
pkey bundle --product slug --device id --grace-days n [--no-config] [--license id] [--base-url url] [--out file] [--force] [--json]
```

pkey bundle mints one offline activation bundle and writes it to a file (default &lt;product&gt;-&lt;first 8 of device id&gt;.pkeybundle; --base-url defaults to https://key.plrs.im). Copy that file to the air-gapped device and import it there.

--base-url must be https:, or http:// on localhost or 127.0.0.1 for local development: the token is sent to whatever origin you name, so any other origin is refused before anything is sent. The file is written with mode 0600, is never created over an existing one without --force, and is never written through a symbolic link.

--json prints one line, the result: the bundle id, the file, the device, the grace days and the documents it carries; on a failure, the error and its message.

| Variable | Meaning |
| --- | --- |
| `PKEY_ADMIN_TOKEN` | Used instead of the sign-in pkey login saved: a personal token (pkeyp_...) or an admin API token (pkeya_...) with the bundles:mint scope, sent as Authorization: Bearer. Make an API token in the console under API tokens; its value is shown once, when you make it. It can be revoked on its own and ends on the date you chose. Do not commit it or export it into a shared shell. |

`--json`: one JSON line on stdout.

### `pkey migrate`

Dry-run a data migration and read its report.

```text
pkey migrate list [--base-url url] [--json]
pkey migrate dry-run job [--base-url url] [--json]
pkey migrate report run [--base-url url] [--json]
```

pkey migrate reads a deployment's data-migration runner: the jobs, a run's report and a dry run (which changes no data). A job's changes are applied, and undone, from the console, pinned to a report this command printed: both need a recent sign-in that an admin API token cannot give.

| Variable | Meaning |
| --- | --- |
| `PKEY_ADMIN_TOKEN` | Instead of the sign-in `pkey login` saved: a personal token (`pkeyp_...`), or an admin API token (`pkeya_...`) with the `migrations:report` scope. Mint one in the console: /manage -&gt; API tokens -&gt; New token. An API token reaches the migration job list, reports and dry runs, and nothing else. |

`--json`: one JSON line on stdout.

### `pkey ci`

Set up publishing from GitHub Actions.

```text
pkey ci init [--channel c] [--dir d] [--action-ref sha] [--force] [--json]
```

ci init writes .github/workflows/release.yml (a v* tag publishes to --channel, default stable, from --dir, default dist) and refuses an existing file without --force. When .pkey/release declares no release key it makes one: the public half goes into .pkey/release, the private half into a 0600 file under $XDG_CONFIG_HOME/pkey/release-keys (default ~/.config), outside the repo. It prints the gh secret set line and never runs gh. The Action is pinned to --action-ref, a full commit SHA; without it the workflow holds a commit-sha placeholder for you to replace.

### `pkey release`

Publish, sign and move releases from CI.

```text
pkey release publish --product slug --version v --dir path [--deliverable app] [--tag vX.Y.Z] [--channel c] [--source r2|github] [--meta builds.json] [--base-url url] [--release-key-file pem] [--min-supported-seq n] [--no-record] [--content-stamp file | --embedded dir --pin pack@v ...] [--content-interface registry.json [--strict]] [--dry-run]
pkey release publish --product slug --version v --dir path --deliverable packId [--out dir] [--bases dir] [--release-key-file pem] [--base-url url] [--dry-run] [--content-key-file pem --delegation sha256] [--provides ids.json] [--removes id[,id...] ...] [--script-extensions ext[,ext...]] [--script-types Type[,Type...]]
pkey release content-stamp --product slug --out pkey-content.json [--embedded dir] [--pin packId@version ...] [--hold packId@version[=reason] ...] [--base-url url]
pkey release revoke packId@version --reason text --product slug [--replacement version] [--release-key-file pem] [--base-url url] [--dry-run]
pkey release revoke --delegation sha256|file --reason text --product slug [--release-key-file pem] [--base-url url] [--dry-run]
pkey release keys generate --kid kid --out file [--force]
pkey release keys generate --content --out file
pkey release delegate --product slug --prefix packId --types type,... --public-key key [--expires-in days] [--notes text] [--release-key-file pem] [--base-url url] [--dry-run]
pkey release promote|pin releaseId --channel c --product slug [--deliverable id]
pkey release unpin --channel c --product slug [--deliverable id]
pkey release yank releaseId --reason text --product slug
```

pkey release publish matches the files under --dir against .pkey/release's deliverables.app.artifacts map (&lt;file&gt;.sig and &lt;file&gt;.sha256 ride along as sidecars), hashes them, uploads what Polaris Key does not already hold, and submits the release descriptor. --dry-run prints the descriptor and the server's verdict and uploads and writes nothing.

With a release key (PKEY_RELEASE_KEY, or --release-key-file) it also signs the release record (pkey-release+jws) under the .pkey/release releaseKeys entry whose public key matches, checks it, and submits it with the descriptor; a dry run prints the record unsigned. pkey release keys generate writes a new private release key to --out and prints its releaseKeys entry.

When .pkey/release declares packs, an app publish states its pins: --content-stamp is the pkey-content.json pkey release content-stamp wrote before the export (from the pkey-marker/1 markers under --embedded, verified, and --pin packId@version resolved through Polaris Key), and each build's embeds come from the artifact map; both go into the descriptor, which the record is moved from.

--deliverable &lt;packId&gt; publishes a pack: per declared variant, the payload at &lt;dir&gt;/&lt;variant key or "default"&gt;/ (one .pck file, or the tree), checked, stripped of project.binary and the class cache, linted, indexed (pkey-files/1), with a full object, file blobs, a gaps object and deltas against the releases --bases keeps (zstd &gt;= 1.5.5 on PATH), and for a PCK variant of 4 MiB or more a pkey-chunks/1 chunk index with chunk bundles shared along the --bases chain (patch.strategies chunk, discovery release.chunks); it signs the pack record, uploads in stage rounds, submits it, and writes a marker beside each payload. --out keeps the record, payloads and chunk indexes for the next publish's --bases.

A godot.pck lint (P4-28) refuses a resource that references an app script or a UID outside the pack's uid cache unless .pkey/release lists it in deliverables.app.content.attachable (the device's PKeyOptions.pack_attachable), and refuses as scripts .gd, .gdc, .cs plus --script-extensions (bare extensions of a GDExtension script language) and the class names --script-types gives (the device asks its engine for both).

Save compatibility (P4-20): a pack release signs the content ids it provides, from --provides or the pack's declared provides.from (default .pkey/provides.json; provides.required fails a publish without it); Polaris Key refuses a release that stops providing an id its predecessor provided at a live contentApi level both support, unless --removes acknowledges it. An app publish with --content-interface hashes that registry (canonical JSON, SHA-256), stores it with the release and warns when it changed since the channel's current app release while contentApi did not (--strict fails instead, before anything is uploaded).

pkey release content-stamp --hold packId@version[=reason] keeps a compatible pack at one release for this app release (written into the stamp's holds; never a pinned pack).

pkey release revoke signs a kind: revocation release record with the release key and submits it: devices stop using that pack release, and --replacement names the release of the same pack they take instead. Revocations are permanent; a later revoke of the same release supersedes the replacement or reason, never the revoked status.

pkey release keys generate --content writes a new content key (no kid) and prints its public key; pkey release delegate signs a kind: delegation record with the release key that lets that key sign data-only pack releases (files.tree, data.json, l10n.table) of compatible or standalone packs under --prefix (whole segments) for --expires-in days (default 180, at most 366). A content team then publishes with PKEY_CONTENT_KEY (or --content-key-file) and --delegation &lt;sha256&gt;: the files must pass the data-only rule, and the record is signed under the kid pkd1-&lt;sha256&gt;.

pkey release revoke --delegation revokes a delegation and every pack release signed under it.

--meta is a JSON file \{"&lt;buildId&gt;": \{"buildNumber", "minOS", "requires"\}\}. An ipa or apk payload's facts (bundle id, versions, entitlements; package, version code, ABIs, signer) are read into the descriptor for the storefront feeds.

A CI command runs in GitHub Actions with permissions: id-token: write, or with PKEY_CI_TOKEN. The CI commands exchange the job's GitHub OIDC token for a short-lived pkeyci_ token themselves; no secret is stored in the repository. --product defaults to the nearest .pkey/product and --base-url to $PKEY_BASE_URL, else key.plrs.im. See /docs/build/ci/.

## Feeds

### `pkey feeds`

Package-feed setup and feed pruning.

```text
pkey feeds setup --ecosystem npm|pypi|swift|maven|oci|godot|cargo|go --owner slug [--namespace key=value ...] [--package name [--version v]] [--origin url] [--token-env NAME] [--json]
pkey feeds setup --write [--owner slug] [--no-browser] [--base-url url] [--json]
pkey feeds prune --product slug [--deliverable id] [--apply] [--json] [--base-url url]
```

pkey feeds prune deletes each package's builds of main and dev (X-main.N, X-dev.N, PyPI X.devN) below its newest stable release, the backfill of the Worker's automatic feed cleanup, which is on by default after a one-time dry-run notice. It is a dry run unless --apply: it prints what would go, per package, with counts and bytes. With --apply it also lists any version skipped (held since the plan, so kept) and exits non-zero if any version failed. The token needs release:yank, which an operator grants.

pkey feeds setup prints the copy-paste setup for one package feed on the registry host (default https://pkg.plrs.im), the same snippets the console's Setup tab shows: strict routing only (the npm scope, uv explicit = true, Gradle exclusiveContent, SwiftPM --scope, a fully qualified image reference, the Godot editor URLs). --namespace sets the feed's namespace (scope=@acme, groupPrefixes=gg.acme,gg.acme.tools); --token-env NAME adds the credential lines, reading the registry token from that environment variable. Offline: nothing is sent anywhere.

pkey feeds setup --write signs in with a code and a read-only personal token that you approve in Polaris Locker, then sets up the tools it finds on PATH. It changes only the lines it owns, in files under your home directory at 0600, and keeps the first version of a changed file as &lt;file&gt;.pkey-backup. It refuses (exit 4) in CI and without a terminal, where you print the setup instead; --owner limits it to one product's feeds. A Godot feed is skipped: the editor needs its own URL, made in Polaris Locker under Packages.

A CI command runs in GitHub Actions with permissions: id-token: write, or with PKEY_CI_TOKEN. The CI commands exchange the job's GitHub OIDC token for a short-lived pkeyci_ token themselves; no secret is stored in the repository. --product defaults to the nearest .pkey/product and --base-url to $PKEY_BASE_URL, else key.plrs.im. See /docs/build/ci/.

## Channels

### `pkey channel`

Declare a delivery channel and sync it from CI.

```text
pkey channel add <id> [--field name=value ...] [--outlet-id id] [--json]
pkey channel sync [--channel c] [--version v] [--dir d] [--deliverable packId [--from dir]] [--product slug] [--base-url url] [--dry-run] [--json]
```

channel add declares one channel in .pkey/distribution, creating the file when absent and keeping the comments already there, with a comment on every field. Channels: polaris-key, app-store, testflight, altstore, altstore-pal, google-play, play-testing, obtainium, fdroid, microsoft-store, app-installer, winget, steam, itch, flathub, snap, homebrew, scoop, web. --field sets one of the channel's fields (a value starting [ or \{ is JSON); the answer names the ones still unset. --outlet-id names the entry when you declare a channel twice. Nothing is written if the id is taken or .pkey/ would stop validating.

channel sync runs what each declared channel needs: a pull request for winget, Homebrew, Scoop and Flathub, as pkey storefront &lt;store&gt; pr does, and with --dir an itch.io push per platform, a Snap upload and the F-Droid repository build, from the files .pkey/release maps (no fitting file is a skip). --channel is the release track (default stable); --version is what itch.io records (default: the tag in GITHUB_REF_NAME). A channel whose credential is unset is skipped, naming the variable (PKEY_PR_TOKEN, BUTLER_API_KEY, SNAPCRAFT_STORE_CREDENTIALS, PKEY_FDROID_KS_PASS, PKEY_FDROID_KEYSTORE, PKEY_FDROID_ALIAS); Flathub is skipped until its first submission (pkey storefront flathub init). A failed step fails the command after the rest ran. It needs PKEY_CI_TOKEN, or permissions: id-token: write in GitHub Actions. snap metadata stays a pre-build step. --dry-run runs nothing and prints each checked command. --deliverable &lt;packId&gt; plans that pack's store transports instead of the channels: Background Assets (package, upload; needs macOS and ASC_KEY_ID, ASC_ISSUER_ID, ASC_PRIVATE_KEY or ASC_KEY_PATH), a Steam depot (vdf, build; needs STEAM_USERNAME, STEAM_CONFIG_VDF, the secret your workflow writes to ~/Steam/config/config.vdf, and steamcmd) and Play Asset Delivery, which is always skipped: run pkey transport play-pad modules before the build. A transport that skips leaves the pack on the Polaris Key CDN. It runs the rest from --from, the pack publish's --out directory, for the pack release --version; a step after one that failed is skipped. --dry-run prints each command, the Steam account as $STEAM_USERNAME.

`--json`: one JSON line on stdout.


## Shell

### `pkey completion`

Print a shell completion script.

```text
pkey completion bash|zsh|fish
```

The script is generated from pkey's own command table: the commands, their subcommands and their flags. bash: eval "$(pkey completion bash)" in ~/.bashrc. zsh: eval "$(pkey completion zsh)" in ~/.zshrc, after compinit. fish: pkey completion fish &gt; ~/.config/fish/completions/pkey.fish.

No `--json`: the answer is text.

### `pkey help`

Show this help, or one command's.

```text
pkey help [command]
```

pkey &lt;command&gt; --help (or -h) prints the same as pkey help &lt;command&gt; and runs nothing. Colour is used only on a terminal; NO_COLOR, --no-color and a pipe give plain text, and --ascii (or TERM=dumb) ASCII symbols.

No `--json`: the answer is text.
