# @polaris-key/docs

The Astro Starlight site served at `/docs`: help for people using an app, developer guides and reference, and operator and contributor material.

## Where it sits

- Built to `dist/` with `base: "/docs"`. `../worker` copies it into its `[assets]` root under `docs/` and serves each path behind its access tier (`../worker/src/docs.ts`).
- Reads sources elsewhere in the repo: `../shared-manifest/schemas/v1` and `../worker/openapi` (copied to `public/` at build start), `../brand`, `tools/services.json`, the conformance corpus and parity files, `../cli/src/help`, and each UI kit's committed baselines.
- Feeds back into the repo: `../worker/src/docsCsp.generated.ts` (CSP hashes) and `dist/docs-slugs.json`, which the console's help-link gate reads (`../admin`).

## Layout

```
astro.config.mjs        base, redirects read from site-map.json, sidebar from src/lib/doors.ts
site-map.json           page moves and the hidden stubs that reserve planned paths
old-pages.json          every page path that existed before the restructure; each must still resolve
lint-debt.json          known hits of the writing lints; only shrinks
help-messages.json      message id -> Help page (schema: help-messages.schema.json)
src/
  content/docs/       the pages, in three doors: help/ · start/ build/ features/ reference/ ·
                      operate/ contribute/ (plus index and access)
  lib/doors.ts        door and access tier of a page from its directory (TIER_PREFIXES), sidebar trees
  lib/                frontmatter vocabularies (docs.ts), shots, baselines, help messages, snippets
  components/docs/    page components (Callout, Steps, Snippet, SdkPicker, HelpMessage, ...)
  components/ui/      UI-kit component pages
scripts/
  copy-artifacts.mjs      schemas, OpenAPI and brand files -> public/ (gitignored)
  gen-reference.mjs       writes the generated reference pages
  redirect-fragments.mjs  keeps a #fragment through a moved-page redirect
  collect-csp-hashes.mjs  inline script/style hashes -> the worker's docsCsp.generated.ts
  emit-slug-manifest.mjs  dist/docs-slugs.json: routes, frontmatter, heading anchors
  check-links.mjs         internal link and anchor check on dist/
  site-map.mjs            applies site-map.json rows
  lint-docs.ts            the writing lints
test/                   page, door, frontmatter, site-map and generator suites
test/snippets/          snippet compile lane: covered.ts, extract.ts, lanes.ts, pylane.py
```

- Doors and tiers: a page's door and access tier come from its directory, never from frontmatter. `TIER_PREFIXES` in `src/lib/doors.ts` is the one table; `../worker/src/docs.ts` mirrors it as `DOCS_TIERS`.
- Build steps, in order (`pnpm --filter @polaris-key/docs build`): `copy-artifacts`, `astro build`, `redirect-fragments`, `collect-csp-hashes`, `emit-slug-manifest`. Skipping the build and editing either output by hand fails CI.
- Generated pages: `gen-reference.mjs` writes `reference/validation-codes.mdx`, `config-entry.mdx`, `error-codes.mdx`, `routes.mdx`, `parity.mdx`, `protocol/fingerprint-constants.mdx`, `protocol/corpus.mdx` and `contribute/data-model.mdx`. Never edit them; edit the source and regenerate. `pnpm gen` (repo root) also writes the generators, settings and CLI reference pages.
- Moving a page is a row in `site-map.json`, then `node scripts/site-map.mjs apply`. The console's help-link tables follow in the same change (`../admin/src/console/nav.ts`, `../admin/src/lib/docsLinks.ts`).
- Lint debt: `pnpm --filter @polaris-key/docs lint:docs` fails on a hit `lint-debt.json` does not hold and on an entry nothing hits. Clear a page's entries in the change that rewrites it. `tsx scripts/lint-docs.ts --update` rewrites the file.
- Snippets: a `ts`, `tsx`, `js` or `python` fence on a page listed in `test/snippets/covered.ts` compiles in its SDK lane against the built packages; the Python lane needs `sdks/python/.venv`. Other pages are held to `test/snippets/advisory-baseline.json`, which only shrinks. Conventions are in `test/snippets/extract.ts`.
- Page rules (frontmatter, quoting, MDX braces, link form, page types): follow the writing page and the AGENTS.md docs conventions, not a copy here.

## Rules here

- Terminology comes from the concepts page (`src/content/docs/start/concepts.md`); `lint:docs` enforces the mechanical writing rules. See [AGENTS.md](../../AGENTS.md).
- The docs site is tiered: `test/doors.test.ts` pins every content directory to a door and a tier; `../worker/test/docsGate.test.ts` pins the Worker's gate to the same table. See [AGENTS.md](../../AGENTS.md).
- Generated pages are never hand-edited: `test/generated.test.ts` byte-compares each emitter's output with the committed page, and `pnpm gen --check` covers the docs reference family. See [AGENTS.md](../../AGENTS.md).
- Code blocks are compiled: `test/snippets/snippets.test.ts` holds covered pages to their SDK lane. See [AGENTS.md](../../AGENTS.md).
- Console help links live in two tables gated against `dist/docs-slugs.json`: `../worker/test/docsLinks.test.ts`. See [AGENTS.md](../../AGENTS.md).
- A moved page keeps its old path: `test/siteMap.test.ts` checks `old-pages.json` and every redirect. See [AGENTS.md](../../AGENTS.md).
- Docs-site CSP hashes come from the build: `../worker/test/docsCspParity.test.ts` compares `docsCsp.generated.ts` with `dist/`. See [AGENTS.md](../../AGENTS.md).
