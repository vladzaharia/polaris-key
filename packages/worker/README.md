# @polaris-key/worker

The one Cloudflare Worker behind `key.plrs.im`: the licensing, config, release, distribution, update, identity, sync and commerce APIs, the operator console API, and the host for the admin SPA and the gated docs site.

## Where it sits

- Called by the SDKs and the `pkey` CLI (`/<product>/<service>/…`), the publish Action's CI calls, the admin SPA (`/manage/api/…`), Polaris Locker (the customer site), and store and GitHub webhooks.
- Calls D1 (`DB`), KV (`HOT`), R2 (`BLOBS`), the Durable Objects `RL`, `UPDATE_HEALTH` and `SINGLE_USE`, queues, email and outbound store APIs. The bindings are tagged on `Env` in `src/platform/env.ts` and declared in `wrangler.toml`.
- Builds on `@polaris-key/protocol`, `jws`, `catalog`, `manifest`, `client-core`, `brand` and `zstd-wasm`.
- Serves the built `../admin` and `../docs` output from one `[assets]` root.
- A second script, `src/deltasEntry.ts` (`wrangler.deltas.toml`), consumes the lazy-delta queue and nothing else.

## Layout

```
src/
  index.ts            Worker entry: fetch, scheduled, queue; exports the Durable Objects
  dispatch.ts         request pipeline, driven from Node tests with an in-memory Db
  router.ts           pure route matching; SERVICE_NAMESPACES from the generated SERVICE_SLUGS
  mount.ts            composition root: the table of mounted services
  platform/           primitives: Env, crypto, KV, key vault, encodings
  db/                 the Db interface and its D1 and SQLite implementations
  core/               always-on substrate; domain folders licensing/ accounts/ notify/ trust/
                      assets/ registry/ ops/ settings/ rbac/ console/, hooks.ts for service reads
    adminCsp.ts       hashes of the admin SPA's inline scripts (hand-maintained)
  services/<slug>/    one opt-in service each: license config release distribution update
                      identity sync commerce; public.ts is what the console may import
  console/            operator console API under /manage/api
  docs.ts             tier gate and serving for /docs
  docsCsp.generated.ts  docs-site CSP hashes (written by the docs build)
  scheduled.ts        cron work; assetQueue.ts the hosted-asset queue
  platformInventory.generated.ts  from the tagged Env members
migrations/           D1 migrations, 00XX_<name>.sql
openapi/              polaris-key.v3.yaml, the HTTP spec
scripts/              assemble-assets.mjs, generators for the platform inventory, settings and
                      storefront CI, deploy preflight (check-config.mjs), registry-clients/
test/                 Node lane (vitest, better-sqlite3 as D1); test/transcripts/ records the
                      HTTP conversations
test-workerd/         workerd lane (vitest-pool-workers); vitest.workers.config.ts
test-workerd-deltas/  workerd lane for the deltas consumer; vitest.deltas.workers.config.ts
wrangler.toml         environments, bindings, crons; wrangler.deltas.toml the consumer script
```

- `core/` never imports a service. A service reads another's state only through the descriptor hooks in `src/core/hooks.ts`. The one allowed service-to-service edge is `update → release`.
- A new service is the checklist in the layout page below, not a one-line change.
- Admin and docs reach the Worker only as built files: `pnpm --filter @polaris-key/worker assemble` copies `../admin/dist` into `assets/` and `../docs/dist` into `assets/docs/`. `assets/` is gitignored.
- CSP couplings, both checked against built output (the tests skip when the build is absent):
  - `src/core/adminCsp.ts` must list exactly the inline-script hashes of `../admin/index.html` and `manage.html` (`test/adminCspParity.test.ts`, and `test/theme.test.tsx` in admin).
  - `src/docsCsp.generated.ts` is written by `../docs/scripts/collect-csp-hashes.mjs` and compared with `../docs/dist` (`test/docsCspParity.test.ts`).
- Migrations: name a new file `00XX_<name>.sql`. The lead assigns the number at merge.
- Node 22 only: `better-sqlite3` does not build on newer majors, and the suite then fails to collect. Prefix commands with `mise exec node@22 --`.
- `pnpm build` does not typecheck the Worker; run `typecheck`. `test` is the Node lane, `test:workerd` the runtime lane; Node allows runtime code generation that workerd forbids.

## Rules here

- Layers and service boundaries: `test/boundaries.test.ts` walks every file under `src/` and the runtime import graph. See [AGENTS.md](../../AGENTS.md).
- A new route needs a spec entry: `test/routeCoverage.test.ts` checks `openapi/polaris-key.v3.yaml` against the router in three directions. See [AGENTS.md](../../AGENTS.md).
- Generated files: `test/platformInventory.test.ts`, `test/settings-generated.test.ts` and `test/storefront/ciPlaneGenerated.test.ts` fail on drift; `src/*.generated.ts` is never hand-edited. See [AGENTS.md](../../AGENTS.md).
- Never hand-edit the recorded transcripts: `test/transcripts.test.ts` records them, `pnpm gen transcripts` rewrites them. See [AGENTS.md](../../AGENTS.md).
- A new error code needs an entry in `conformance/parity/errors.json` first: `pnpm gen constants` refuses a Worker code it lacks. See [AGENTS.md](../../AGENTS.md).
- The docs site is tiered: `DOCS_TIERS` in `src/docs.ts` mirrors `TIER_PREFIXES` in the docs package; `test/docsGate.test.ts` pins it. See [AGENTS.md](../../AGENTS.md).
- Toolchain constraint (Node 22): see [AGENTS.md](../../AGENTS.md).
