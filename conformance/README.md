# conformance

The golden vectors, recorded HTTP conversations and parity registries that make every language verify the wire contract identically.

## Where it sits

- Written by generators, never by hand: `tools/sign-corpus.ts` writes `corpus/v2/`, and the Worker's scenario tests write `transcripts/` (`pnpm gen transcripts`).
- Read by every SDK's tests: the Node and browser runners here, Python, Swift (through `CorpusLocator`), Kotlin (`sdks/kotlin/conformance`) and Godot (through its mirror).
- `parity/` is hand-written. `tools/parity-check.ts` checks each SDK's `parity.json` against it, and `tools/gen-sdk-constants.ts` turns it into every SDK's constants module.
- The two runners call `@polaris-key/client-core`, `@polaris-key/jws`, `@polaris-key/protocol`, `@polaris-key/catalog`, `@polaris-key/zstd-wasm` and the Node and React SDKs. Nothing calls into the runners.

## Layout

```
conformance/
  corpus/v2/            golden vectors from one signer (wire contract v5); generated
    cases.json          signed documents, JWS cases, trust, bundles, feeds, release records
    *-matrix.json       gate, stage, config, update, outlet, plan, feed-url, presentation, ui, backend
    fingerprint.json, headers.json, device-label.json, sync-scenarios.json, noise-vectors.json, sync-vectors.json, peer-matrix.json, device-proof.json
    content/            content corpus: cases.json (generated) and blobs/ (inputs)
  transcripts/          one JSON per HTTP conversation, recorded through the Worker router; generated
  parity/
    features.json       the feature registry every SDK declares against
    errors.json         the error-code registry
    enums.json          platform, arch, license status and the other shared enums
    copy.en.json        core copy: a title and message per error code and status
    copy.<locale>.json  translated copy packs, checked against copy.en.json
    *.schema.json       schemas for the files above and for each SDK's parity.json
  runners/
    node/               @polaris-key/conformance-node: corpusV2, transcripts, sync scenarios and the matrix tests
      suites.ts         the case driver both JS runners share
      peerMatrixSuites.ts  the peer-matrix suites both JS runners share
      transcriptReplay.ts  the fake server a replay runs against
    browser/            @polaris-key/conformance-browser: Vitest browser mode (Playwright)
```

Each SDK keeps its own `parity.json`: `packages/sdk-node`, `packages/sdk-react`, `sdks/python`, `sdks/swift`, `sdks/godot`, `sdks/kotlin`. The Godot runner reads the mirrors at `sdks/godot/tests/corpus/v2/` and `sdks/godot/tests/transcripts/`.

## Rules here

- Never hand-edit generated corpus files; `pnpm gen corpus --check` and `pnpm gen transcripts --check` fail on any difference. See [AGENTS.md](../AGENTS.md).
- A wire change bumps `PROTOCOL_VERSION` and regenerates the corpus; every runner and `pnpm gen --check` must pass. See [AGENTS.md](../AGENTS.md).
- Generated files carry a GENERATED banner; `tools/generators.test.ts` fails when a banner has no registry entry. See [AGENTS.md](../AGENTS.md).
- A new error code needs an entry in `parity/errors.json` first; `pnpm gen constants` refuses a Worker code it lacks and each SDK's registry test refuses an SDK code it lacks. See [AGENTS.md](../AGENTS.md).
- Never weaken a runner to make a change pass. See [AGENTS.md](../AGENTS.md).

### Generated corpus files

These are output; never edit them:

- `corpus/v2/cases.json`, `gate-matrix.json`, `fingerprint.json`, `stage-matrix.json`, `headers.json`, `config-matrix.json`, `update-matrix.json`, `outlet-matrix.json`, `plan-matrix.json`, `feed-url-matrix.json`, `sync-scenarios.json`, `device-label.json`, `presentation-matrix.json`, `portal-matrix.json`, `ui-matrix.json`, `backend-matrix.json`, `noise-vectors.json`, `sync-vectors.json`, `peer-matrix.json`, `device-proof.json`
- `corpus/v2/content/cases.json`
- the one generator-owned mirror, `sdks/godot/tests/corpus/v2/` (an exported Godot pack reads only `res://`; `content/` is not mirrored)

Every other runner, Swift included, reads `conformance/` in place. The Swift tests find it through `CorpusLocator` (`#filePath`), so there is no Swift copy and `sdks/swift/Tests/PolarisKeyTests/Resources/` must not exist.

The generator is `tools/sign-corpus.ts`, a driver over one module per family in `tools/corpus/` and the independent reference implementations in `tools/corpus/reference/`. Regenerate with `pnpm gen corpus` and commit the result in the same change. `pnpm gen corpus --check` regenerates in memory and fails on any difference (the mirror included), on a stray JSON file in either directory, and on the retired Swift mirror's directory.

`corpus/v2/content/blobs/` is the opposite: generator inputs (the zstd blobs, the `pkey-chunks/1` indexes and bundles, and `refs.json`). They are hash-checked against the `blobs` table in `content/cases.json` and never rewritten by a normal or `--check` run. Only the explicit `--rebuild-content-blobs` mode of `tools/sign-corpus.ts` writes them. It is pinned to zstd 1.5.7 and may only add blobs and `refs.json` entries: it throws, writing nothing, if an existing one would change. Changing an existing blob is a PR of its own.

The HTTP transcripts follow the same rule. `transcripts/*.json` and their Godot mirror at `sdks/godot/tests/transcripts/` are recorded by the Worker's scenario tests (`packages/worker/test/transcripts/`) through `pnpm gen transcripts`. A Worker change that alters a recorded response regenerates them in the same change, and the SDK replayers then show which SDKs must follow. The replayers: `runners/node/transcriptReplay.ts`, `packages/sdk-react/test/transcripts.test.ts`, `sdks/python/tests/transcript_replay.py`, `sdks/swift/Tests/PolarisKeyTests/TranscriptReplay.swift`, `sdks/kotlin/conformance/.../TranscriptReplay.kt`, `sdks/godot/tests/suite_transcripts.gd`.

### Changing the wire

A wire change is an all-languages event, in this order: contract (`docs/security/WIRE-CONTRACT-V5.md`), catalog, corpus, SDKs. A feature is not done until every implementation passes: client-core, Node, React, Python, Swift, Godot, and Kotlin for the features its parity manifest has implemented.
