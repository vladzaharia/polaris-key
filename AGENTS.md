# AGENTS.md

Instructions for any coding agent in this repository. Vendor-neutral and canonical: if a
tool-specific file (`CLAUDE.md`, `.opencode/`, …) disagrees with this one, this one wins.
Polaris Key is a **contract-first monorepo**: one Cloudflare Worker and SDKs for Node, React,
Python, Swift, Godot and Kotlin. **The wire contract is the source of truth, and every language must
verify it identically.**

## Commands

**Use Node 22.** Prefix every JS/TS command with `mise exec node@22 --`. The worker suite drives D1
through the native `better-sqlite3`, which does not build on a newer Node major: the whole package
then fails to collect instead of failing at the relevant change.

## The green gate

`pnpm gate` is the gate (`tools/gate.mjs`). It is scoped by default to the lanes your diff turns on
(`tools/ci-scope.json`, the same scope CI uses); `pnpm gate --full` runs every step and
`pnpm gate --plan` prints what would run without running it. CI runs every lane on `main`.

Machine hooks: `PKEY_GATE_BASE` (base revision), `PKEY_GATE_HEAVY` (prefix for the heavy steps),
`PKEY_GATE_SLOTS` (concurrent test steps per machine). Details: `tools/gate.mjs`.

One test, per toolchain, while you build:

- JS/TS: `pnpm --filter <pkg> exec vitest run <file>`
- Python: `cd sdks/python && .venv/bin/python -m pytest -q tests/<file>`
- Swift: `cd sdks/swift && swift test --filter <Suite>`
- Kotlin: `cd sdks/kotlin && ./gradlew --no-daemon -Ppkey.jvmOnly=true :<module>:test --tests <Class>`
- Godot: `PKEY_TEST_SUITES=<suite> sdks/godot/tools/run_tests.sh`

CI also runs what has no step above: `pnpm ui:lint`, `pnpm ui:report`, `pnpm test:browser` (also
Firefox and WebKit), `pnpm --filter @polaris-key/react test:browser`, the Kotlin JVM suites and the
`adminCspParity` test. The `.husky/pre-commit` hook runs `pnpm gen --fast --check` and
`pnpm typecheck`; a green hook is not a green gate.

## Hard rules

<a id="rule-1"></a>**1. Never hand-edit generated corpus files or transcripts.** Regenerate with
`pnpm gen corpus` or `pnpm gen transcripts` and commit the result in the same change. Never weaken
a runner to make a change pass. Enforced by `pnpm gen corpus --check` and
`pnpm gen transcripts --check`; detail (the file list, the Godot mirror, the content blobs):
`conformance/README.md`.

<a id="rule-2"></a>**2. A wire change bumps `PROTOCOL_VERSION` and regenerates the corpus.** The
constant is in `packages/shared-protocol/src/core.ts` (now 4); the spec, with the signed document
set, is `docs/security/WIRE-CONTRACT-V4.md`. The order is contract → catalog → corpus → SDKs, and a
feature is done when every SDK passes (Kotlin for what its parity manifest implements). Enforced by
every SDK's conformance runner; detail: `conformance/README.md`.

<a id="rule-3"></a>**3. Generated files carry a GENERATED banner — regenerate, never hand-edit.**
`tools/generators.ts` declares every family once. Enforced by `pnpm gen --check`,
`tools/generators.test.ts` (a banner with no entry), the Worker's `ciPlaneGenerated`,
`platformInventory` and `settings-generated` tests, and `packages/cli/test/sdkConfig.test.ts`.

<a id="rule-4"></a>**4. Terminology comes from the concepts page**
(`packages/docs/src/content/docs/start/concepts.md`); when code and the glossary disagree, the
glossary wins. Customers see **Polaris Locker** (the customer site, customer mail, Help, SDK
presentation, badges); **Polaris Key** is the platform (the console at key.plrs.im, the developer
docs, the CLI, the API) and names every identifier. Device, not machine. Tier, not plan. The
**product** is the record in Polaris Key; the **app** is the developer's build that embeds an SDK.
"Profile" is taken twice already; do not overload it. Enforced by the docs lints and in review;
detail: `packages/docs/AGENTS.md`.

<a id="rule-5"></a>**5. Products are DATA. Never add a product-specific key to code.** A product
describes itself in a `.pkey/` directory in its own repo; `products/<slug>/` is the in-repo fixture
form. Adding or changing a product never needs a Worker redeploy. If you are about to write
`if (product === "djdl")`, stop. Enforced in review.

<a id="rule-6"></a>**6. Layers and service boundaries are enforced by a test.** A layer imports only
itself and lower layers; the one cross-service import is `update → release`, and a service reads
another's state through the descriptor hooks in `packages/worker/src/core/hooks.ts`. Every D1 table
has an owner. Enforced by the Worker's `test/boundaries.test.ts`, `test/tableCrossings.test.ts` and
`test/auditWriter.test.ts`; detail: `packages/worker/AGENTS.md`.

<a id="rule-7"></a>**7. Raw hardware values are hashed on-device and never transmitted.** A
fingerprint is a set of per-component hashes; the server recomputes the composite `hwid` and never
trusts the client's copy. No installed-application enumeration: a probe answers only for
product-declared companion apps. Enforced in review; detail: `docs/PRIVACY.md`.

<a id="rule-8"></a>**8. Identifiers are Polaris Key.** Packages `@polaris-key/*`, PyPI
`polaris-key`, SwiftPM `PolarisKey`, CLI `pkey`, manifest dir `.pkey/`, tokens `pkey_` (license),
`pkeyt_` (device), `pkeyci_` (CI), `pkeyr_` (registry), `pkeya_` (admin API), `pkeyp_` (personal),
headers `X-PKey-*`, env `PKEY_CONFIG_*`, issuer `key.plrs.im`. The Polaris Locker brand renames none
of them. The `@plrs` / `polaris-suite` / `.polaris/` naming is dead (Amendment A1): read
`docs/superpowers/`'s spec closeout, not its plans. Enforced in review.

<a id="rule-9"></a>**9. A validation rule needs a mutation-table entry.** A rule added to the
`.pkey/` validator (`packages/shared-manifest/src/index.ts`) needs an entry saying whether the
published JSON Schemas can express it (`schema: "rejects"`) or not (`schema: "accepts"`). Enforced
by `packages/shared-manifest/test/schema-parity.test.ts`, which reads the codes from the validator
source.

<a id="rule-10"></a>**10. A new route needs a spec entry.** Add it to
`packages/worker/openapi/polaris-key.v3.yaml` **and** to the service descriptor's `surface` (a core
route: the `routeCoverage` table). Enforced by `packages/worker/test/routeCoverage.test.ts`, which
holds router, descriptors and spec to each other: documenting a route that does not exist is drift
too.

<a id="rule-11"></a>**11. The docs site is tiered; the repo is the agent-readable source.**
`key.plrs.im/docs` serves the landing page, the access page, Help and the developer sections
(`start/`, `build/`, `features/`, `reference/`) with no session; Operate → Console needs a console
session; Operate → Platform (the runbook included), Contribute and the full search bundle need
`can(platform, docs)` (`packages/worker/src/docs.ts`, `DOCS_TIERS`). A sessionless reader of a gated
page is sent to `/docs/access/`. There is no `llms.txt`. An agent reads this file and the repo, not
the deployed site.

PR.

## Docs

contributor guide: `packages/docs/src/content/docs/contribute/`.

## Working

Prefer a background job that reports on exit to a sleep-and-poll loop. If polling is unavoidable,
use short intervals tied to an exit status or final log line. Never sleep "just in case"; do
independent work while a job runs.

## Testing

Keep a work package well under an hour. Tests are a means, not the work: run scoped tests while
building and run the gate once at hand-off. Run only what your change touches:

- the tests for the modules you changed (one per toolchain, as in
  [the green gate](#the-green-gate)), never a repo-wide `pnpm test` or a whole SDK suite "once at
  the end";
- `prettier --check` on the files you changed, not repo-wide `pnpm lint` or `pnpm format`;
- `pnpm gen --check` only when you changed a generator input;
- a wire or corpus change runs every SDK's conformance and transcript runners, filtered to them.

CI runs the full matrix on the push to `main`.

Run `pnpm gate` once at hand-off; the lead's `$PKEY_LEAD/gate.sh` wraps it. The gate retries a
failed step once on its own. Fix the failure, then rerun only that step with `pnpm gate --only <n>`
(or `--from <n>`); never rerun the whole gate for one failure.

If untouched code passes on retry, record the timing flake and move on. Never raise timeouts to
get green.

## Review

Reviewers never run the gate; the builder did. They review the changed files only. A fix round
reruns only the failing steps and affected tests.

Reviewers never block on conflicts with current `main`. Diff from the branch's merge base and note
the conflict for the lead.

A review gets at most one fix round. If re-review still blocks, return the branch to the lead.

## Hand-off

Merge `main` at most once, right before hand-off. Do not re-merge after review because `main`
moved.

Name each D1 migration `00XX_<name>.sql`. The lead assigns its number at merge time; state that in
your report.

The repository is public: never push a security audit write-up or an unreleased security-fix
branch. Those stay local until the fix ships.

Finish clean: stop every background job before reporting. Do not hand back with a shell, server,
container or watcher still running.
